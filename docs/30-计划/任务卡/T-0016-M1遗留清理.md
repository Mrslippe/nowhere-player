## 1. 背景

M1 端到端验收通过了，但留下三个"不影响演示、影响日常使用"的问题。它们在真实使用中都会被撞到，且都在音频/状态机这条线上，一起清掉比分开做省事。

## 2. 目标

### 2.1 设备热插拔

现状：`np-audio` 只在 `play/pause/seek` 时检查设备，播放中拔耳机 → UI 仍显示"播放中"，声音没了。

要求：
- actor 在 tick 循环里**每 4 次 tick（约 1 秒）**探测一次默认输出设备是否变化（比较设备名即可，cpal 没有热插拔事件 API）。
- 变化时：释放旧 `Player` → 用新设备重开**当前曲目** → `seek` 回原位置 → 若之前在播则继续播。
- 重开失败：`status: error`、`error.code: E_DEVICE_LOST`，队列保留，用户 `play` 可重试。
- 探测本身不能阻塞 tick：只做一次设备名比较（廉价），重开才是有成本的，且只在变化时发生。

### 2.2 解码线程死亡恢复

现状：解码线程出错后 `last_error()` 有记录，但 actor 不处理，再 `play` 还是报错。

要求：
- tick 里检查 `last_error()` 非空且 `status == playing` → 尝试重开当前曲目并 `seek` 到原位置，**最多重试 1 次**。
- 重试再失败：`status: error`，`error.code: E_DECODE`。
- 成功恢复后清空错误状态。

### 2.3 `repeat=one` 与手动切歌

现状：`repeat=one` 时手动点"下一首"会重播当前曲——违反直觉。

要求：
- **自然播完** → 尊重 `repeat=one`（重播当前）。
- **显式 `next`/`prev`** → 忽略 `repeat=one`，正常切歌；`prev` 在首曲仍重播首曲（保持现状）。
- 这条要在 `np-core` 的状态机里用参数表达（如 `AdvanceReason::{Natural, Manual}`），不要在两处写 if。

## 3. 非目标

- 不做多设备并行输出。
- 不做设备切换的 UI（只发状态）。
- 不改 `AudioSink` trait 的形状（只允许在 `np-audio` 增加只读方法）。
- 不动 M2 的命令层。

## 4. 必读 / 必须核实

1. `docs/20-架构/音频架构.md`（线程模型、`ProcessingPlan`、§7 未决项 3/5）
2. `crates/np-audio/src/lib.rs`（`Player` 现有 API：`device_name` / `last_error` / `seek` / `is_ended`）
3. `apps/desktop/src-tauri/src/player_actor.rs`（tick 循环、切歌路径、`EventSink`）
4. **核实**：`CpalDevices` 是否已能拿到"当前默认设备名"；拿不到就在 `np-audio` 加一个只读方法（不改 trait）

**可写**：


## 6. 实施要求

- 设备探测必须在 tick 循环里做，**不能新开线程轮询**（会引入第二处状态）。
- 重开/恢复路径必须复用现有的"先 `self.player = None` 再 open"时序，不允许出现两个 `Player` 同时存在。
- 恢复时要把原位置记下来，`seek` 用它；`seek` 失败不阻断，继续播。
- `AdvanceReason` 要能被单测直接构造，不要在 actor 里散落布尔参数。
- 任何新增状态字段必须是 `Option` 且序列化为 `null`（已冻结的兼容约定）。

## 7. 验收标准

- [ ] `cargo test -p np-core` 通过：`AdvanceReason` 相关 ≥ 4 例（natural+repeat=one 重播、manual+repeat=one 切歌、natural+off 末尾停、manual+off 末尾不越界）
- [ ] `cargo test -p nowhere-desktop` 通过：≥ 2 例（设备变化触发重开、解码错误触发一次重试）
- [ ] `cargo clippy --workspace --all-targets -- -D warnings` / `fmt --check` 零问题
- [ ] 真机（`tauri dev`）：播放中切换系统默认输出设备 → 1–2 秒内恢复播放且位置不回零（附日志）
- [ ] 真机：`repeat=one` 下点下一首 → 真的切到下一首（不再是重播）
- [ ] 真机：自然播完且 `repeat=one` → 重播当前曲
- [ ] 拨出设备后不 panic，`status` 变为 `error` 且 `error.code` 可读

## 8. 测试要求

- 设备相关：用可注入的"设备名提供者"做单测，不要依赖真实硬件。
- 恢复路径：构造一个 `Player` 打开失败的状态，断言只重试一次。

## 11. 风险

- 设备名在某些驱动下不稳定（同一设备名称变化）→ 用"名称 + 通道数"做复合判断可降低误报；若误报频繁，在回报里说明并给出替代判据。
- 重开时 `Player::open` 会跑解码探测，可能耗时 50–200ms，期间 tick 会跳过若干次——允许，但要在日志里体现。
- 恢复过程中的 `seek` 如果落在文件末尾之外，要钳制到 `duration_ms`。
