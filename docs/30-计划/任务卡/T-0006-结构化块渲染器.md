## 1. 背景

终端双方案对比的 A 方案：用 React 组件渲染 `Block[]`，追求"像终端但不是终端"的表现力。
本卡只做**渲染器**，不做输入框、不做滚动容器、不做命令执行——那些属于 T-0008 的实验室。

## 2. 目标

导出一个纯受控组件 `<BlocksView blocks={Block[]} />`，把 6 种 `Output` 原语渲染成 React 结构，视觉对齐设计语言（等宽 13px、行高 1.6、语义色走 CSS 变量）。

**输入行**：`›` 提示符 + 命令原文 + 右侧状态（运行中转圈 / 完成显示耗时）+ 完成后整体变暗。
**尾注**：`footer` 存在时，用 12px `--fg-muted` 显示在输出区下方。

## 3. 非目标

- 不做输入框、不做光标、不做补全（T-0008）。
- 不做滚动容器与"贴底"逻辑（T-0008）。
- 不接 IPC、不执行命令。
- 不做 xterm 方案（T-0007）。

## 6. 实施要求

### 6.1 文件结构

```
renderers/blocks/
├─ BlocksView.tsx        # 入口：接收 Block[]
├─ BlockItem.tsx         # 单个块：输入行 + outputs + footer
├─ outputs/
│  ├─ TextOutput.tsx
│  ├─ TableOutput.tsx
│  ├─ ProgressOutput.tsx
│  ├─ ErrorOutput.tsx
│  ├─ HintOutput.tsx
│  └─ MediaOutput.tsx
├─ blocks.css            # 样式（只用 CSS 变量）
└─ *.test.tsx
```

### 6.2 各原语要求

| 原语 | 要求 |
|---|---|
| `text` | 按 `spans` 逐段渲染 `<span>`；`tone` 作为整段默认色；`bold/dim/italic` 生效 |
| `table` | 列宽按内容自适应；`selectable` 时行有 hover 背景；单元格文本超 40 字符截断加 `…`（`title` 属性存全文） |
| `progress` | 单行：`label` + 条 + `current/total unit`；`total=0` 时为不确定态（用 Spinner 或条纹） |
| `error` | 左侧 `--danger` 竖线 + `code`（等宽、muted）+ 消息 + `hint` + `actions` 渲染为按钮（无行为，仅展示） |
| `hint` | 12px `--fg-muted`；有 `suggestion` 时把建议用 `--accent` 标出 |
| `media` | 48×48 圆角方块；`ref` 是 URL 时用 `<img>`，失败或非 URL 时退化为渐变占位（与 T-0004 的确定性渐变逻辑类似，但**不要 import 播放器目录**，自己实现一份 10 行的） |

### 6.3 视觉

- 等宽字体走 `--font-mono`，字号 13px，行高 1.6，块间距 12px。
- 块之间不加分割线，靠留白。
- 输入行完成态：`opacity: .55`；运行态：右侧 12px Spinner。
- 任何颜色只能引用 CSS 变量。

## 7. 验收标准

- [ ] `pnpm -C apps/web typecheck` 通过
- [ ] `pnpm -C apps/web test` 通过，且新增 ≥ 7 个用例（6 种原语各 1 + 整块 1）
- [ ] 用 `terminal-demo.json` 渲染时，6 种原语全部出现且不报错
- [ ] Table 单元格超长时出现 `…` 且 `title` 为全文（单测断言）
- [ ] 组件内无 `#RRGGBB` 字面量
- [ ] `prefers-reduced-motion` 下无过渡
- [ ] 不跑 `scripts/check.ps1`

## 8. 测试要求

- 每个原语 1 个渲染用例（RTL，断言关键文本/结构）。
- 整块 1 个用例：输入行 + outputs + footer 都渲染出来。
- 不要求快照测试。

## 11. 风险

- 不要为了"好看"引入图标以外的依赖；`actions` 先渲染成 `Button variant="ghost"`，点击无行为。
- 中文与英文混排的对齐问题本卡不处理（表格对齐由 CSS 解决），xterm 方案才需要算字符宽度。
