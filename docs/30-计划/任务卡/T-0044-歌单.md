## 1. 背景

歌单是最后一个大功能。schema 已在 [`数据模型.md` §9](../../20-架构/数据模型.md) 定稿：`playlists` + `playlist_items`，**本地与在线曲目都能装**。

## 2. 目标

### 2.1 数据层（np-library，schema v2）

- 迁移 `user_version` 1 → 2：新增两张表，**不改已有表**；升级前备份 `.db.bak`（已有逻辑）。
- 仓储方法：
  - `create_playlist(name) -> id`（重名 → 错误）
  - `rename_playlist(id, name)`
  - `delete_playlist(id)`（连同 items）
  - `list_playlists() -> Vec<PlaylistSummary>`（含条目数）
  - `get_playlist(id) -> (Playlist, Vec<PlaylistItem>)`
  - `add_item(id, item)`（`position` 取当前最大值 + 1）
  - `remove_item(id, position)`（删除后**重排 position**，保持连续）
- `name` 校验：`[A-Za-z0-9\u4e00-\u9fa5 \-_]{1,48}`，UNIQUE COLLATE NOCASE。

### 2.2 命令层

```
playlist list
playlist create <名字>
playlist rename <旧> <新>
playlist delete <名字>
playlist show <名字>
playlist add <名字> <序号>        # 序号来自 active_listing
playlist remove <名字> <序号>     # 歌单内位置
playlist play <名字> [序号]       # 默认第 1 首
```

- `playlist show` **要设置 `active_listing = Playlist(name)`**，这样 `play 3` 能直接用。
- `playlist add`：从当前 `active_listing` 取第 n 条，**本地存 path，远程存 `(source, source_id)` + 冗余元数据**（见 schema §9.2）。
- `playlist remove` 后 position 重排，序号保持 1 基连续。
- 所有命令失败给人话：`歌单不存在：<名字>`、`歌单已存在：<名字>`、`歌单里只有 N 首`。

### 2.3 播放

`playlist play <名字> [n]`：

1. 取第 n 条；
2. `local` → 直接 `player.play(path)`；文件不存在 → `E_CMD_ARG`「文件不存在，可能已移动」；
3. `remote` → 走现有 `OnlineService::prepare`（缓存命中即秒开）；
4. 输出写明来源与歌单位置：`播放 · <歌单> 第 3 首 · <标题> · 来源：B站`。

**v1 不做连续播放**（见 §3）。

## 3. 非目标（明确排除）

- **不做歌单连续播放**（播完自动下一首）。需要队列支持远程引用 + 预取，另开卡。
- 不做歌单排序/拖拽/封面。
- 不做歌单导入导出。
- 不做"收藏当前播放"的快捷命令（可用 `playlist add` + 序号实现）。

## 10. 风险

- **迁移是这次唯一的破坏性改动**：必须在有真实数据的库上验（用 M5 的 `library.db` 副本），不能只测空库。
- 远程条目存了冗余元数据，**源挂了也要能显示**；不要为了"一致性"改成 join。
- `playlist add` 依赖 `active_listing`，用户忘了先搜索会报错——错误文案必须教他："先 search 或 library list"。
- 歌单名允许中文与空格，**引号规则**要能通（`playlist create 周杰伦 情歌` 会被解析成两个参数，必须 `playlist create "周杰伦 情歌"`）——错误文案要说清。
