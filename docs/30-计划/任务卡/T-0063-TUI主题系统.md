## 0. 事实基线

| 项 | 当前值 |
|---|---|
| np-tui 配色 | 硬编码一套 dark `Palette` |
| 现有主题系统 | `np-core::theme`：14 color token + 8 结构轴 + `themes/*.json` |
| 内置主题 | `amber` / `graphite` / `ice` / `phosphor` / `tui-block` / `tui-wire` / `tui-paper` |
| 命令 | `theme list / set / export`（在 np-app，已可用） |

---

## 1. 目标

**把 `np-core::theme` 的调色板映射到 Ratatui 的 `Style`**，让 TUI 吃同一份主题文件。

### 1.1 映射规则

| theme token | Ratatui |
|---|---|
| `bg` | 全局 `Back` |
| `fg` | 正文 `Fore` |
| `fgMuted` | 次要文本（hint、时间） |
| `fgFaint` | 分隔线、占位 |
| `accent` | 高亮、进度填充、当前项 |
| `danger` | 错误块 |
| `warn` / `success` | 状态点 |
| `line` / `lineStrong` | 边框 |

**结构轴（8 个）在 TUI 里大多无意义**（radius/border/shadow），**只取三个**：

| 轴 | TUI 映射 |
|---|---|
| `density` | 行距（compact=1 行，normal=1 行但表格多 padding 行） |
| `progress` | `line` → `Gauge`；`blocks`/`bracket` → 分段字符 |
| `font` | 忽略（终端字体由用户决定） |

其余轴在 TUI 里**明确忽略并在 `theme export` 时保留原值**（不丢数据）。

### 1.2 命令

- `theme list` / `theme set <id>` / `theme export <id>` **沿用 np-app 现有实现**，TUI 只负责：
  - 启动时读 `settings.json` 里的 `theme.id`；
  - `theme set` 成功后**立即重绘**（不需要重启）。
- 非法颜色值 → 回退到内置 dark，并打一行 hint。

### 1.3 内置主题的 TUI 效果

- `graphite` / `amber` / `ice` / `phosphor`：正常映射。
- `tui-paper`（亮色）：**必须验证**亮色在终端里的可读性（对比度 ≥ 7:1），以及封面在浅色背景下的观感。
- 若某主题的 `bg` 与终端实际背景不一致（用户 WT 有自己的背景），**以主题 bg 为准**绘制整屏底色。

## 2. 非目标

- 不做主题编辑器。
- 不做结构轴的完整实现（只 3 个）。
- 不改 `np-core::theme`。

## 6. 风险

| # | 风险 | 缓解 |
|---|---|---|
| 1 | 终端背景与主题 bg 不一致导致观感割裂 | **整屏绘制 bg**（`Clear` + 填底），不依赖终端背景 |
| 2 | Sixel 封面在亮色下边缘发灰 | 封面加 1px `line` 边框 |
| 3 | `theme set` 走 np-app 写 settings，TUI 需要重读 | set 成功后重新 `load_theme()`，不要缓存旧值 |
| 4 | 某些主题 `accent` 与 `bg` 对比不足（如 tui-paper 的墨色 accent） | 高亮项改用 `reverse`（反白）而不是 accent 色 |
