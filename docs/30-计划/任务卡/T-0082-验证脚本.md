## 1. 目标：一个统一验收入口

```powershell
pwsh -NoProfile -File scripts/verify.ps1 -Card T-0082 `
     -Selftest "library list --limit 3;search 晴天"
```

### 1.1 它做什么（按顺序）

| # | 步骤 | 失败即中止 |
|---|---|---|
| 1 | 记录 `git rev-parse --short HEAD`、`git status --porcelain`（是否脏） | 脏只**警告**，不中止 |
| 2 | `cargo build --release -p np-tui` | ✅ |
| 3 | 记录二进制 **sha256 + 字节数 + 构建时间** | — |
| 4 | 运行 `scripts/check.ps1` | ✅ |
| 5 | 逐条运行 `-Selftest` 命令（`NP_TUI_DATA_DIR` 指向**临时副本**，不碰真实库） | ✅ |
| 6 | 检查输出里是否出现 `E_` 错误码 | ✅ |
| 7 | 写报告到 `tmp/verify/<card>/report.md` | — |

### 1.2 报告头（关键）

```markdown
# 验收报告 · T-0082
- git HEAD:      c68fde3
- 工作区:        干净
- 构建时间:      2026-11-12T22:10:41+08:00
- 二进制:        np-tui.exe 10,525,696 B
- 二进制 sha256: 3f2a…
- 门禁:          通过（698 passed）
- 自检命令:      2 条，全部成功
```

**有了这六行，"证据对应哪份代码"就不再靠记忆。**

### 1.3 副作用断言

每条自检命令都要记：

```
$ library list --limit 3
exit=0, stdout 171 B
（输出前 5 行附后）
```

**exit 必须是 0**；非 0 直接判失败，即使输出"看起来对"。

## 2. 非目标

- 不做截图（视觉验收另说）。
- 不替代 `check.ps1`（它是子集调用）。
- 不做 CI（本地脚本即可）。

## 3. 授权路径

```
scripts/verify.ps1          ← 新建
scripts/check.ps1           ← 只允许加一行"被 verify 调用时跳过重复构建"（可选）
```

**禁止**：`crates/**`、`docs/**`（报告写在 `tmp/`）

## 4. 验收标准

- [ ] 脚本能对 T-0081 生成报告，**报告头含 HEAD / 构建时间 / 二进制 sha256** `[数字]`
- [ ] 故意用一条失败命令（如 `-Selftest "play 99"`）→ **退出码非 0**，报告标记失败 `[数字]`
- [ ] 输出里含 `E_` 时判失败 `[数字]`
- [ ] 工作区有未提交改动时**警告但不中止**，且报告里写明"脏" `[数字]`
- [ ] 自检用**临时数据目录副本**，不修改真实库（前后 sha256 一致） `[数字]`
- [ ] 脚本自身 `-Card` 缺省时给出用法提示 `[数字]`

## 5. 风险

| # | 风险 | 缓解 |
|---|---|---|
| 1 | 复制真实库到临时目录可能很大 | 只复制 `library.db`（WAL/SHM 一并），covers 已删 |
| 2 | Windows 下 `pwsh` 版本差异 | 只用 PS7 语法；在脚本头检查 `$PSVersionTable` |
| 3 | 构建耗时让脚本变慢 | `cargo build` 增量通常 < 10s；保存输出供排查 |
