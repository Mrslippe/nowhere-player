## 1. 背景

封面已经写进缓存目录，但没人能看见：播放器小窗还在用"确定性渐变"占位，库里也没有接口把 `cover_key` 变成可加载的 URL。

这一卡补上最后一环，让"扫描 → 播放 → 看到封面"闭环。

## 2. 目标

1. 后端提供封面 URL：把 `cover_key` 变成前端能 `<img src>` 的地址。
2. 播放器小窗优先显示真实封面，加载失败或无封面时回退到现有渐变。
3. 终端 `library list` / `search` 结果的 `Track` 带上 `coverKey`（已由 serde 输出，确认即可）。

## 3. 非目标

- 不做专辑网格、不做封面墙。
- 不做封面下载（远程源）。
- 不做主题（M4）。

## 4. 必读 / 必须核实

1. `docs/20-架构/数据模型.md` §3（封面路径约定：`covers_dir()/<key>.jpg`）
2. `crates/np-library/src/covers.rs` 与 `db.rs`（`covers_dir()`）
3. `apps/desktop/src-tauri/tauri.conf.json`（当前 assets 协议是否开启）
4. **核实**：Tauri 2 的 asset 协议在 `tauri.conf.json` 里怎么配 `scope`；能否用运行时 `asset_protocol_scope().allow_directory()` 追加

## 5. 授权路径

**可写**：

```
apps/desktop/src-tauri/src/ipc.rs
apps/desktop/src-tauri/src/lib.rs            ← 仅注册 + setup 追加 scope
apps/desktop/src-tauri/tauri.conf.json       ← 仅 assetProtocol 配置
apps/desktop/src-tauri/capabilities/default.json  ← 仅 asset 权限
apps/web/src/features/player/**
apps/web/src/shared/**
```

**禁改**：`crates/**`、`docs/**`、根 `Cargo.toml`、`package.json`

### 5.1 注册点核对

| 注册点 | 是否需要改 | 对应文件 | 已列入授权路径 |
|---|---|---|---|
| 依赖清单 | 否 | — | ☑ |
| 模块声明 | 否 | — | ☑ |
| 命令注册 | **是**（`library.coverUrl`） | `lib.rs` 的 `generate_handler!` | ☑ |
| 入口 / 路由 | **是**（asset 协议 + 权限） | `tauri.conf.json`、`capabilities/` | ☑ |

## 6. 实施要求

### 6.1 后端

- 新增 IPC `library.coverUrl { key }` → 返回 `asset://localhost/<绝对路径>`（用 `convertFileSrc` 等价逻辑在 Rust 侧拼，或直接返回绝对路径让前端 `convertFileSrc`，**二选一，在回报里说明**）。
- `setup` 里把 covers 目录加进 asset scope（运行时追加，避免硬编码 `$APPDATA` 通配）。
- key 非法（含 `/`、`..`、长度不对）→ 返回 `{ code: "E_CMD_ARG" }`，**不要拼路径**。

### 6.2 前端

- `player-bridge` 或新的 `cover.ts`：给定 `coverKey` → URL；带内存缓存（同一 key 只请求一次）。
- `PlayerCard` 的封面：有 key 时渲染 `<img>`，`onError` 回退渐变；无 key 直接用渐变。
- 图片 `decoding="async"`、`loading="eager"`（只有一张）。
- 不改变现有渐变算法的确定性。

## 7. 验收标准

- [ ] `cargo test -p nowhere-desktop` 通过：`coverUrl` 的 key 校验（合法/含 `..`/含 `/`/空）
- [ ] `pnpm -C apps/web exec vitest run src/features/player src/shared` 通过：URL 构建、缓存、失败回退
- [ ] `cargo clippy --workspace --all-targets -- -D warnings` / `fmt --check` 零问题
- [ ] **真机**：扫描一个含内嵌封面的曲库 → 播放 → 播放器小窗显示真实封面（附截图）
- [ ] 无封面的曲目 → 仍显示渐变（附截图）
- [ ] 非法 key 不导致 panic 或路径穿越

## 8. 测试要求

- key 校验用纯函数测试，不要依赖文件系统。
- 前端 URL 构建用纯函数 + 假 key 测试。

## 9. 文档影响

- 回报中给出：`coverUrl` 的返回形式（asset URL 还是绝对路径）、scope 配置方式、缓存策略。
- 主线据此更新 `开发方案 §4.3`（新增 IPC）与 `数据模型 §3`。

## 10. 回报格式

四段式。

## 11. 风险

- **asset 协议是安全边界**：scope 配太宽（如 `$APPDATA/**`）会把整个应用数据目录暴露给前端，只允许 covers 子目录。
- `convertFileSrc` 在不同平台生成的 URL 形式不同（Windows `http://asset.localhost/...`），不要硬编码。
- 大封面（512px）解码可能有一帧卡顿，`decoding="async"` 必须加。
