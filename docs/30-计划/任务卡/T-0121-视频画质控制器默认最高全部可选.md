## 0. 事实基线

- 视频当前请求固定 `qn=10000`、`codec=0`，只拿 AVC；2K/4K 可能在 HEVC 流里。
- `qn=25000` 不是标准画质档；标准档：30000 杜比、20000 4K、15000 2K、10000 原画、400 蓝光、250 超清、150 高清、80 流畅。
- `find_flv` 当前返回第一条 FLV codec；`accept_qn` 只来自这一条。
- 用户要求：**默认找最高画质**，清晰度菜单给出**所有可选项**。
- 房间 23197314 真机最高为 2K 高帧率，预计 qn=15000 + HEVC；需真机验证。

## 1. 目标

### 取流

- 视频 playurl 请求：

  ```text
  codec=0,1       # AVC + HEVC
  qn=20000        # 最高常规档请求；服务端按权限回退
  only_audio=0
  ```

- 解析所有 `http_stream/flv` codec，不再返回第一条：
  - 选 `current_qn` 最高的候选；
  - 同 qn 优先 HEVC（高码率/高帧率通常在 HEVC）；
  - 返回 union `accept_qn`，排序从高到低；
  - 保留所选 `codec`/`current_qn` 用于诊断。
- `DEFAULT_VIDEO_QN` 从 10000 改为 **20000**；服务端只给 15000/10000 时按 `current_qn` 回退。
- `qn=25000` 不作为视频目标。

### 菜单

- 菜单项来自 union `accept_qn`，显示所有可选项；
- 标签：
  ```text
  30000 杜比
  20000 4K
  15000 2K
  10000 原画
  400 蓝光
  250 超清
  150 高清
  80 流畅
  其它 qn <n>
  ```
- 当前选中项按服务端 `current_qn`，不是请求值；
- 默认打开视频时高亮最高可用档。

### 切换

- 菜单选 qn 后，按 `codec=0,1&qn=<qn>` 重取；
- 解析后选该 qn 能实际提供的候选；若服务端回退，更新菜单当前项并提示；
- 仍通过现有 `loadfile replace` 无缝换流，不重建窗口；
- 失败保留旧画面。

## 2. 非目标

- 不做自动码率/带宽探测；默认最高，用户可手动降档。
- 不请求 Dolby 专属参数；若 `accept_qn` 出现 30000，菜单显示，切换失败则回退。
- 不做 HLS/fmp4；仍用 FLV。
- 不改控制条动画/主题/图标。

## 4. 实现要点

- `PlayInfo` 增加/调整：
  - `flv_url` 为最高候选；
  - `accept_qn` 为 union 降序；
  - `codec` 为所选 `avc|hevc`；
  - 可选 `qualities` 由 TUI 继续用 `accept_qn` 生成，避免 API 层耦合中文标签。
- `parse_play_info` 遍历 streams/formats/codecs，收集 `FlvCandidate`：
  - 过滤空 host/base_url；
  - `best`：current_qn 最大；同 qn 时 HEVC 优先；
  - union accept_qn 去重降序。
- `video_play_info_url_with_qn` 改 `codec=0,1`；`DEFAULT_VIDEO_QN=20_000`。
- `VideoTarget` 的 `quality_note` 用 `quality_label`；`quality_options` 使用降序 union。
- `begin_quality_switch` 用所选 qn；成功后 `current_qn` 来自服务端。
- 测试覆盖：
  - 多 codec 夹具：AVC qn10000 / HEVC qn15000，选 HEVC；
  - union accept_qn 降序去重；
  - 请求 qn20000，服务端回退 15000；
  - 菜单包含 15000/20000/10000；
  - 切换 15000 走 qn=15000。
- 真机 T3：房间 23197314，检查默认 `current_qn=15000`、菜单有 2K、切 10000/15000 后音画正常。
