# T-0076 无头自检模式（测试基础设施）

| 字段 | 值 |
|---|---|
| 卡号 | T-0076 |
| 里程碑 | M8-9 |
| 依赖 | T-0073 / T-0074（播放与数据目录） |
| 预估 | 0.5 天 |
| 时间预算 | 墙钟 3 小时 |
| 负责人 | 常驻「音源 / 网络」代理 |
| 优先级 | **高：它解锁"远程播放"这条被卡住的门禁** |

---

## 0. 问题

自动化无法稳定把按键送进 TUI 窗口（焦点被抢），导致：

- 远程搜索 → prepare → 播放，**无法真机验证**；
- 批次 3/4/5 的很多验收都依赖"按几个键"，同样不可靠。

**根因不是功能坏了，是我们没有"不用键盘也能驱动"的入口。**

---

## 1. 目标

加一个**仅开发/测试使用**的无头模式：

```bash
NP_TUI_SELFTEST="search 晴天"  nowhere-tui.exe
```

行为：

1. 跳过 TUI（不进 alternate screen、不接管光标）；
2. 依次执行环境变量里的命令（`;` 分隔）；
3. 把每个 `Block` 用**纯文本**打印到 stdout（`Output` → 一行行文本）；
4. 结束，退出码 0（失败 1）。

### 1.1 约束

| 约束 | 说明 |
|---|---|
| **仅环境变量触发** | 不提供 CLI 参数，不出现在 `--help` |
| **不影响正常启动** | 未设变量时行为完全不变 |
| **不写入用户数据目录** | 自检用 `NP_TUI_DATA_DIR` 指定的临时目录 |
| **不进 raw mode** | 普通 stdout，可重定向到文件 |

## 2. 用途（这张卡解锁的东西）

| 场景 | 命令 |
|---|---|
| 远程搜索 | `NP_TUI_SELFTEST="search 晴天"` |
| 远程播放准备 | `NP_TUI_SELFTEST="search 晴天;play 1"` |
| 媒体库 | `NP_TUI_SELFTEST="library list --limit 5"` |
| 主题 | `NP_TUI_SELFTEST="theme set tui-paper;theme list"` |
| 歌单 | `NP_TUI_SELFTEST="playlist list"` |

**判定方式**：看 stdout 文本，不需要截图、不需要窗口焦点。

## 3. 非目标

- 不做通用 CLI（不加参数解析、不做脚本语言）。
- 不替代正常 UI 测试。
- 不做自动化断言框架（文本输出人工/脚本判读即可）。

## 4. 授权路径

```
crates/np-tui/**
```

**禁止**：其它 crate、`apps/**`、`docs/**`

## 5. 验收标准

- [ ] `cargo test --workspace` 全绿（≥741） `[数字]`
- [ ] 未设 `NP_TUI_SELFTEST` 时行为不变（启动时间、内存不回归） `[数字]`
- [ ] `NP_TUI_SELFTEST="library list --limit 3"` 输出 3 行表格文本 `[数字]`
- [ ] `NP_TUI_SELFTEST="search 晴天"` **真实网络返回在线结果**（stdout 能看到 B 站标题） `[数字]`
- [ ] `NP_TUI_SELFTEST="search 晴天;play 1"` 完成 prepare 并输出缓存路径或播放状态 `[数字]`
- [ ] 失败时退出码非 0，且 stderr 有人话 `[数字]`

## 6. 风险

| # | 风险 | 缓解 |
|---|---|---|
| 1 | 自检模式误入产品路径 | 环境变量名带 `SELFTEST`，代码里单一入口判断 |
| 2 | 远程搜索触发限流 | 单次，不重试；失败如实返回 |
| 3 | 有人拿它做批量脚本打别人服务器 | 文档写明"仅自检用"，不加循环/重试能力 |
