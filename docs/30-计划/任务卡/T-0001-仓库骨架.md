## 1. 背景

项目当前只有 `docs/`，没有任何工程骨架。后续所有任务都依赖 workspace 与目录结构先立起来。
本卡同时作为开发管线的**首次闭环验证**：卡 → 实现 → 门禁 → 评审 → 集成。

## 2. 目标

1. 初始化本地 git 仓库（不 push、不配置远程）。
2. 建立 Rust workspace，含 5 个空 crate：`np-core`、`np-audio`、`np-library`、`np-sources`、`np-system`。
3. 根级工程配置齐备：工具链锁定、编辑器约定、行尾约定、忽略规则。
4. 声明 pnpm workspace，为 `apps/*` 预留位置。
5. 提供可运行的门禁脚本 `scripts/check.ps1` 与 `scripts/check.sh`。
6. 补齐根级 `README.md`、`CHANGELOG.md`。

## 3. 非目标

- 不创建 Tauri 应用（T-0002 负责）。
- 不创建 `apps/web` 源码（T-0002 负责）。
- 不安装任何前端依赖、不新增任何第三方 Rust 依赖（本卡 crate 只允许 std）。
- 不写任何业务代码。

## 4. 输入（按顺序读）

1. `AGENTS.md`
2. `docs/40-规范/项目结构规范.md`（§2 目录、§6 命名、§9 禁令）
3. `docs/40-规范/智能体工作管线.md`（§4 任务卡、§9 回报格式）

## 6. 实施要求

### 6.1 git

- `git init`
- 仓库本地配置：`user.name = "Nowhere Dev"`、`user.email = "dev@nowhere.local"`、`core.autocrlf = false`
- 不配置 remote，不 push

### 6.2 Rust workspace

根 `Cargo.toml`：

- `[workspace]`，`members = ["crates/*"]`，`resolver = "3"`
- `[workspace.package]`：`version = "0.0.0"`、`edition = "2024"`、`rust-version = "1.90"`、`license = "MIT OR Apache-2.0"`
- 每个 crate：`publish = false`，`lib.rs` 仅含模块级文档注释（一句话说明职责），无其他代码

五个 crate 的职责一句话（写进各自的 `//!`）：

| crate | 文档首行 |
|---|---|
| np-core | 领域模型、命令定义、事件与错误码 |
| np-audio | 解码、重采样、混音与音频输出 |
| np-library | 媒体库扫描、标签解析与检索 |
| np-sources | 音源适配器与播放地址解析 |
| np-system | 托盘、媒体键、单实例等系统集成 |

### 6.3 工具链

`rust-toolchain.toml`：`channel = "1.98.0"`，`components = ["rustfmt", "clippy"]`。

### 6.4 编辑器与行尾

- `.editorconfig`：`charset = utf-8`、`end_of_line = lf`、`insert_final_newline = true`、`trim_trailing_whitespace = true`；Rust 4 空格；TS/JSON/YAML/MD 2 空格。
- `.gitattributes`：`* text=auto eol=lf`；`*.png binary`、`*.ico binary`、`*.jpg binary`。

### 6.5 忽略规则

`target/`、`node_modules/`、`dist/`、`*.log`、`/tmp/`、`.env`、`.DS_Store`、`Thumbs.db`。

### 6.6 前端 workspace 占位

- `package.json`（根）：`private: true`、`packageManager: "pnpm@11.22.0"`、`engines.node: ">=20"`；**不写**指向尚不存在目录的脚本。
- `pnpm-workspace.yaml`：`packages: ["apps/*"]`。

### 6.7 门禁脚本

`scripts/check.ps1` 依次执行并打印每步结果，任一失败立即 `exit 1`：

1. `cargo fmt --all -- --check`
2. `cargo clippy --workspace --all-targets -- -D warnings`
3. `cargo test --workspace`
4. 若 `apps/web/package.json` 存在：`pnpm -C apps/web typecheck` 与 `pnpm -C apps/web test`

`scripts/check.sh` 为等价 bash 版本，逻辑一致。

### 6.8 根级文档

- `README.md`：项目名、一句话简介、当前阶段（M0）、文档入口（指向 `AGENTS.md` 与 `docs/README.md`）、目录结构概览。≤ 40 行。
- `CHANGELOG.md`：`## Unreleased` 下 `### Added` 一行"初始工程骨架"。

### 6.9 提交

`git add -A` 后提交一次：`chore: 初始化工程骨架 (T-0001)`。

## 7. 验收标准

- [ ] `cargo metadata --no-deps --format-version 1` 成功且列出 5 个 package
- [ ] `cargo build --workspace` 成功
- [ ] `cargo fmt --all -- --check` 通过
- [ ] `cargo clippy --workspace --all-targets -- -D warnings` 通过
- [ ] `pwsh scripts/check.ps1` 退出码为 0
- [ ] `git log --oneline` 恰好 1 条提交，`git status --short` 为空
- [ ] 目录树与本卡 §2 一致，无多余文件（尤其是没有 `apps/` 目录）
- [ ] 五个 `lib.rs` 各有且仅有一行模块级文档

## 8. 测试要求

本卡无业务逻辑，不要求新增单元测试。但 fmt/clippy 必须零问题；`cargo test` 至少要能跑通（0 个测试也算通过）。

## 9. 文档影响

无。若发现规范缺项（例如目录树与脚本约定不一致），在回报的"未决"里提出，由主线决定是否改文档。

## 11. 风险

- edition 2024 需要 rustc ≥ 1.85，本机 1.98 满足。
- 首次 `cargo build` 可能触发索引更新，属正常耗时；若因网络失败，**如实报告错误原文**，不要尝试更换源或降级。
