## 1. 背景

`DES-014` 的 P1 已落地，但 Player、Browse 树、键位和状态栏仍未达到最终设计。本卡按 2026-11-13 冻结的设计稿一次性收口到 72×24 默认布局，并删除补全与多余键位。

---

## 2. 目标

- 新窗口默认 72×24；`layout_areas` 只返回 `top / player / controller`，状态栏嵌外框下边线。
- Player 无左右边框，内容宽 = 外框内宽 − 2；6 行视觉 + overlay + 整宽进度条；右下 `Mode ↻`。
- Browse 树顺序为 `歌单 / 子项 / 媒体库 / 搜索 / 队列 / 设置`；初始选中歌单；歌单 >5 折叠，≤5 展开；`Shift+Enter` 切换。
- Controller 内保留 `Tab` 补全；不再用 Tab 切焦点；其余多余键位删除。
- 内置主题只留 MilkGreen，自定义主题和 token 兜底保留。
- 圆角、焦点边框、计数弱化、状态栏分色按冻结方案落地。

## 3. 非目标

- 不改队列表、歌单表、设置表的列内容（H 决定）。
- 不改命令语法、错误码、`np-core` 命令契约。
- 不删除自定义主题机制；不删除 `ThemeTokens::default` 兜底。
- 不新增 Rust 依赖；不做鼠标交互；不做动画。

## 19. 播放控制状态修复（2026-11-14）

问题不是 GUI/TUI 逻辑混合；Tauri/GUI 已删除。实际是 `TuiAudio` 适配层的三个缺口：

1. `open_path` 新建 `Player` 后没有把当前音量重新设回去，所以切歌回到 100%。
2. `mode()` 是空实现，`PlaybackState.mode` 一直返回 `PlaybackMode::default()`；播放模式标签也固定为 `Mode ↻`。
3. 歌单条目可能是 Remote（B 站），`path` 为空；List Enter 只尝试本地路径，失败后回退 `play N`，没有走 `playlist play "歌单" N`。

修复：

- `open_path` 打开新 Player 后立即 `set_volume(self.volume.get())`。
- `TuiAudio` 保存 `mode`，`snapshot()` 返回实际模式，`mode()` 写入；Player 底边显示 `Mode · / ↺ / ↻ / ⇄`。
- List Enter 遇到 Remote 且当前视图是歌单时执行 `playlist play "歌单" 序号`；Local 仍直接播放。
- 新增音量/模式跨曲目测试。
