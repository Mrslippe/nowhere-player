## 1. 目标

把「结构」从 skin 里拆成 **8 个枚举轴**，用户可通过主题 JSON 组合。

**本卡的硬约束：`plain` 与 `phosphor` 的渲染结果必须零变化**——轴只是把既有取值显式化。

## 2. 契约（两端必须一致）

### 2.1 主题 JSON 新增可选字段

```jsonc
"structure": {
  "radius":    "none | subtle | soft",
  "border":    "none | hairline | box",
  "density":   "compact | normal | relaxed",
  "progress":  "line | blocks | bracket",
  "selection": "bar | reverse | bg",
  "labels":    "sentence | upper",
  "stripe":    "off | on",
  "font":      "mixed | mono"
}
```

- 全部可选；缺项回落 **skin 预设**（见 §2.3）。
- 非法值 → 回落该轴的 skin 预设，并给一条 warning（不整主题失败）。

### 2.2 DOM 属性（前端唯一开关）

```html
<html data-structure-radius="soft"
      data-structure-border="hairline"
      data-structure-density="normal"
      data-structure-progress="line"
      data-structure-selection="bar"
      data-structure-labels="sentence"
      data-structure-stripe="off"
      data-structure-font="mixed">
```

**只用这 8 个属性切结构**，不加新的 class 命名空间。

### 2.3 两个现有 skin = 两组预设

| 轴 | `plain` | `phosphor` |
|---|---|---|
| radius | `soft` | `none` |
| border | `hairline` | `none` |
| density | `normal` | `compact` |
| progress | `line` | `line` |
| selection | `bar` | `bg` |
| labels | `sentence` | `sentence` |
| stripe | `off` | `off` |
| font | `mixed` | `mono` |

**零变化验收**的依据就是这张表——当主题没写 `structure` 时，行为必须与今天完全一致。

### 2.4 各轴的作用范围

| 轴 | 影响 |
|---|---|
| `radius` | 卡片/控件/弹层的圆角：0 / 2px / 现值 |
| `border` | `none` 无框；`hairline` 1px 高光边（现状）；`box` 1px 实线框 + 表头/分区线 |
| `density` | 行高 20 / 24 / 28；表格 cell padding 同步 |
| `progress` | `line` 现有细线；`blocks` `▰▰▰▱▱` 字符块；`bracket` `[■■■□□□]` |
| `selection` | `bar` 左侧 2px；`reverse` 整行反白（bg↔fg）；`bg` 仅底色提亮 |
| `labels` | `upper` 时表头/字段名转大写 + `letter-spacing: .06em`；**不影响正文** |
| `stripe` | `on` 时表格隔行 `bgElev` 底 |
| `font` | `mono` 时界面字体也用等宽 |

## 3. 分工

### 3.1 音源代理（Rust，约 1 天）

```
crates/np-core/src/theme.rs        ← 新增 Structure 结构体 + 解析/校验/默认
```

- `Structure` 8 个 `Option<Enum>`；`resolve(skin)` 返回**补全后的** 8 个值。
- 校验：非法值 → 回落 + warning（复用现有 `ThemeError`/warnings 机制）。
- `ThemeSpec` 序列化时带上解析后的 `structure`（用户导出能看到完整值）。
- 单测：默认补全、非法回落、8 轴全覆盖、`plain/phosphor` 预设正确。

### 3.2 UI 代理（web，约 2.5 天）

```
apps/web/src/shared/theme-loader.ts      ← 应用时写 8 个 data-structure-* 属性
apps/web/src/design/skin/*.css           ← 现有 skin 的取值改为 data 属性驱动
apps/web/src/features/**/*.css           ← 各轴的样式分支
apps/web/src/design/components/**        ← 进度条组件支持 blocks/bracket
```

- **`theme-loader` 负责写属性**：缺省时按 §2.3 的 skin 预设补全后写入。
- **CSS 用属性选择器切分支**，不要在每个组件里写 JS 判断。
- 进度条的 `blocks`/`bracket` 需要 DOM 支持：用 `::before` 的 `content` 或 SVG/文本；**不允许为它改公开选择器名**。

## 10. 风险

- **属性名一旦发出就是公共契约**：`data-structure-*` 要一次定死，后续只能加轴不能改名。
- **零变化验收是硬门槛**：`plain/phosphor` 有任何像素差异都说明轴拆分时改变了既有语义。
- `blocks` 进度的字符宽度依赖等宽字体；`font=mixed` 时必须回退成 `line`（否则方块乱码）——**这条要写进代码注释**。
- 属性选择器会让 CSS 体积增长，注意不要复制整段样式，用 `:root[data-structure-x=y]` 只覆盖差异项。
