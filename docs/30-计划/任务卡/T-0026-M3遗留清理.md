## 1. 背景

M3 全链路通了，但留了三个小尾巴。都不影响功能，但会让 M4 的主题评审看起来"没做完"（播放器上艺人/专辑还是占位文案）。

## 2. 目标

1. **播放器窗显示真实标题/艺人/专辑**：已有 `library.trackByPath`，把 `Track.title/artist/album` 接到 `PlayerCard`；取不到时仍回退到文件名/占位。
2. **`trackByPath` 路径规范化**：`E:/a/b.wav` 与 `E:\a\b.wav`、以及大小写差异都能命中同一条记录。
3. **`library stat` 增加封面缓存体积**：让用户知道缓存占了多少。

## 3. 非目标

- 不做缓存清理命令（`clean` 已有：全量扫描结束自动清）。
- 不做 favicon（dev 期 404 是噪声，无影响）。
- 不做歌词/封面墙。

## 4. 必读 / 必须核实

1. `apps/desktop/src-tauri/src/ipc.rs`（`trackByPath` 现在怎么查）
2. `crates/np-library/src/repo.rs`（`track_by_path` 的 SQL）
3. `apps/web/src/features/player/use-track-cover.ts`（已有 path→Track 的解析，可复用）

## 6. 实施要求

### 6.1 元数据渲染

- `use-track-cover` 已经拿到 `Track`，把它扩成 `use-track-meta`（或原文件内扩展），返回 `{ coverSrc, title, artist, album }`。
- 取不到 Track 时：`title = 文件名去扩展名`（现有逻辑），`artist = "本地文件"`，`album = ""`（副标题只显示艺人）。
- 不做截断逻辑的改动（`PlayerCard` 已有单行省略）。

### 6.2 路径规范化

- Windows：`/` → `\`，查询用 `COLLATE NOCASE`。
- 其他平台：保留原样（大小写敏感），只做 `/` 归一。
- 归一化在**查询前**做，不改库里存的路径（`tracks.path` 仍是扫描时的原样值）。
- 不改 `tracks` 表结构，不加列。

### 6.3 缓存体积

- `library stat` 输出多一项：封面缓存 `N 个文件 / X MB`。
- 实现：统计 `covers_dir()` 下 `*.jpg` 的数量与总字节；目录不存在返回 0。
- 大目录（> 5000 文件）要有防护：只统计，不读文件内容，`read_dir` 遍历即可。

## 11. 风险

- `COLLATE NOCASE` 只对 ASCII 生效；Windows 路径含中文时大小写不敏感本来就没意义（中文无大小写），可接受。
- 归一化后如果库里存的是相对路径（不应该发生），查询仍会 miss——保持 miss 行为，不要做模糊匹配。
- 统计缓存体积时不要跟随符号链接（避免死循环）。
