## 1. 背景

扫描时已经算出 `cover_key`（内容哈希），但只存了 key，没存图。这一卡把封面真正落盘、缩放、清理，并让前端能取到。

## 2. 目标

1. 扫描时把封面写到缓存目录：`<cache>/covers/<key>.jpg`。
2. 统一缩放到 **512px 长边、JPEG quality 82**（不放大，小图保持原样）。
3. 来源优先级：内嵌图 > 同目录 `cover.jpg` / `folder.jpg` / `front.jpg`。
4. 扫描结束时清理**无引用**的封面文件（数据库里没有 `cover_key` 指向它）。
5. 提供 `covers_dir()` 给上层拼路径。

## 3. 非目标

- 不做封面下载（远程源，M4）。
- 不做 UI 展示（前端另卡接线）。
- 不做缩略图多尺寸（只存 512 一种，前端缩放）。

## 4. 必读 / 必须核实

1. `docs/20-架构/数据模型.md` §3（封面约定）
2. `crates/np-library/src/metadata.rs`（现有 `cover_key` 哈希逻辑）
3. **核实**：`image` crate 当前版本的 JPEG 编码 API 与 `thumbnail` 行为

## 5. 授权路径

**可写**：

```
crates/np-library/src/**
crates/np-library/Cargo.toml      ← 仅允许加 image（features: jpeg, png）
```

**禁改**：`apps/**`、`crates/np-core/**`、`crates/np-audio/**`、`docs/**`、根 `Cargo.toml`、`package.json`

## 6. 实施要求

- `Database::open` 时接收（或设置）缓存目录路径；扫描器写入时用同一路径。
- 写文件要**原子**：先写 `<key>.tmp` 再 `rename`，避免半截文件被前端读到。
- 已存在同名文件 → 跳过（内容哈希相同，必然一致）。
- 解码失败（非图片 / 损坏）→ 记一次 `failed`，不中断扫描。
- 缩放：`min(512 / w, 512 / h, 1.0)`，用 `image::imageops::resize` + `FilterType::Lanczos3`。
- 清理：只在**全量扫描结束**时做（增量扫描不清理，避免误删）。

## 7. 验收标准

- [ ] `cargo test -p np-library` 通过，新增 ≥ 6 用例：
  - 内嵌图 → 生成 `.jpg`，尺寸 ≤ 512
  - 小图（100×100）不被放大
  - 同目录 `cover.jpg` 在无内嵌图时被采用
  - 同 key 不重复写（mtime 不变）
  - 损坏图片 → failed 计数 +1，不 panic
  - 清理：删掉一条 track 后全量扫描，孤立封面被删；仍被引用的不删
- [ ] `cargo clippy -p np-library --all-targets -- -D warnings` / `fmt --check` 零问题
- [ ] 只新增 `image` 一个依赖
- [ ] 生成的 JPEG 用 `image` 读回可解析（测试里断言）

## 8. 测试要求

- 用代码生成测试图片（`image::RgbImage`），不要塞二进制。
- 缓存目录用临时目录，测试结束清理。

## 9. 文档影响

- 回报中给出：`covers_dir()` 的形状、清理策略、单张封面平均体积。
- 若发现契约里"清理时机"不清楚，停手提出。

## 10. 回报格式

四段式。

## 11. 风险

- `image` crate 的默认 features 很大（含所有格式），**必须只开 `jpeg` 与 `png`**，否则编译时间与体积都会暴涨。
- 大图（> 4000px）解码耗内存，要加一个上限（超过 8000px 直接跳过并记 failed）。
- 封面文件与数据库的一致性靠"扫描结束清理"，中途崩溃会留孤儿文件——可接受（下次全量会清）。
