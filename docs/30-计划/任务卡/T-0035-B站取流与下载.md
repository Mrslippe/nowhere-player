## 1. 背景

搜索能用了，但 `resolve` 还是占位错误。这一卡让 B 站曲目**真的能下载成一个本地文件**，从而能被现有播放器播放。

## 2. 目标

1. `BilibiliSource::resolve`：`bvid` → `playurl` 接口 → 取 **DASH 音频流**最高码率 → `ResolvedStream { url, mime, expires_at }`。
2. `Downloader`（可注入）：把 `ResolvedStream` 下载到 `<cache>/streams/<source>-<id>.<ext>`。
3. 缓存命中直接返回路径；半截文件（`.part`）视为未命中并删除。
4. 容量清理：超过 500MB 按 mtime LRU 删除。
5. 全部可离线测试（注入 `Transport` + 假文件系统或临时目录）。

## 3. 非目标

- 不接命令层（T-0038）。
- 不做网易云 / yt-dlp。
- 不做流式播放（ADR-0004 已否决）。
- 不做进度上报（T-0038 做，用现有 `progress` 原语）。

## 6. 实施要求

### 6.1 resolve

- 接口：`https://api.bilibili.com/x/player/playurl?bvid=<bv>&cid=<cid>&fnval=16&fourk=1`
  （`fnval=16` 才有 DASH；`cid` 从 `pagelist` 或搜索结果的 `cid` 取——若搜索结果没带，就再调一次 `view` 接口）。
- 从 `dash.audio[]` 里选 **`bandwidth` 最大**的一条；没有 DASH 时回退 `durl[0].url`。
- `expires_at`：从 URL 的 `deadline` 参数解析（秒级 Unix 时间戳）；解析不到就给 `None`。
- 要带 `Referer: https://www.bilibili.com` 与 `Origin`——**这是 B 站 CDN 的硬要求**，与"不伪造 UA"不冲突（UA 仍用固定桌面 UA）。

### 6.2 下载

- `Downloader` trait：`download(&self, stream: &ResolvedStream, dest: &Path) -> Result<DownloadOutcome>`。
- 生产实现用 `reqwest::blocking`；**先写 `<dest>.part` 再 rename**（同封面缓存的原子写）。
- 断点续传**不做**（B 站地址几分钟就过期，续传意义不大）。
- 失败时删除 `.part`。

### 6.3 缓存

- 路径：`<cache>/streams/<source_id>.m4a`（mime 决定扩展名：`audio/mp4` → `.m4a`）。
- 命中：文件存在且大小 > 0 → 直接用。
- 清理：目录总大小 > 500MB 时，按 mtime 从旧到新删，直到低于 400MB。

## 7. 验收标准

- [ ] `cargo test -p np-sources` 通过，新增 ≥ 10 用例：
  - resolve：DASH 存在 → 选最大 `bandwidth`；无 DASH → 回退 durl；`deadline` 解析成功/失败
  - 缺 `cid` → 调 view 接口补齐
  - 下载：成功写文件且无 `.part` 残留；中途失败 → `.part` 被删
  - 缓存：命中不重新下载（用假 Transport 计数断言）；`.part` 视为未命中
  - 清理：造 6 个文件超阈值 → 最旧的被删、总大小回落到阈值下
- [ ] `cargo clippy -p np-sources --all-targets -- -D warnings` / `fmt --check` 零问题
- [ ] 全部离线（测试零网络）

## 11. 风险

- **B 站 CDN 要求 Referer**，缺了会 403。这条要写进夹具说明，别以后被人当成"多余的 header"删掉。
- DASH 音频是 **m4a（AAC）**，symphonia 能解；但如果是 `fnval` 参数写错拿到 flv，播放器会失败——**要验证拿到的 mime**。
- 下载没有进度回调，几 MB 的阻塞下载会让命令层卡住 2–5 秒；T-0038 必须把它放到后台线程，**这一卡先把接口设计成"可以被线程调用"**（不持有 UI 状态）。
- 清理阈值 500MB 是拍的，实测后可以调，但要写进代码常量而不是散落魔法数。
