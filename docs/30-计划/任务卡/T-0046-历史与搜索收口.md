## 1. 背景（产品原话）

1. 「点上下方向键切历史指令时，如果历史指令触发了候选，上下键就被候选栏吃掉了」
2. 「`queue list` 列出来的播放列表不显示名称显示文件名，完全不可看」
3. 「搜索结果太多了，最好全部加起来不用翻页就能看完」
4. 「搜索支持可选参数：搜索歌手（或作者）、指定平台、结果条数」

## 2. 目标

### A. 历史导航不触发候选

- ↑/↓ 翻历史时，**不请求补全、不显示候选列表**。
- 翻完之后**不自动触发**；用户再输入一个字符才开始补全。
- 候选列表打开时 ↑/↓ 仍然是移动高亮（这条不变）。

判定用一个显式状态位（`historyNavigating`），不要靠"上一次是键盘还是鼠标"猜。

### B. `queue list` 显示元数据

输出列：`序号 | 标题 | 艺人 | 时长`（有来源时加来源列）。

- 本地曲目：`path` → 查库（`trackByPath`）取 `title/artist/duration_ms`；查不到回退文件名。
- 远程曲目：用会话映射（`OnlineService` 的 `RemoteMeta`）。
- 都查不到：显示文件名 + `—`（不要留空列，也不要假装有时间）。
- 队列长度很多时也要一次列完（队列本来就短）。

### C. 默认结果数收紧

- 默认 **总数 20 条**（每源 10 条），可通过 `--limit` 覆盖。
- 上限仍是 100。
- 提示行写清「共 N 条（每源 10，--limit 可调）」。

### D. 搜索参数

```
search [关键词] [--artist <名>] [--source <all|bilibili|netease>] [--limit <n>]
```

| 参数 | 语义 |
|---|---|
| 关键词 | 可为空（只给 `--artist` 时，用艺人名当关键词发给源） |
| `--artist` | **额外过滤**：结果 `artist` 字段包含该名（不区分大小写）。B 站按上传者名匹配 |
| `--source` | 只搜指定源；`all` 等于默认 |
| `--limit` | 本次总数上限（1–100） |

- 关键词与 `--artist` 都没有 → `E_CMD_ARG`。
- `--source` 值非法 → `E_CMD_ARG`（列出可用值）。
- 过滤后不足的结果**不自动放宽**。

### 与 `--local` 的关系

`--local` 保留，语义不变（只搜本地库）。`--source` 与 `--local` 同时给 → `E_CMD_ARG`（互斥）。

## 10. 风险

- **`--artist` 是过滤而不是"按艺人搜"**：如果源本身对艺人名不敏感（B 站上传者名），可能出现"关键词命中了但被 artist 过滤掉"的空结果。**空结果时提示要说清是"过滤前有 N 条、被 --artist 过滤掉了"**，否则用户以为源挂了。
- `queue list` 查库是 N 次查询（每个 path 一次）；队列通常 <100，可接受，但**要批量或缓存**，不要写成 O(n) 次开库。
- 默认 20 条会让"搜不到想要的"更容易发生——所以 `--limit` 必须在提示行里可见。
- 并行风险：T-0045 正在改同一批组件的外观。**你只改 .tsx 的逻辑与 .ts，不要动 CSS 文件**；如果发现必须改 CSS，停下来报告。
