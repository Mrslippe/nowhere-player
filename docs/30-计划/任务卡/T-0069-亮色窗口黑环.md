## 0. 现象

亮色主题（`tui-paper`，底 `#f2efe9`）下，**Windows Terminal 的 padding 区域仍是 profile 的黑色背景**，视觉上一圈黑围着白色界面。

## 1. 根因

| 层 | 说明 |
|---|---|
| **WT padding** | fragment 里写了 `padding: 10,10,10,10`，该区域用 profile 背景色绘制 |
| 未绘制单元格 | 已解决（整屏铺主题底） |
| 标题/标签栏 | WT 装饰，本卡不处理 |

## 2. 方案（按顺序实施）

### A. padding 归零 + TUI 自绘内边距

- fragment：`"padding": "0,0,0,0"`；
- TUI 在主题模式（有显式 bg）下，**在内容区外画 1 格主题底色**作为视觉留白。

**效果**：黑环消失，且留白颜色由主题控制。

**注意**：跟随终端模式（无主题）**不画**这层留白，否则会覆盖用户终端背景。

### B. OSC 11 运行时设置终端背景（增强，需先探测）

```
设置：\x1b]11;#rrggbb\x1b\\      （ST 结尾）
恢复：\x1b]111\x1b\\
```

- **先探测**：启动时发 OSC 11 查询（`\x1b]11;?\x1b\\`），读取响应判断终端是否支持。
- **支持则**在切到有 bg 的主题时设置；退出/切回跟随模式时恢复。
- **不支持则跳过**，只靠 A。
- **不得**假设支持——WT 对"设置"的支持需实测确认。

### B2. 专注模式启动（**默认关闭**）

产品要求：把「无窗口装饰」也做到位。

> 产品修正（2026-11-12）：**默认关闭**。Windows 上标题栏承载拖动/最小化/关闭，
> 隐藏后只能用 `Alt+F4`——**把常用操作变难了**。

- 默认**不加** `--focus`；
- 想极致无边框的用户可 `config set tui.focusMode true` 开启；
- **兼容性**：显式开启后若 `wt --focus` 启动失败（旧版不支持），**自动重试不带它**，并记日志。

效果叠加：`padding=0` + `--focus` + 主题底色 → **窗口里只剩内容**。

### B3. 隐藏滚动条

WT 的 profile 有 **Scrollbar Visibility**：`visible` / `hidden` / `always`。

- fragment 里设 **`hidden`**（JSON 键名需查证，UI 上叫 "Scrollbar Visibility"）；
- 效果：右侧滚动条消失，鼠标悬停右缘时临时出现；
- 若该键在 fragment 中不被接受，**退回"接受滚动条"并在回报里说明**。

### B4. 字体未安装告警（bug）

**现象**：测试拉起窗口一直提示"没有安装字体"。

**原因**：fragment 里写死了 `"font": { "face": "Sarasa Mono SC" }`，**本机未安装**。

**修复**：

1. **不要在 fragment 里写死字体名**；
2. 启动时**探测已装字体**（Windows 注册表 `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Fonts` 或枚举字体目录）：
   - 有 `Sarasa Mono SC` / `Maple Mono CN` → 写入 profile；
   - 都没有 → **不写 `font.face`**，用 WT 默认字体；
3. 状态栏可提示一行：「未检测到等宽中文字体，使用终端默认字体」。

**原则**：**宁可不用我们的字体，也不要弹警告**。

### C. 兜底：双 profile

若 A+B 后仍明显，提供 `nowhere-dark` / `nowhere-light` 两个 profile，`theme set` 提示用户切到对应 profile（不自动重启）。

**本卡不实现 C**，仅在回报里说明是否需要。
