## 1. 问题

### A. 播放器阴影被窗口边界裁掉

窗口 360×140、卡片 340×120、四周 10px 透明边距。CSS 阴影 `0 12px 32px`：

- 外延 ≈ `|offsetY| + blur` = 12 + 32 = **44px**
- 可用空间只有 **10px**

→ 阴影在 10px 处被窗口边缘切断，看起来像"卡片贴着一圈硬边"。

### B. 输入框焦点条要动起来

现在输入框下方是一条静态的琥珀色 2px 线。产品要：

- **聚焦时**：从左端向右延伸至全长
- **失焦时**：从右端退回左端
- 速率走**贝塞尔曲线**

## 2. 目标

### A. 阴影不裁切

1. 算出外延，窗口留白必须 ≥ 外延 + 2px 余量。
2. 建议：`margin 20px` + 阴影 `0 4px 16px rgba(0,0,0,.42)`（外延 20）→ 窗口 **380×160**。
3. 若实测仍被裁（不同 DPI/亚像素），**加大 margin 而不是减小阴影**——阴影是为了和壁纸分离，削它等于退回原问题。
4. Rust 侧 `windows.rs` 的窗口尺寸同步改；拖拽区仍只挂卡片。

### B. 焦点条动效

```
默认：scaleX(0)，transform-origin: left
聚焦：scaleX(1)，220ms cubic-bezier(.22,1,.36,1)   ← 从左到右长出
失焦：scaleX(0)，160ms cubic-bezier(.4,0,1,1)      ← 从右往左退回
```

- 用 `transform: scaleX()`，**不要动画 `width`**（会触发布局）。
- 时长/缓动进 token：`--np-dur-focus-in` / `--np-dur-focus-out` / `--np-ease-focus-in` / `--np-ease-focus-out`。
- `prefers-reduced-motion: reduce` → 两个时长都归 0（保留最终状态，不做过渡）。

## 10. 风险

- **加大窗口会让"可点击区域"变大**：透明边距内点击仍落在窗口上（不会穿透到桌面）。这是既有行为，但如果用户抱怨"点到空气"，需要另做点击穿透（本卡不做）。
- 焦点条用 `scaleX` 时，若父容器有 `overflow: hidden` 且条在边缘，可能被裁——检查一眼。
- 阴影调大后，**深色壁纸上会更明显、浅色壁纸上会发灰**：两张背景各截一张，别只验一种。
