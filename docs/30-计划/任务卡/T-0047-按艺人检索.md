## 1. 现象与探测结论（已完成，作为本卡依据）

```
search 不为谁而作的歌 --artist 明前奶绿 --source bilibili  → 0 条
```

探测（真实接口，`page_size=50`，duration 两桶合并）结论：

- 三种拼法（纯关键词 / 关键词+艺人 / 艺人+关键词）**都召回了大量标题含"明前奶绿"的切片**；
- 但上传者是 `StunningRose`、`坑又菜的白` 等搬运号，**没有一条 `author == 明前奶绿`**；
- 因此"按上传者过滤"在这类内容上**结构性地必然为 0**。

**根因不是候选池大小，是 `--artist` 的语义**：B 站没有"艺人"字段，只有上传者和标题。

## 2. 产品决定（2026-11-11）

> `--artist` 的语义改为**"这个人的名字"**，匹配范围按平台：
> - **B 站**：上传者 **或** 标题包含该名；
> - **网易云**：仍按艺人字段（它的 `artists` 是真实元数据，不要动）。

排序优先级：**上传者命中的排在标题命中之前**。

## 3. 目标

1. 改过滤语义（见 §2），`artist 明前奶绿` 能返回那些切片。
2. 带 `--artist` 时**扩大候选池**：每源 `min(limit*3, 50)`（默认 10 太小）。
3. 查询构造：`--artist` 仍拼进发给源的 query（`关键词 + 空格 + 艺人`），因为探测显示它能**提高召回**（三种里 `艺人 关键词` 命中的切片最多）。
4. 空结果提示保留：「过滤前 N 条，被 --artist 过滤掉了 M 条」。

## 4. 非目标（**已明确推迟，不要做**）

- **不做 UP 主空间检索**（`space/wbi/arc/search`）。产品决定先不做，但在 ADR/文档里留一条记录，将来需要"按 UP 找全部视频"时再开卡。
- 不做 `--mention` 之类的第二个参数。
- 不改网易云的过滤逻辑。

## 6. 实施要求

### 6.1 匹配函数

```
fn matches_artist(track, name) -> MatchKind   // Author | Title | None
```

- 大小写不敏感子串；去首尾空白。
- B 站：先比 `artist`（上传者），再比 `title`。
- 网易云：只比 `artist`。

### 6.2 排序

过滤后按 `MatchKind` 稳定排序：`Author` 全在前，`Title` 在后；同档保持源返回顺序（不要按播放量重排，T-0040 的重排规则只用于无 artist 的情况）。

### 6.3 候选池

- 无 `--artist`：维持现状（每源 10）。
- 有 `--artist`：每源 `min(limit*3, 50)`，过滤后再按总 limit 截断。

### 6.4 查询构造

- 关键词与 artist 都有 → `<关键词> <艺人>`。
- 只有 artist → `<艺人>`。
- 保持现有 300ms 节流与串行。

- [ ] `cargo test -p nowhere-desktop` 通过：排序（Author 优先）+ 候选池放大 + 空结果文案 ≥ 6 例
- [ ] 原有 111 例 np-sources 测试全绿（网易云行为不变）
- [ ] `cargo clippy --workspace --all-targets -- -D warnings` / `fmt` / `cargo test --workspace` 全绿
- [ ] **真机**（主线）：`search 不为谁而作的歌 --artist 明前奶绿 --source bilibili` 能返回那批切片；`search 晴天 --artist 周杰伦 --source netease` 行为不变

## 8. 测试要求

- 全部离线，假源断言"发了什么查询、过滤后剩几条、顺序如何"。
- 夹具补一份"标题含艺人名、上传者不含"的样本。

## 9. 文档影响

- 回报中给出：匹配规则的最终定义、两种 MatchKind 的实际占比、延迟变化。
- 主线据此更新 `命令表` 的 `--artist` 语义，并在 ADR-0004 记一条"UP 空间检索已推迟"。

## 10. 回报格式

四段式。

## 11. 风险

- **标题匹配会过召回**：`明前奶绿` 会带出"提到她的所有视频"。这是产品选定的取舍——**用户要的是"找到那个人唱那首歌"，不是"只找他上传的"**。真实效果请如实报告（命中多少条、其中多少是切片/无关）。
- 拼查询可能稀释关键词（探测里三种都还行，但要复测）。
- 不要顺手改网易云：它的 artist 是结构化字段，改了会破坏精确性。
