## 0. 现象与定位

**现象**：频谱刷新时，终端光标在画面上四处闪动。

**代码位置**：`crates/np-tui/src/main.rs:776`

```rust
frame.set_cursor_position((cursor_x, cursor_y));   // 每帧都调用
```

频谱 20fps → **光标每秒被"移动 + 显示"20 次**，视觉上表现为闪动。

## 1. 先测量（不要直接改）

在 backend 外面包一层计数适配器，统计每秒发出的光标相关序列：

| 计数项 | 含义 |
|---|---|
| `MoveTo` / `SetCursorPosition` | 光标移动次数 |
| `Show` / `Hide` | 光标显隐次数 |

**要求给出改前基线**：`20 帧/秒` 时应能看到约 20 次移动。

## 1.5 社区做法（调研结论）

| 来源 | 手法 |
|---|---|
| CodeWhale PR #1477 | **DECSET 2026** 同步更新，专治 Windows 终端闪烁 |
| renga 提交 | 帧末光标改为 **MoveTo → Show** 顺序，止住 conpty 闪烁 |
| CodeWhale #5023 | 重绘期间**稳定 IME 光标** |
| neovim | 改进光标刷新处理 |
| Ink | 用 `cli-cursor` **隐藏**光标，按需显示 |

**最有效的是 DECSET 2026（同步更新）**：

```
CSI ? 2026 h   ← 开始同步更新
  …整帧绘制…
CSI ? 2026 l   ← 结束，终端一次性呈现
```

**本卡的 A/B/C 三步之上，先做这一条**（P0）：它能同时消掉"光标跳"和"整屏闪"。

- 不支持该序列的终端会忽略，**无副作用**。
- 实现位置：包住每次 `terminal.draw` 的写序列。



### P0. 同步更新（DECSET 2026）

每次绘制前后发 `\x1b[?2026h` / `\x1b[?2026l`，让终端原子呈现整帧。

验收：肉眼无闪烁；终端不支持时行为不变。

### A. 光标样式：稳态方块

启动时设置 `SetCursorStyle::SteadyBlock`（不闪烁）。

- 目的：去掉"闪烁"成分，只剩位置跳动。
- 验收：视觉上不再一明一暗。

### B. 频谱帧率 20fps → 12fps

- 音频可视化 12fps 足够（人眼对柱状图的时间平滑不敏感）。
- 顺带把 CPU 从 2.8% 降下来。
- **不改暂停不刷新**的行为。

### C. 光标位置未变时不发移动

- 记录上一帧的目标 `(x, y)`；相同时**跳过** `set_cursor_position`。
- 风险：ratatui 在 `draw` 中若未设位置会**隐藏光标**，导致输入法候选窗失去锚点。
- 因此本步必须**先在本机实测输入法**（打拼音，看候选窗位置），不可行就回退。

## 3. 验收标准

- [ ] 改前基线：光标移动序列 ≈ 20 次/秒 `[数字]`
- [ ] **P0 同步更新已启用**：绘制前后各发一次 `2026h/2026l` `[数字]`
- [ ] P0 后视觉无闪烁（录屏或连续两帧对比） `[图]`
- [ ] A 后：光标不再闪烁（截图两帧同位置） `[数字]`
- [ ] B 后：移动序列 ≤ 12 次/秒 `[数字]`
- [ ] C 后（若可行）：移动序列 ≈ **0 次/秒**（位置不变时） `[数字]`
- [ ] **输入法**：中文拼音候选窗仍在输入行下方 `[图]`
- [ ] 播放 CPU **≤ 2.8%**（不因修复回升） `[数字]`
- [ ] 频谱观感无明显卡顿（12fps 下） `[图]`

## 4. 非目标

- 不改频谱算法。
- 不改面板布局。

## 6. 风险

| # | 风险 | 缓解 |
|---|---|---|
| 1 | C 步导致光标被隐藏、输入法锚点丢失 | 先实测；不行就只做 A+B |
| 2 | 12fps 让频谱显得"跳" | 已有时间平均（EMA），12fps 应更平滑；如仍卡顿回 15fps |
| 3 | 稳态方块在某些终端不生效 | 记录终端行为；不生效时靠 A+B 兜底 |
