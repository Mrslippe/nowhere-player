## 1. 目标 A：渲染快照测试

把「渲染出来是什么」变成**可 diff 的文本**。

### 1.1 实现方式（不引新依赖）

用 `ratatui::backend::TestBackend`：

```rust
let mut terminal = Terminal::new(TestBackend::new(80, 24)).unwrap();
terminal.draw(|f| render(f, &app)).unwrap();
let rendered = buffer_to_text(terminal.backend().buffer());
```

- **金标文件**存放在 `crates/np-tui/tests/golden/<名字>.txt`；
- 比较时逐行 diff，失败时打印**第一处差异的行号 + 两行内容**；
- `UPDATE_GOLDEN=1 cargo test` 时重写金标（人工确认后再提交）。

**禁止**引入 `insta` 等新依赖（红线）。

### 1.2 必须覆盖的六个画面

| # | 画面 | 重点 |
|---|---|---|
| 1 | 媒体库表格（18 条中的前 5 行） | 中文列宽、表头、选中行 |
| 2 | 错误块（`E_CMD_ARG` + hint） | 前缀、换行、颜色标记不参与文本 |
| 3 | 候选弹层（3 条，高亮第 2 条） | 高亮标记、usage 行 |
| 4 | 播放器条（标题/艺人/进度/视觉区） | 截断、时间格式、进度字符 |
| 5 | 状态栏（焦点左 / 焦点右 / 过滤中） | 三态键位提示 |
| 6 | 启动页（80×24 与 60×20 两种） | 大字、降级、主题名 |

### 1.3 变异测试（证明快照有效）

挑一条金标，**故意改一个字符**（例如把表头 `时长` 改成 `长度`），跑测试确认**失败**并指出差异行；然后改回。
**把这次失败输出贴进回报**——证明快照真的能抓变化。

## 2. 目标 B：文档检查进门禁

新增 `scripts/check-docs.ps1`，检查两类问题：

| 类型 | 规则 |
|---|---|
| **悬空相对链接** | `docs/**/*.md` 中 `](相对路径)` 指向的文件必须存在 |
| **已删路径引用** | 正文出现 `apps/web`、`apps/desktop`、`src-tauri`、`pnpm` → **列出并警告** |

- 悬空链接 → **错误（exit 1）**；
- 已删路径 → **警告**（历史文档里允许出现，但必须显式列出来供人判断）；
- 加进 `check.ps1` 末尾。

## 6. 风险

| # | 风险 | 缓解 |
|---|---|---|
| 1 | 金标在不同终端宽度下不稳定 | 固定 `TestBackend` 尺寸（80×24 等），与真实终端无关 |

| 4 | 快照测试过于敏感，改样式就红 | 这是**预期行为**——改样式就该更新金标并 review diff |
