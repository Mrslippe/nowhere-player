## 1. 背景

M2 要让配置窗变成真终端：用户敲 `play 3`、`queue add ~/Music/a.flac`，程序解析成结构化命令再执行。

这一卡只做**纯解析层**：命令定义、注册表、分词、参数校验、错误建议。**不执行、不接 IPC、不碰前端。**

## 2. 目标

在 `np-core` 新增 `command` 模块：

1. `CommandSpec`：命令名、别名、一句话说明、usage、参数规格。
2. `Registry`：全量命令表、按名/别名查找、拼写建议。
3. `parse(input) -> Result<Parsed, ParseError>`：分词 + 解析 + 校验。
4. `Parsed`：`{ spec, positional: Vec<String>, flags: BTreeMap<String, String> }`。
5. 错误带可读信息：`E_CMD_UNKNOWN`（含 `did you mean`）、`E_CMD_ARG`（含 usage）。

**v1 命令集**（只定义、不实现执行）：

| 命令 | 参数 |
|---|---|
| `play [index\|path]` | 无参=继续 |
| `pause` / `resume` / `next` / `prev` | 无参 |
| `seek <ms\|mm:ss\|±s>` | 1 个位置参数 |
| `vol <0-100\|±N>` | 1 个位置参数 |
| `queue`（无参=list） | 子命令 `add` / `remove` / `clear` / `jump` |
| `mode <repeat off\|one\|all> [shuffle on\|off]` | 见 usage |
| `help [cmd]` / `version` / `clear` | 前端处理，仅登记 |

## 6. 实施要求

### 6.1 分词规则（写进代码注释，测试锁死）

- 空白分隔；`"..."` 与 `'...'` 包裹的内容保持整体（用于含空格的路径）。
- **反斜杠是字面量，不是转义符**——Windows 路径 `C:\Music\a.flac` 必须原样保留。这是与 POSIX shell 的**有意差异**，要在文档注释里写明。
- 引号内不处理任何转义；引号不闭合 → `E_CMD_ARG`（提示"引号未闭合"）。
- 空输入 / 纯空白 → 返回 `None`，不是错误。

### 6.2 查找

- 名字与别名都命中；**大小写不敏感**（`Play` 等价 `play`），但错误建议里显示规范写法。
- 拼写建议：编辑距离 ≤ 2 且取最小者；多个候选按距离再按字典序。
- 子命令（`queue add`）在父命令内解析，不注册成独立顶层命令。

### 6.3 参数校验

- 数字参数：解析失败 → `E_CMD_ARG` + usage。
- `vol` 与 `seek` 的**取值范围不在解析层校验**（`vol 999` 解析成功，执行层钳制）——解析层只管形状，不管语义。
- 多余参数 → `E_CMD_ARG`（不要静默忽略）。

## 7. 验收标准

- [ ] `cargo test -p np-core` 通过，新增 **≥ 20** 个用例，覆盖：
  - 分词：含空格路径（引号）、Windows 反斜杠路径、多个空格、空输入、引号未闭合
  - 查找：规范名、别名、大小写混写、未知命令的建议（`plya` → `play`）
  - 参数：缺参、多参、数字非法、`vol 999` 解析成功、`seek 1:30` 解析成功
  - 子命令：`queue add` / `queue list`（无参）/ `queue bogus`（未知子命令）
- [ ] `cargo clippy -p np-core --all-targets -- -D warnings` 零警告
- [ ] `cargo fmt --all -- --check` 通过
- [ ] 无新增第三方依赖（`Cargo.lock` 不应出现新条目）
- [ ] `lib.rs` 只有 `pub mod command;` + re-export，业务逻辑不越界

## 8. 测试要求

- 全部为纯函数测试，无 IO、无设备。
- 至少 1 个测试断言「反斜杠原样保留」，防止有人把它当转义符改掉。

## 10. 回报格式

## 11. 风险

- 引号与反斜杠的规则最容易反复：**先写测试再写实现**，别边写边改规则。
- 别名不要贪多，`p` 这种要谨慎（与路径冲突）；本卡只允许显式登记的别名。
- 不要为"以后可能加命令"设计插件式注册表——静态表足够。
