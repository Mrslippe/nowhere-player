## 1. 背景

两套终端渲染器已就绪，但**还没被放在同一个界面里对比过**。
本卡把输出模型、输入框、两个渲染器接起来，并内置一套可打分的对比面板——这是 M0 唯一的决策点：用哪套终端。

## 2. 目标

一个可交互的实验室页面，满足：

1. **同一份数据**喂给两个渲染器（不存在"各用各的假数据"）。
2. **三种视图**：`?variant=blocks`、`?variant=xterm`、`?variant=both`（左右分屏，同步滚动）。
3. **可输入**：底部输入框，回车后生成一个新的 `Block`（用本地 mock 生成输出，不接 IPC）。
4. **可评分**：五维打分面板，实时算加权总分，可导出 JSON。
5. **可切换主题**：graphite / amber / ice，验证两套渲染器在换肤下的表现。

## 3. 非目标

- 不接真实命令解析（M1）。
- 不做补全、不做历史（M2）。
- 不改两个渲染器的内部实现（它们已冻结）。
- 不做 IPC 通道。

## 6. 实施要求

### 6.1 页面结构

```
┌──────────────────────────────────────────────────────────┐
│ 顶栏：variant 切换（blocks / xterm / both） · 主题切换 · 清空 │
├──────────────────────────────────────────────────────────┤
│                       终端区域                            │
│   (both 模式下左右各半，中间 1px 分隔线)                   │
├──────────────────────────────────────────────────────────┤
│ › 输入框（回车执行）                                       │
├──────────────────────────────────────────────────────────┤
│ 评分面板（可折叠）：5 维 × 1-5 分 · 加权总分 · 导出 JSON   │
└──────────────────────────────────────────────────────────┘
```

### 6.2 假命令生成器

`mock-commands.ts` 提供 `runMockCommand(input: string): Block`，支持 6 个命令，分别产出对应原语的输出：

| 输入 | 产出 |
|---|---|
| `scan` | progress + table |
| `search 晴天` | table（带可播性标记） |
| `play 1` | text（正在播放…） |
| `perm` | error（`E_LIB_PERMISSION`） |
| `hint` | hint |
| `cover` | media |

未识别输入 → `error`，`code: E_CMD_UNKNOWN`，`hint: did you mean 'scan'?`。
**不要**做成"输入什么都能跑"的假象；未知命令就报未知命令。

### 6.3 两个渲染器的接入

- A：`<BlocksView blocks={blocks} />`（纯受控，数据变即重渲染）。
- B：`<XtermSurface blocks={blocks} />`（内部 reset 后整段重写，**已经是这个语义，不要改**）。
- 两者共享同一个 `blocks: Block[]` 状态，保证"同一份数据"。

### 6.4 同步滚动（both 模式）

- 两侧滚动位置按百分比同步；用 `scroll` 事件 + `requestAnimationFrame` 节流。
- xterm 侧滚动容器是其内部 `.xterm-viewport`，需要通过 ref 拿到；取不到时降级为"不同步"，不报错。

### 6.5 评分面板

| 维度 | 权重 | 交互 |
|---|---|---|
| 视觉完成度 | 30% | 1–5 分按钮组 |
| 交互体验 | 25% | 同上 |
| 中文输入（IME） | 20% | 同上 |
| 性能 | 15% | 同上 |
| 扩展成本 | 10% | 同上 |

- 实时显示：每维得分、加权总分（保留两位小数）、当前领先方。
- `localStorage` 持久化（key: `np.m0.compare`）。
- "导出 JSON"按钮：把评分 + 时间戳 + 两套渲染器的包体积（从 `performance.getEntriesByType('resource')` 粗算也可，拿不到就写 `null`）复制到剪贴板。

### 6.6 视觉

- 顶栏 36px，底部输入 40px，评分面板折叠态 28px。
- 输入框用等宽字体、`›` 前缀、无边框（只有底部 1px `--line`）。
- 终端区域背景 `--bg`，与外层一致（不做卡片、不做圆角死角）。

## 11. 风险

- xterm 在 `both` 模式下宽度减半，`FitAddon` 需要监听容器尺寸变化（`ResizeObserver`），否则列数不对。
- 左右分屏时两边的滚动高度不一致是正常的（行高不同），同步按百分比而非行号。
- 中文输入法测试需要真人；你只需保证输入框是原生 `<textarea>` 或 `<input>`，不要用自绘光标。
