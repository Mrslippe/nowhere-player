## 0. 目标

只抽“接缝”，不重写 UI：

1. `ScrollState`：Browse/Settings 共用滚动窗口。
2. `Chrome`：外框/标题/主题名/状态栏的共享绘制。
3. `Bars`：音量条、音高条、播放进度条的共享块条算法。
4. 评估并只在低风险处抽浮层（SettingsEditor/ChatInput），不改变键位/状态机。

**渲染结果必须与 T-0098 完全一致**；现有 golden 不变。

## 1. 非目标

- 不引入组件树/Widget trait；
- 不改布局基准、键位、状态 TTL、弹幕协议；
- 不重写 App/audio/网络；
- 不新增依赖；
- 不做主题系统重构。

## 2. 授权路径

```text
crates/np-tui/src/**

```

## 3. 实施

### 3.1 ScrollState

```rust
pub(crate) struct ScrollState { pub first: usize, pub visible: usize }
impl ScrollState {
  fn follow(&mut self, selected: usize, total: usize);
  fn range(&self, total: usize) -> Range<usize>;
  fn has_above/has_below(...);
}
```

- Browse 7 行、Settings 6 行；
- 从 render 的滚动计算抽出；
- 现有“↑/↓/↕”和滚动条行为不变；
- 单测 0/边界/选中跳转。

### 3.2 Chrome / Status

抽到 `ui/chrome.rs`：

```text
draw_outer_chrome(frame, area, palette, title, theme)
draw_status_bar(frame, area, palette, state, hints)
```

- Live 与主界面共用的外框形状/粗线/主题名；
- 状态栏左右 1 格、中文提示由调用方传入；
- 不改变现有字符/坐标。

### 3.3 Bars

抽到 `ui/bars.rs`：

```text
draw_block_bar(frame, area, palette, filled, total, spacing)
```

- 音量条 20 格；
- Live 音高条按内容宽自适应；
- 播放进度条按比例填充；
- 统一 `▰` + 颜色区分，禁止 `▱`；
- 各调用方保留自己的数值/时间显示。

### 3.4 浮层（可选，低风险才做）

- `SettingsEditor` 或 `ChatInput` 的状态/键处理如能在不改行为下抽出，可做；
- 如果会改键路由，停止并报告，留 T-0099b。
