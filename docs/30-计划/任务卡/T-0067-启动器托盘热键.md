## 1. 目标

### A. 单二进制自举（关键设计）

**一个 `nowhere-tui.exe` 同时承担"启动器"和"程序本体"**：

```
双击 exe（无 TTY）
  → 检测到不在终端里
  → 用 wt.exe 重新拉起自己（带 profile）并退出
  → WT 里的那份检测到有 TTY，正常跑 TUI
```

- 判据：Windows 上 `GetConsoleMode` 失败 / 标准输出不是终端；
- 拉起命令：`wt.exe -p "Nowhere Player" <exe路径>`；
- **wt 不存在时**回退 `cmd /c start`（并提示"封面将降级为字符"）。

**好处**：用户只有一个可执行文件，不用懂"要先开终端"。

### B. Windows Terminal fragment 安装

按 [DES-009](../../10-设计/Windows-Terminal-外观.md)：

- 首次运行时把 fragment JSON 写到 `%LOCALAPPDATA%\Microsoft\Windows Terminal\Fragments\Nowhere\nowhere.json`；
- **UTF-8 无 BOM**（WT 读不了 UTF-16，这是文档明写的坑）；
- 已存在且内容相同 → 跳过；内容不同 → 覆盖；
- 提供 `config uninstall-fragment` 或卸载时删除。

### C. 托盘

- 图标常驻；菜单：`显示窗口` / `播放·暂停` / `下一首` / `退出`；
- 托盘跑在**独立线程**（Windows 需要消息泵）；
- 与主循环通过 `mpsc` 通信，**不共享可变状态**。

### D. 全局热键

- 默认 `Ctrl+Alt+Space` 播放/暂停；
- 可选 `Ctrl+Alt+←/→` 上/下一首；
- 冲突时**不崩溃**，在状态栏提示"热键注册失败"。

## 2. 非目标

- 不做"关闭窗口后后台继续播放"（进程随窗口结束）。
- 不做开机自启（另开卡）。
- 不做 macOS/Linux 的托盘细节（先 Windows）。

## 5. 测试要求

- fragment 生成：纯函数单测（内容、编码、幂等）。
- 自举判据：可注入的 `is_tty()` 假实现，覆盖三种分支（TTY / 无 TTY+有 wt / 无 TTY+无 wt）。
- 托盘/热键：手动验证（无自动化）。

## 6. 风险

| # | 风险 | 缓解 |
|---|---|---|
| 1 | 托盘消息泵与 crossterm 事件循环冲突 | 托盘独立线程；主循环只收 channel 消息 |
| 2 | 自举时 WT 未安装 → 反复重开 | 记录已尝试标记（env 变量），二次启动不再重开 |
| 3 | fragment 写失败（权限） | 降级为"不装 fragment"，TUI 仍可用 |
| 4 | 热键被系统/其他程序占用 | 注册失败只提示，不阻塞启动 |
