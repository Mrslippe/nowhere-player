## 1. 背景

终端窗现在还是 M0 的"对比实验室"：输入框只跑本地 mock 命令，输出不经过后端。T-0018 已经把 `cmd.exec` 和 `terminal:block` 做出来了，这一卡把前端接上去——敲一条命令，走真实链路。

## 2. 目标

1. 终端窗的输入框改为调用 `cmd.exec`，不再跑 mock。
2. 订阅 `terminal:block`，把块渲染进 `renderers/blocks`（结构化渲染器）。
3. 保留实验室的 `?variant=xterm`，但**默认走真实链路**；mock 只在无 Tauri（浏览器）时兜底。
4. `clear` 在本地处理（清空块列表），不发后端。
5. 首屏显示欢迎块（版本 + `help` 提示），不发命令。

## 3. 非目标

- 不做补全（T-0020）。
- 不做历史（T-0020）。
- 不改两个渲染器的内部实现。
- 不做 xterm 方案的接线（只保留实验室入口）。

## 4. 必读 / 必须核实

1. `docs/30-计划/命令表.md`（1 基序号、`clear` 本地处理）
2. `docs/20-架构/终端输出模型.md`（`Block` 形状）
3. `apps/web/src/features/terminal/`（现有实验室与 `mock-commands.ts`）
4. `apps/web/src/shared/player-bridge.ts`（T-0014 的 IPC 封装风格，照它写）
5. **核实**：`cmd.exec` 的返回是 `{ blockId, ok }`，**输出不在返回值里**，必须靠事件；事件可能先于返回值到达

## 6. 实施要求

- `command-bridge.ts`：`exec(input): Promise<{blockId, ok}>` + `subscribeBlocks(handler)`；浏览器无 Tauri 时退化为 mock（复用现有 `runMockCommand`）。
- **块按 `id` 去重/覆盖**：先收到 `running` 再收到最终块，同一个 `id` 要替换而不是追加两条。
- `blockId` 由前端生成（自增或 `crypto.randomUUID()`），保证唯一。
- 提交后清空输入框、滚动贴底、焦点保持。
- 失败（`ok: false`）不额外弹 UI：错误已经由 `error` 原语渲染在块里。
- `clear` 只清本地块数组，不发后端。
- 首屏欢迎块：版本号 + "输入 help 查看命令"。
- 保留 `?variant=xterm` 与 `?variant=both` 的实验室入口（开发期用），但默认是 `blocks` + 真实链路。

## 11. 风险

- **事件先于返回值**：不要写完 `await exec()` 才开始订阅；订阅必须在组件挂载时就建立。
- `terminal:block` 是广播到所有窗口的（T-0018 用 `app.emit`），播放器窗也会收到——本卡的订阅只发生在终端窗，天然隔离；但如果将来播放器窗也订阅，需要按块 id 过滤。
- 不要为了"看起来实时"而给块加打字机动画——那会让 T-0020 的补全逻辑更难做。
