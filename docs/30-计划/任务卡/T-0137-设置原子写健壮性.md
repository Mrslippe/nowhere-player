## 0. 事实基线

- `Settings::save` 固定写 `settings.json.tmp`，无重试。
- 用户在设置页快速改动时偶发“写入临时设置文件失败”。
- 错误发生在 `fs::write(tmp)`，不是设置值校验或 `rename`。
- 最常见原因是 Windows Defender/索引短暂占用固定 tmp，或两个 SettingsHandle/进程同时写。

## 1. 目标

- 临时文件名唯一：`settings.json.<pid>.<counter>.tmp`，避免并发碰撞。
- 写入使用 `OpenOptions` + `write_all` + `sync_all`，关闭后再 rename。
- 对 `PermissionDenied` / `WouldBlock` 等暂时性错误做 3 次短退避重试。
- 失败时保留原 `settings.json`，清理本次临时文件；错误信息带路径与 OS 错误。
- 并发保存测试：多线程写同一目录不报错，最终文件是合法 JSON。
- 不改变设置文件格式、key、默认值。

## 2. 非目标

- 不做多进程锁/合并；最后写入者胜出。
- 不改 `SettingsHandle` 的 Mutex 语义。
- 不新增依赖。

## 5. 结果

2026-11-21：

- `Settings::save` 改为唯一临时文件：`settings.json.<pid>.<counter>.tmp`。
- 写入改为 `OpenOptions` + `write_all` + `sync_all`，关闭后再 rename。
- `PermissionDenied` / `WouldBlock`（Windows 共享冲突常见映射）重试 3 次，20/40ms 退避；rename 同样重试。
- 失败时保留原 `settings.json`、清理本次 tmp；错误信息带临时文件路径与 OS 错误。
- 新增测试：8 线程并发保存、唯一 tmp 清理、rename 失败保留原路径。
- 验证：`cargo test -p np-core settings::tests` 16 passed；`cargo clippy -p np-core --all-targets -- -D warnings` 通过。
- 说明：多进程仍是最后写入者胜出；不做跨进程锁/合并。
