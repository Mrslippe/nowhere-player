## 0. 事实基线

| `np-app` | 在线 prepare 时下载封面 → `store_cover` |

| 二进制 | 10.9 MB |

## 1. 目标

**把封面从"数据管线"里彻底摘掉，只保留数据库字段（不删列）。**

### A. `np-library`：停止提取与缓存

- 扫描时**不再解析内嵌封面**（省 CPU 与 IO，扫描更快）；
- 不再写 `covers/` 目录；
- **保留** `tracks.cover_key` 列（schema 不动，避免迁移风险）；
- `store_cover()` 保留签名但标记 `#[deprecated]` 或直接删除（见 B）。

### B. `np-app`：停止下载封面

- 在线 prepare 不再抓封面；
- 删除对 `store_cover` 的调用。

### C. 依赖清理

- `np-library` 移除 `image` 依赖（若无其它用途）；
- `cargo tree -p np-tui | grep -c image` 应为 **0**；
- 报告二进制体积变化。

## 2. 产品裁决（2026-11-12 扩展）

> 「都可以删」+「全部删掉吧保证项目纯净，反正以后要用再加回来」

**因此本卡升级为"彻底移除封面子系统"**，包括：

| 项 | 处理 |
|---|---|
| `covers/` 目录里的存量文件 | **删除**（启动时一次性清理并记日志） |
| 数据库 `cover_key` 列 | **删除**（迁移 v3，迁移前照常备份 `.db.bak`） |
| `image` crate | **从整个 workspace 移除** |
| `cache` 命令的 `covers` 类别 | **删除**（`cache stat/clear` 只保留 `streams`/`all`） |
| `library stat` 的"封面缓存"行 | **删除** |
| 封面相关单测/夹具 | **删除** |

**恢复方式（写进文档）**：需要时从 git 历史取回，并重新迁移 schema；`cover_key` 列删除后不能"就地恢复"。

### 2.1 删除的安全要求

1. **迁移前必须有备份**（沿用现有 `.db.bak` 机制）；
2. 删除 `covers/` 时**打一行日志**：`covers: removed N files`；
3. 失败不阻塞启动（目录占用/权限问题只警告）；
4. **不做后台静默删除**——只在启动时执行一次，且写日志。

## 3. 授权路径（扩展）

```
crates/np-library/src/**          ← 停止提取、删除 covers 目录逻辑、迁移 v3
crates/np-app/src/**              ← 停止下载、cache/library 输出调整
crates/np-core/src/**             ← 仅限：删除 cache 的 covers 类别、命令帮助文本
crates/*/Cargo.toml               ← 移除 image 依赖
```

**禁止**：`crates/np-tui/**`（已完工）、`crates/np-audio/**`、`apps/**`、`docs/**`

### 3.1 np-core 的窄授权说明

只允许改**与封面相关的**：`cache` 命令的类别枚举、help 文本、以及因此受影响的正则/解析测试。
**不许改** 命令语法、错误码、`Output` 契约。

## 5. 风险

| # | 风险 | 缓解 |
|---|---|---|
| 1 | `image` 被其它 crate 间接使用 | `cargo tree --workspace -i image` 先查 |
| 2 | 删 `store_cover` 破坏 `np-app` 编译 | 一起改，先改调用方 |
| 3 | 扫描耗时对比不公平（磁盘缓存） | 清 OS 缓存不现实 → 用**同一文件集跑两次取第二次**，并在回报说明方法 |
| 4 | 未来想恢复封面要重写 | 记录在 `当前状态` 的"已知取舍"里 |
