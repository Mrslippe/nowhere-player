## 1. 背景（真机验收发现）

在线曲目能搜、能下、能播（`status: playing`，位置正常推进），但**播放器小窗显示的是缓存文件名**：

```
bilibili-BV1BZbSzZEGT      ← 现在
【Hi-Res无损音质】｜《晴天》- 周杰伦   ← 应该是这个
```

原因：播放器窗靠 `library.trackByPath(path)` 取元数据，而**远程曲目不在库里**，只能退回"文件名去扩展名"。

这一条不修，M5 的能力用户看不出来——他刚搜到的那首歌，播放器上显示一串代号。

## 2. 目标

1. 下载完成后，把远程曲目的元数据登记到一个**会话级映射**：`缓存路径 → (source, source_id, title, artist, duration_ms)`。
2. `library.trackByPath` 查不到时，**回退查这张映射**，返回一个 `Track` 形状的对象（`kind: "remote"`）。
3. 前端不改（它已经在调 `trackByPath`）。

## 3. 非目标

- 不做远程封面（网易云无 `picUrl`，B 站图需带 Referer 下载 + 违反 CSP 直连；另开卡）。
- 不做远程曲目入库。
- 不做歌词。

## 6. 实施要求

- 映射存在 `OnlineService` 内（`Mutex<HashMap<PathBuf, RemoteMeta>>`），**会话级，不持久化**。
- `RemoteMeta { source: String, source_id: String, title: String, artist: String, duration_ms: u64 }`。
- `Track` 形状：`kind: "remote"`、`path` 为缓存路径、`source` 为源 id、`source_id` 为远程 id、`title`/`artist`/`duration_ms` 填真实值、`cover_key` 为空串、其余字段给合理默认（`album` 空、`track_no` 0 等）。
- **优先级**：本地库命中优先；未命中再查映射。两者都 miss 返回 `null`（前端已有回退）。
- 下载失败或未完成时不登记。

## 7. 验收标准

- [ ] `cargo test -p nowhere-desktop` 通过，新增 ≥ 5 例：
  - 本地命中时不查映射
  - 远程命中返回 `kind: "remote"` + 正确字段
  - 两边都 miss → `None`
  - `prepare` 成功后映射里有该路径
  - `prepare` 失败不登记
- [ ] `cargo clippy --workspace --all-targets -- -D warnings` / `fmt --check` / `cargo test --workspace` 全绿
- [ ] **真机**（主线）：`play <在线序号>` 后，播放器小窗显示真实标题与艺人

## 8. 测试要求

- 全场离线，假源 + 假下载器。

## 9. 文档影响

- 回报中给出：`RemoteMeta` 字段、`Track` 的默认值选择、映射的生命周期。

## 10. 回报格式

四段式。

## 11. 风险

- **别让远程元数据污染本地查询路径**：`trackByPath` 的本地实现不要改，只加一层 fallback。
- 缓存文件被清理（500MB LRU）后映射还在——这会导致"元数据有、文件没了"。**清理时同步移除映射**，或在播放前校验文件存在。
- `kind: "remote"` 是新增取值，前端如果有按 `kind` 分支的逻辑要看一眼（当前没有）。
