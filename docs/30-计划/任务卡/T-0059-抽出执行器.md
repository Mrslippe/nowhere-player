## 1. 目标

把 `Executor` 及其依赖抽到新 crate **`crates/np-app`**，Tauri 侧只留薄壳。

### 1.1 必须消除的 Tauri 依赖（12 处）

| # | 依赖 | 处理 |
|---|---|---|
| 1 | `AppHandle` 取 `app_config_dir` / `app_cache_dir` | 改成**构造时注入 `Paths` 结构体** |
| 2 | `app.emit(...)`（`theme:changed`、`player:*`） | 抽 `trait EventSink { fn emit(&self, name, payload) }`；Tauri 实现发事件，TUI 实现写到内部状态 |
| 3 | 窗口操作（显示/隐藏/置顶） | 抽 `trait WindowOps`；Tauri 实现调窗口 API；TUI 实现为空操作 |
| 4 | 播放器实例 | 已是 `np-audio::Player`，与 Tauri 无关，直接搬 |

### 1.2 目标结构

```
crates/np-app/
  src/lib.rs        pub struct Executor { ... }
  src/paths.rs      struct Paths { config_dir, cache_dir, data_dir }
  src/ports.rs      trait EventSink / trait WindowOps
  src/command/      ← 从 command_exec.rs 搬来

apps/desktop/src-tauri/src/
  command_exec.rs   ← 只剩薄适配：把 Tauri 的 AppHandle 适配成 Ports
```

## 2. 硬约束

1. **现有 Tauri 应用零回归**：所有 697 个测试必须继续通过，行为不变。
2. **不重写逻辑**：这是**搬迁 + 注入口**，不是重构。任何"顺手优化"都不要做。
3. **`np-app` 不得依赖 `tauri`**：`cargo tree -p np-app | grep tauri` 必须为空。
4. 事件名与负载格式**保持不变**（ARCH-005 契约）。

## 3. 非目标

- 不写任何 TUI 代码（T-0060）。
- 不改命令语义。
- 不删 `apps/web`（迁移最后一步才删）。

## 6. 测试要求

- 搬迁后**不新增测试**也要全绿——这本身是回归证明。
- 若某处因注入而必须改签名，补对应单测。

## 7. 文档影响

- 回报给出：`Paths` / `EventSink` / `WindowOps` 的最终定义，以及 `command_exec.rs` 剩余职责。
- 主线更新 `项目结构规范`（新增 `np-app`）与 ADR-0006。

## 8. 风险

- **11k 行搬迁容易混入行为改动**：要求每次移动后 `cargo test --workspace` 全绿再继续，分 3–4 次提交。
- **事件 emit 抽取**：`player:*` 是高频事件，抽成 trait 时注意不要引入每次 emit 的堆分配。
- **`WindowOps` 可能过度设计**：TUI 侧多数操作是空实现——若实现后发现只有 2–3 个方法，就直接用 `Option<Arc<dyn WindowOps>>`，别造大接口。
