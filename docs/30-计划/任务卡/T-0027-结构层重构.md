## 1. 背景

M4 要做 `phosphor` skin，但现在的样式把**结构决策**（圆角、边框、阴影、密度、字体）和**颜色决策**混在一起写在组件 CSS 里。不拆开，换 skin 就得复制整套组件样式。

**这一卡只做拆分，不产出任何新外观。** 完成后 `plain` 看起来必须和现在一模一样。

## 2. 目标

把 `apps/web/src/design/` 与 `features/*/*.css` 的样式分成三层：

```
tokens.css     颜色 + 字号 + 间距的原始值（已有，扩充）
skin/*.css     结构决策：圆角、边框、阴影、密度、字体、装饰母题
components     组件样式，只引用上面两层的变量，不写死值
```

并引入 `data-skin="plain"`，窗口根元素上挂这个属性。

## 3. 非目标

- **不做 `phosphor`**（T-0028）。
- 不改任何组件的 JSX 结构（除加 `data-skin` 的挂载点）。
- 不做主题加载器（T-0029）。
- 不改视觉：`plain` 必须像素级不变。

## 4. 必读 / 必须核实

1. `docs/10-设计/设计语言.md`（现有 token 体系）
2. `apps/web/src/design/tokens.css` / `themes.css` / `components.css`
3. `apps/web/src/features/player/player.css`、`features/terminal/terminal.css`
4. `docs/20-架构/adr/ADR-0003-主题模型.md`（skin 的定义与边界）
5. **核实**：现在有多少处硬编码的结构值（`border-radius`、`box-shadow`、`font-family`、`border`）

## 6. 实施要求

### 6.1 结构变量清单（必须先定，写进 `design/skin/base.css`）

| 变量 | 含义 | `plain` 的值 |
|---|---|---|
| `--np-radius-card` | 卡片圆角 | `18px` |
| `--np-radius-inner` | 内部元素圆角 | `12px` |
| `--np-border-card` | 卡片描边 | `1px solid var(--line)` |
| `--np-shadow-card` | 卡片投影 | `var(--shadow-1)` |
| `--np-font-ui` | UI 字体栈 | 现状 |
| `--np-font-mono` | 等宽字体栈 | 现状 |
| `--np-density-line` | 终端行高 | `1.6` |
| `--np-bleed` | 是否全出血（无内边距/无卡片） | `0` |

### 6.2 拆分规则

- **颜色不进 skin**（颜色归 tokens），skin 只管"形状、边框、阴影、字体、密度、装饰"。
- 组件 CSS 里出现 `border-radius: 18px` 这种字面量 → 全部换成 `var(--np-radius-*)`。
- 装饰母题（A 的刻度线、C 的印刷线）**这一卡不做**，只留变量位。

### 6.3 不变量

- `plain` 的渲染结果必须与改动前**逐像素一致**（用截图对比，允许 ≤1px 抗锯齿差异）。
- 组件 JSX 结构不变（`data-skin` 只加在窗口根）。

## 8. 测试要求

- 现有组件测试必须全绿——如果某个测试因为样式改动而失败，说明改动了结构，要回退。

## 10. 回报格式

四段式；验证段必须包含视觉回归证据。

## 11. 风险

- **这是全项目最容易引入回归的一卡**：CSS 拆分不影响类型，测试也不会失败，只有眼睛能看出来。**必须做截图对比**，不能只看测试绿。
- 拆分粒度不要过细：`--np-radius-1/2/3` 这种编号变量会让 skin 作者猜语义。用**角色名**（card / inner / control）。
- 如果发现某个组件必须改结构才能拆干净，**停下来报告**——那说明组件设计有问题，不该在这一卡里顺手改。
