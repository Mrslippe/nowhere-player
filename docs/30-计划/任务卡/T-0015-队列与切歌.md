## 1. 背景

T-0013 把 `next`/`prev` 留成了 `E_UNSUPPORTED`——因为没有队列。这一卡补上：队列模型、切歌、循环/随机模式。

## 2. 目标

1. `np-core` 增加 `Queue`：有序曲目、当前指针、`next`/`prev`/`jump`/`remove`/`clear`、`shuffle`/`repeat` 语义。
2. `PlayerActor` 接队列：`next`/`prev` 真正切歌；自然播完自动进下一首。
3. IPC 增加 `queue.list` / `queue.add` / `queue.remove` / `queue.clear` / `queue.jump`。
4. `PlaybackState.mode` 真正反映 `repeat/shuffle`，并新增 `queueLength` / `queueIndex`（可空）。
5. 队列**只存内存**，持久化留到 M3。

## 3. 非目标

- 不做队列 UI（前端是 T-0014 的范围）。
- 不做持久化、不做播放列表文件。
- 不做在线曲目（M2）。
- 不做 gapless 预加载（M1 后期）。

## 4. 必读 / 必须核实

1. `docs/20-架构/音频架构.md` §5（`PlaybackState` 已冻结字段）
2. `crates/np-core/src/player.rs`（现有状态机与 `PlayerCommand`）
3. `apps/desktop/src-tauri/src/player_actor.rs`（命令循环、`next`/`prev` 当前返回 `E_UNSUPPORTED`）
4. 核实：actor 的 tick 循环是否已有"ended 边沿"处理点，切歌要复用同一处

## 6. 实施要求

- `Queue` 是纯数据结构 + 纯函数，**不持有 Player**，可在无设备环境单测。
- 切歌语义：`next` 在 `repeat=off` 且是最后一首时停在上首并置 `ended`；`repeat=all` 回绕。
- `shuffle` 用「先打乱顺序、再按序播」而不是每次随机取（避免重复播同一首）。
- **`next` 必须在 actor 线程内执行**：先 `player.stop()`/drop 旧 `Player`，再 `Player::open` 新文件，最后决定是否 `play`。整个替换过程不能跨线程移动 `Player`。
- 打开失败时：跳过该曲目、尝试下一首，最多连续跳过 3 首；全失败则 `status: error` 并停。
- 队列变更后立即发 `player:state` 快照（含 `queueLength`/`queueIndex`）。
- `PlaybackState` 新增字段必须可选（`null` 表示未知），不破坏 T-0014 的消费方。

## 7. 验收标准

- [ ] `cargo test -p np-core` 通过，`Queue` 新增 ≥ 10 个用例（next/prev 边界、repeat 三态、shuffle 不重复、remove 当前项、clear）
- [ ] `cargo test -p nowhere-desktop` 通过
- [ ] `cargo clippy --workspace --all-targets -- -D warnings` / `fmt --check` 零问题
- [ ] `tauri dev` 下：加入 3 首 → `player.play` → 自然播完自动进下一首（连续两次）
- [ ] `player.next` 在最后一首且 `repeat=off` 时不越界；`repeat=all` 时回绕
- [ ] 队列为空时 `next` 返回 `E_UNSUPPORTED`，不 panic
- [ ] 加入一个不存在的文件，播放时自动跳过并播下一首（最多跳 3 首）
- [ ] `player:state` 快照包含 `queueLength`/`queueIndex` 且随队列变化

## 8. 测试要求

- `Queue` 的纯函数测试为主，不依赖音频设备。
- actor 层只做 1–2 个集成测试（可用临时 wav，生成方式参照 `np-audio/examples`）。

## 9. 文档影响

- 回报中给出：`Queue` 的公开 API、`PlaybackState` 的新增字段、切歌时的资源释放时序。

## 10. 回报格式

四段式。

## 11. 风险

- **`Player` 不能跨线程**：切歌必须在 actor 线程内完成，不能 `spawn` 出去做。
- 切歌时旧 `Player` 未 drop 就 open 新的，可能两个输出流同时开 → 必须显式 `take()` 旧值并 drop。
- `seek` 与 `next` 并发到达时，latest-wins 的合并逻辑要覆盖切歌。
