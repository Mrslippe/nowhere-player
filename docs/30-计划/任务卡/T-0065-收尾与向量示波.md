## 1. 目标

### A. 修主题背景（bug，最高优先）

**现象**：状态栏已显示 `主题 TUI 票据`，但整屏背景仍是暗色。

**要求**：
- 模式 B（选了具体主题）时**必须整屏绘制主题 `bg`**（先 `Clear`，再铺底色）。
- 模式 A（跟随终端）**不得绘制背景**（保持现状）。
- 验收：`theme set tui-paper` 后截图里背景是纸色 `#f2efe9`，不是暗色 `[图]`。

### B. `np-audio` 立体声 tap

```rust
pub fn latest_stereo(&self, left: &mut [f32], right: &mut [f32]) -> usize
```

- 环形缓冲同时保存 L/R（若源是单声道，两边填相同值）。
- **不改变现有 `latest()` 的语义**；26 个音频测试必须继续通过。
- 写入仍在音频回调，**无锁、无分配**。

### C. Vectorscope

- 用 `latest_stereo` 取 L/R，画 **Lissajous 图**（X=左，Y=右）。
- Braille 画布；无信号时画一条 45° 参考线。
- 单声道源（L==R）会退化成一条直线——**这是正确行为**，不是 bug。

## 4. 已定的技术判断（不要重开）

**不引 `rustfft`。** 理由（代理的评估，我采纳）：
- 仍是 2048 点 / 20fps，手写 radix-2 足够；
- Hann + dB + 平均都是线性成本，实测 2.8%；
- Vectorscope 只吃时域样本，不需要 FFT；
- 真正需要它的场景（8192 点、多视图同时 FFT）目前不存在。

**但 CPU 2.8% 已贴近 3% 上限**：本卡任何新增绘制，**若播放 CPU 超过 3%，先把帧率降到 15fps**，不要靠"再优化一点"。

## 6. 风险

| # | 风险 | 缓解 |
|---|---|---|
| 1 | 整屏绘底影响滚动/重绘性能 | 只填一次（Clear + 底色），不逐帧重填整屏 |
| 2 | 立体声缓冲翻倍内存 | 8192 槽 × 2 × 8B ≈ 128KB，可接受 |
| 3 | Vectorscope 在 28 列面板里太小看不清 | 沉浸模式里为主；面板内可省略或极简 |
| 4 | 降帧后动效观感变差 | 15fps 对频谱仍够用；优先保 CPU |
