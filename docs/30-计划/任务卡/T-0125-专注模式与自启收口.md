## 0. 事实基线

- 开机自启已实现：`startup.rs` 写 HKCU Run，`main.rs` 每次启动按 `startup.enabled` 自愈。
- `tui.focusMode` 现在只传给 Windows Terminal 的 `--focus`，不是 UI 专注模式。
- 主界面布局为 Browse/List 上区 + Player 下区。

## 1. 目标

- 新增 `App.focus_mode`，启动时读 `tui.focusMode`。
- `Ctrl+F` 切换：隐藏 Browse/List，Player 占满内容区；保留外框、状态栏、Controller 浮层。
- 小终端（宽 <50 或高 <12）回退普通布局并提示。
- 切换时写回 `tui.focusMode`，下次启动保持；状态栏显示退出提示。
- `startup::set_enabled` 幂等：值与当前 exe 一致时不重复写注册表。
- 启动自启失败时在状态栏提示，不静默。
- 更新 README / TUI 交互模型 / CHANGELOG。

## 2. 非目标

- 不做无边框窗口或 Windows Terminal 外观改造。
- 不做“开机最小化到托盘”。
- 不改 Live 页布局。
- 不改 `np-video`。

## 5. 结果

2026-11-21：

- 专注模式：
  - `App.focus_mode`（默认 false）；`main` 启动时读 `tui.focusMode`。
  - `keymap` 新增 `ToggleFocusMode` 与 `CONTROL_BINDINGS`（`Ctrl+F`，label 同源）；
    普通 `f`、`Ctrl+Shift+F` 不受影响，未登记的 Ctrl 组合仍按原键解析。
  - Live 页解析但忽略，状态栏提示「直播中不可切换专注模式」。
  - 非 Live 切换写回 `tui.focusMode` 并刷新设置页；设置页切换「专注模式」也立即生效，
    「动效」仍提示下次启动生效。
  - `render` 在 Live 之后、普通布局之前分支：外框 + `layout_inner(full)` 上的 Player +
    Controller/登录浮层 + 状态栏；50×12 以下回退普通布局，退出提示仍保留。
- 自启：
  - `startup::set_enabled` 先 `reg query`；值等于当前 exe 时 enable 不再写，
    disable 不存在直接成功；`REG_SZ` 解析与幂等决策拆成纯函数并单测。
  - `NP_TUI_STARTUP_KEY` 覆盖值名保留；路径整体加引号，含空格也正确。
  - `main` 自启失败写状态栏「自启设置失败：…」，不再静默。
- 验证（2026-11-21）：
  - `cargo fmt --all`：通过；
  - `cargo test -p np-tui`：338 passed / 0 failed / 1 ignored
    （新增 keymap 1、startup 4、focus 渲染/回退 3、controller 写回 1、设置立即生效 1）；
  - `cargo clippy -p np-tui --all-targets -- -D warnings`：通过。
- 未执行：真实注销/重启自启人工验收（卡要求 `[人工]`），留给验收阶段。
