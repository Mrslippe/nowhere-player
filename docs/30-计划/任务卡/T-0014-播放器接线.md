---

## 1. 背景

播放器小窗现在还是 M0 的静态原型（假数据、`?state=` 切换）。T-0013 已经把真实状态推上来了，这一卡把它接上——接完产品就"能听"。

## 2. 目标

1. 订阅 `player:state` 与 `player:position`，用真实数据渲染小窗。
2. 首帧调 `player.snapshot` 拿初始状态，避免空窗。
3. 进度条用 rAF 插值，视觉 60fps，**不因 4 Hz 事件而跳**。
4. 控件接通：播放/暂停、上一首/下一首（当前返回 `E_UNSUPPORTED`，UI 要能优雅提示）。
5. 拖动进度条 → `player.seek`；滚轮 → `player.volume`。
6. 错误态：订阅到的 `error` 非空时显示红点 + 悬停提示。

## 3. 非目标

- 不做队列 UI（T-0015）。
- 不做歌词、封面加载（无曲目元数据）。
- 不做窗口拖拽（已有 `data-tauri-drag-region`，Tauri 原生支持，本卡只验证能用）。

## 4. 必读 / 必须核实

1. `docs/20-架构/音频架构.md` §5（事件名与 `PlaybackState` 字段，**已冻结**）
2. `apps/web/src/features/player/`（现有原型）
3. 核实：`@tauri-apps/api` 的 `event.listen` 在当前版本可用；`invoke` 的点号命令名是 `player.snapshot` 等

## 5. 授权路径

**可写**：

```
apps/web/src/features/player/**
apps/web/src/shared/player-bridge.ts     ← 新建：封装 listen/invoke
apps/web/src/shared/player-bridge.test.ts
```

**禁改**：`crates/**`、`apps/desktop/**`、`app/**`、`design/**`、`docs/**`、`package.json`、`pnpm-lock.yaml`

## 6. 实施要求

- `player-bridge.ts`：`subscribe(handlers)` 返回取消函数；浏览器环境（无 Tauri）退化为 mock，不抛错——这样 `pnpm dev` 仍可预览。
- 位置插值：收到 `positionMs` 后记录 `(position, receivedAt)`，用 `requestAnimationFrame` 外推；每收到新值校准一次（不要累加漂移）。
- 播放/暂停按钮根据 `status` 切换图标，点击发 `player.play` / `player.pause`。
- `status === "ended"` 时进度条归位、按钮变播放。
- 每一条 invoke 失败都要 catch，把 `{code,message}` 显示在悬停提示里，**不要静默吞掉**。
- 组件内禁止硬编码色值；只用 design token。

## 7. 验收标准

- [ ] `pnpm -C apps/web typecheck` / `test`（带路径过滤）通过
- [ ] `tauri dev` 下用 devtools 调 `player.play` 打开一个 wav，小窗显示真实标题/时长并开始走进度
- [ ] 播放中进度条连续移动，无 4 Hz 阶梯感（录 5 秒 GIF 或说明判定依据）
- [ ] 点暂停 → 0.2s 内 UI 变 ▶ 且进度停住；再点继续从原位继续
- [ ] 拖动进度条 → `seek` 生效，松手后位置不跳回
- [ ] `next` 返回 `E_UNSUPPORTED` 时，UI 显示一次性提示而不是崩溃
- [ ] 浏览器 `pnpm dev` 下不报错（mock 模式）
- [ ] 组件内无 `#RRGGBB`

## 8. 测试要求

- `player-bridge` 的单测：mock 模式下 subscribe 不抛错、事件能派发。
- 进度插值的纯函数单测：给定 `(position, elapsed, duration)` 输出钳制在 `[0, duration]`。

## 9. 文档影响

- 回报中给出：`PlaybackState` 的前端镜像类型、插值算法参数、mock 模式的边界。

## 10. 回报格式

四段式。

## 11. 风险

- 事件可能在小窗还没挂载时就到了 —— 先 `snapshot` 再 `listen`，避免漏掉首帧。
- `@tauri-apps/api` 的 `listen` 在浏览器会抛错，必须 try/catch。
- 拖拽进度条与 4 Hz 事件会打架：拖动期间**暂停外推**，以指针位置为准。
