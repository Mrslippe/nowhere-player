# T-0010 CI 门禁

| 字段 | 值 |
|---|---|
| 卡号 | T-0010 |
| 里程碑 | M0 |
| 依赖 | T-0002 |
| 预估 | 0.5 天 |
| 时间预算 | 墙钟 3 小时 |
| 并行 | 可与 T-0009 并行（目录不重叠） |
| 负责人 | 实现者 J |

---

## 1. 背景

现在所有门禁都靠人手动跑 `scripts/check.ps1`，换台机器或忘了跑就会漏。M0 收尾需要一条 CI，把"门禁绿"变成客观事实。

## 2. 目标

在 GitHub Actions 上跑两件事：

1. **Web**：`pnpm install --frozen-lockfile` → `typecheck` → `test` → `build`
2. **Rust**：`fmt --check` → `clippy -D warnings` → `test --workspace`，矩阵覆盖 **Windows + Ubuntu**

## 3. 非目标

- 不做发布/打包（M6 再做 release workflow）。
- 不做缓存优化（先用最朴素的，跑通再说）。
- 不做 macOS runner（M0 不验证；后续加一行即可）。
- 不改任何源代码、不改 `scripts/check.*`。

## 4. 输入（按顺序读）

1. `AGENTS.md` §3（验证命令）
2. `scripts/check.ps1`（本地门禁的实际内容，CI 要与它一致）
3. `apps/web/package.json`、`Cargo.toml`（工具链与脚本名）

## 5. 授权路径

**可写**：

```
.github/workflows/ci.yml
.github/workflows/*.yml（如需拆分）
```

**禁改**：其余全部。

## 6. 实施要求

### 6.1 触发

```yaml
on:
  push:
    branches: [master, main]
  pull_request:
```

### 6.2 Job: web

- `runs-on: ubuntu-latest`
- `actions/checkout@v4`
- `pnpm/action-setup@v4`（版本读 `package.json` 的 `packageManager`）
- `actions/setup-node@v4`（`node-version: 24`，`cache: pnpm`）
- 步骤：`pnpm install --frozen-lockfile` → `pnpm -C apps/web typecheck` → `pnpm -C apps/web test` → `pnpm -C apps/web build`

### 6.3 Job: rust

- `strategy.matrix.os: [windows-latest, ubuntu-latest]`
- Linux 需要先装 Tauri 依赖（这是本卡最容易踩的坑）：

```
sudo apt-get update
sudo apt-get install -y libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf libgtk-3-dev
```

- 步骤：`actions/checkout@v4` → `dtolnay/rust-toolchain@stable`（带 `rustfmt, clippy`）→ `cargo fmt --all -- --check` → `cargo clippy --workspace --all-targets -- -D warnings` → `cargo test --workspace`

> ⚠️ **构建顺序**：clippy/test 会编译 `apps/desktop/src-tauri`，它需要 `apps/web/dist`（`generate_context!` 读取）。所以 rust job 也要先跑前端构建，或者把前端 dist 作为 artifact 传递。
> 推荐做法：在 rust job 里加一步 `pnpm install --frozen-lockfile && pnpm -C apps/web build`（简单、可靠），并在注释里写明原因。

### 6.4 约束

- 不加任何第三方 action，除 `actions/*`、`pnpm/action-setup`、`dtolnay/rust-toolchain`。
- 不使用 `continue-on-error`。
- 单 job 超时设 `timeout-minutes: 30`。

## 7. 验收标准

- [ ] `.github/workflows/ci.yml` 存在，YAML 缩进正确（用 `python -c "import yaml,sys;yaml.safe_load(open('.github/workflows/ci.yml'))"` 验证；若无 python 则用 `node --input-type=module -e "..."` 前先确认有 js-yaml，不可用就人工逐行核对并在回报说明）
- [ ] workflow 里的每一条命令，你都**在本地实际跑过并记录退出码**（GH 特有步骤除外）
- [ ] `git status` 显示只新增了 `.github/` 下的文件
- [ ] 未修改任何源代码、脚本、配置
- [ ] 回报中贴出完整的 `ci.yml` 内容（供主线评审）

## 8. 测试要求

无法在本地跑 GitHub Actions。验收以"命令等价性"为准：CI 里跑的每条命令，本地必须跑通。

## 9. 文档影响

- 回报中给出：`ci.yml` 全文、本地逐条命令的退出码表、以及你对"前端 dist 依赖"这一坑的处理方式。
- 主线会在 `AGENTS.md` §3 补一行"CI：GitHub Actions，见 .github/workflows/ci.yml"。

## 10. 回报格式

四段式。验证段用表格列出每条命令 + 退出码。

## 11. 风险

- **Ubuntu 上 Tauri 编译最容易失败**：缺 `libwebkit2gtk-4.1-dev` / `libappindicator3-dev` 会直接报错，务必按 §6.3 装全。
- `windows-latest` 上 WebView2 已预装，不需要额外步骤。
- `pnpm install` 会因为 `pnpm-workspace.yaml` 的 `allowBuilds` 生效，不需要额外参数。
- 如果 rust job 因 dist 缺失失败，按 §6.3 的推荐做法加前端构建步骤，不要改源代码。
