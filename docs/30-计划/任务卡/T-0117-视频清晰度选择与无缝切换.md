## 0. 事实基线

- 视频 playurl 当前固定 `qn=10000`；`PlayInfo.accept_qn` 真机为 `[10000,400,250]`。
- 用户要求窗口内清晰度选择，**尽量无缝**，不重建窗口。
- 方案：同一个 mpv 进程用 IPC `loadfile <url> replace` 换流，不重启 `np-video`、不销毁窗口。
- 质量由 TUI 取（需要登录 cookie/Transport），np-video 不直接请求 playurl。

## 1. 目标

1. `np-live` 增加按 qn 取视频 playurl：
   ```text
   video_play_info_url_with_qn(room_id, qn)
   fetch_video_play_info_with_auth_qn(...)
   ```
2. TUI 把 `accept_qn` 转成质量列表，随请求传给 np-video：
   ```text
   quality 10000 原画
   quality 400 蓝光
   quality 250 超清
   current_qn 10000
   ```
3. 底部控制条上显示当前清晰度，点击弹原生 Win32 popup menu；
4. 选中后 np-video stdout 发：
   ```text
   control quality 400
   ```
   TUI 用 qn=400 重新取 URL，校验后向 np-video 发：
   ```text
   load <url>
   ```
5. np-video 对现有 mpv 发 IPC：
   ```json
   {"command":["loadfile","<url>","replace"]}
   ```
   不重启宿主窗口；保留窗口、音量、暂停态；刷新 cache 后 speed 控制继续。
6. URL 不写 `np-video.log` / `mpv.log` 可检索字段；只在内存和 IPC 中出现。
7. 失败处理：TUI 取流失败保留当前视频；np-video `loadfile` 失败时回退上一 URL 并 stdout `error`。

## 2. 非目标

- 不保证清晰度切换完全零黑帧；`loadfile` 期间允许短缓冲，但窗口/进程不重建。
- 不做 HLS / 自动清晰度。
- 不改变 TUI 音频 `r` 刷新语义。
- 不新增第三方依赖。

## 4. 实现要点

- 请求解析新增 `quality <qn> <label>`、`current_qn <qn>`；旧 host 忽略。
- `VideoTarget` 带 `qualities: Vec<(u64,String)>`；`quality_note` 仍保留。
- `VideoController` 缓存当前 host 的 URL/当前 qn；质量切换走独立 `quality_rx`，完成后 `HostChild::load(url)`。
- `HostChild::load` 写 `load <url>\n`，校验 URL 无换行；np-video 解析后转 JSON，JSON 字符串需转义引号/反斜杠。
- 原生 popup 使用 `CreatePopupMenu`/`AppendMenuW`/`TrackPopupMenu(TPM_RETURNCMD)`；当前 qn 打勾。
- `loadfile` 后重新应用音量/暂停；cache 遥测重置；speed 由 T-0114 控制器继续。
- 失败回退：保留 `last_good_url`，`loadfile` 命令失败或收到 `error` 时恢复。

### 变更

- `crates/np-live/src/api.rs`：
  - `video_play_info_url_with_qn(room_id, qn)`；`video_play_info_url` 保持原画 10000。
  - `fetch_video_play_info_with_auth_qn(transport, room_id, auth, qn)`；旧的无 qn 入口转发到 10000。
- `crates/np-video/src/protocol.rs`：
  - 启动请求新增可选 `quality <qn> <label>`（最多 16 项、去重、qn 1–1,000,000、标签 ≤40 字符且禁控制字符）与 `current_qn <qn>`；旧 TUI 不发时为空 / 无当前档位。
  - `Event` 新增 `control quality <qn>`（另有 T-0116 的 `control paused` / `control refresh` / `volume`）。
- `crates/np-video/src/host/mod.rs`：
  - 清晰度按钮弹出原生 `CreatePopupMenu` / `AppendMenuW` / `TrackPopupMenu(TPM_RETURNCMD)`；当前 qn `MF_CHECKED`；菜单 owner 是顶层宿主，`WM_ENTERMENULOOP` 阻止控制条收起。
  - 选中后更新 `current_qn` 并 stdout 发 `control quality <qn>`；TUI 取流成功再发 `load <url>`。
  - `Control::Load` → `MpvIpc::loadfile(url, request_id)`，对现有 mpv 进程发 `{"command":["loadfile",<json>,"replace"],"request_id":N}`；不重启 np-video、不销毁窗口、不动视频 Rect。
  - `last_good_url` + `pending_load` + 5s 超时：mpv 回复 `error` 或超时时回退上一 URL 并 stdout `error 清晰度切换失败，已恢复原画面`；TUI 识别该提示后**保留旧画面**，不拆窗口。
  - 换流成功后重新下发 volume / pause，保持用户状态；cache 遥测在 `file-loaded` 时清零，speed tuner 继续工作。
- `crates/np-video/src/main.rs`：stdin 新增 `load <url>` 解析，先 `validate_stream_url` 再发 `Control::Load`；命令内容不写日志。
- `crates/np-video/src/mpv_ipc.rs`：
  - `json_string` 转义引号 / 反斜杠 / 控制字符；`loadfile` 只记录 request id 与字节数。
  - reader 解析 `{"request_id":N,"error":"..."}`；`file-loaded` 重置 telemetry + cache 原子值。
  - 命令日志改为 `bytes=`，回复日志不再输出原文，确保签名 URL 不进入可检索日志。
- `crates/np-tui/src/video.rs`：
  - `VideoTarget` 增加 `qualities` / `current_qn` / `requested_qn`；`accept_qn` 转中文菜单（30000 杜比 / 20000 4K / 15000 2K / 10000 原画 / 400 蓝光 / 250 超清 / 150 高清 / 80 流畅，未知显示 `qn <n>`）。
  - 初始握手新增 `quality` 列表 + `current_qn`。
  - `HostEvent` 解析控制条动作；`HostChild::load` 校验 URL 无换行 / 空格 / `#` 后写 `load <url>\n`。
  - 质量切换 / 刷新走独立 `quality_rx` 后台取流；成功才 `load`，失败只更新状态栏、保留旧画面；旧请求在途时新请求覆盖。
