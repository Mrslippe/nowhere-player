## 1. 背景

终端现在能执行命令，但用户得**记住**命令名和参数。这一卡补上两件事：Tab 补全、↑↓ 历史。做完 M2 就齐了。

## 2. 目标

1. 后端新增 `cmd.complete { input, cursor }` → 候选列表（带替换区间、类型、说明）。
2. 前端输入框接 Tab 补全：弹层、方向键选择、Tab 循环、Enter 采纳、Esc 关闭。
3. 历史：↑/↓ 翻历史，`Ctrl+R` 反向搜索可选；存 `localStorage`（上限 500 条）。
4. 补全候选来源：命令名、子命令、枚举值、以及**动态**的队列序号（`play <n>` 时给出队列长度范围）。

## 3. 非目标

- 不做路径补全（需要文件系统访问与权限，M3 做）。
- 不做模糊搜索（先做前缀匹配）。
- 不做历史持久化到 SQLite（M3）。

## 4. 必读 / 必须核实

1. `docs/30-计划/命令表.md`（命令与子命令结构）
2. `crates/np-core/src/command/`（`Registry` / `CommandSpec` / `Parsed`）

## 6. 实施要求

### 6.1 补全语义

- 输入 `""` → 返回全部命令名（最多 20 条）。
- 输入 `"pl"` → 前缀匹配 `play`；无前缀匹配时再给编辑距离 ≤ 2 的建议（标记为 `suggestion` 类型）。
- 输入 `"queue "` → 返回 `queue` 的子命令。
- 输入 `"mode repeat "` → 返回枚举值 `off/one/all`。
- 输入 `"play "` → 返回动态候选：`1..=queueLength`（后端从 `PlayerApi.snapshot` 拿 `queueLength`；拿不到就返回空，不报错）。
- **替换区间**：返回 `replaceStart`/`replaceEnd`（字节或字符偏移要统一，选字符并在契约里写明），前端据此替换当前 token，不重写整行。

### 6.2 历史

- 每条命令执行后（无论成功失败）推入历史；连续重复不重复入栈。
- `↑` 从最新往回翻，`↓` 往前；翻到底部时恢复"未提交的当前输入"。
- `localStorage` key：`np.cmd.history`；超过 500 条丢最旧。
- 读写要 `try/catch`（隐私模式）。

### 6.3 交互

- Tab 弹层最多 8 条，带一行说明；无候选时不弹层、不改变输入。
- 弹层打开时 `↑/↓` 选择、`Tab` 循环、`Enter` 采纳、`Esc` 关闭（关闭后 `Enter` 才是执行）。
- 弹层定位在光标下方（简化：输入框下方固定位置即可）。

## 11. 风险

- **替换区间的单位**最容易错（字节 vs 字符 vs UTF-16）。中文命令名虽不常见，但路径里会有中文——统一用**字符**并在契约里写明，测试用一条含中文的输入。
- 动态候选要能失败降级：`snapshot` 超时不能卡住补全，返回空列表即可。
- 历史与补全弹层的按键可能打架：弹层打开时 `↑/↓` 归弹层，关闭时归历史。
