# T-0042 设置命令族（all in terminal）

| 字段 | 值 |
|---|---|
| 卡号 | T-0042 |
| 里程碑 | M6-2 |
| 依赖 | ADR-0005、T-0040（音源）、T-0038（命令层） |
| 预估 | 2.5 天 |
| 时间预算 | 墙钟 12 小时（按命令族分四次提交，**任何时刻可构建**） |
| 并行 | 否 |
| 负责人 | 常驻「音源 / 网络」代理 |

---

## 1. 背景

产品决定：**all in terminal**，不做设置窗口。但主题切换、音源开关、缓存管理现在都只能改文件或走 dev 入口——用户没法操作。

这一卡把它们做成命令。

## 2. 目标

四族命令，共用一个 store（见 [ADR-0005](20-架构/adr/ADR-0005-设置存储与命令族.md)）：

```
theme   list | set <id> | export <id>
source  list | enable <id> | disable <id>
cache   stat | clear [streams|covers|all]
config  list | get <key> | set <key> <value> | unset <key> | reset
```

存储：`<config_dir>/settings.json`，原子写，坏文件回落默认。

## 3. 非目标

- 不做设置窗口（产品已否决）。
- 不做配置热重载。
- 不做 yt-dlp（T-0044）。

## 6. 实施要求

### 6.1 store

- `np-core::settings::Settings`：`load(dir) -> (Settings, Vec<Warning>)`、`save(dir)`、`get/set/unset/reset`。
- 值类型 `SettingValue { Str(String), Num(f64), Bool(bool) }`。
- 写：`.tmp` → rename；读：文件不存在视为空；JSON 坏 → 备份 `settings.bad.json` + 返回默认。
- **key 白名单校验**只对受控 key 做：`theme.id` 必须存在于内置或用户主题；`source.<id>.enabled` 的 id 必须已知。

### 6.2 theme

- `theme list`：表格 `[当前] | id | 名称 | 来源(内置/用户) | skin`。
- `theme set <id>`：写 `theme.id` + 立即生效（广播 `theme:changed { id }`，前端应用）。
- `theme export <id>`：复用现有 `theme.exportBuiltin` 逻辑，导出到 `<config>/themes/<id>.json`。

### 6.3 config

- `config list`：按 key 排序输出 `key = value`。
- `config get <key>`：不存在 → `E_CMD_ARG`（带"未设置"提示）。
- `config set <key> <value>`：按 §2 的类型推断解析。
- `config unset` / `config reset`（reset = 清空并恢复默认）。

### 6.4 source

- `source list`：`id | 名称 | 状态 | 说明`。
- `source enable/disable <id>`：写 `source.<id>.enabled`，**下次构建 `SourceRegistry` 时生效**（当前进程内改完即生效更好：直接从 registry 移除/加入）。
- 需要 `np-sources` 暴露 `SourceRegistry::ids()`（只读）——**若没有，先报告再改**。

### 6.5 cache

- `cache stat`：三行（streams / covers / 合计），复用 `cover_cache_usage` 与新建的 streams 统计。
- `cache clear <target>`：删文件不删目录；**若正在播放远程曲目，先停播**；输出释放体积。

## 11. 风险

- **`theme set` 要真的改变界面**，不是只写文件。广播事件后，如果前端没在跑（窗口未创建），重启时要能恢复——**两条路都要通**。
- `cache clear covers` 会删掉本地库封面缓存，下次扫描会重建（慢但不丢功能）——输出文案要提醒。
- `source disable` 后如果用户 `play` 一个已禁用的源的结果，要给人话错误，不是 panic。
- 命令表从 14 条涨到 20+ 条，`help` 的输出会变长——**检查 help 的分页/截断是否还合理**。
- 别把 settings 做成"什么都往里塞"——只放用户可配的，进程状态（缓存路径、db 路径）不进。
