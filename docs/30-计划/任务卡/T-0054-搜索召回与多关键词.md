## 1. 需求（产品原话）

1. 「播放量不高的正主投稿（标题含歌名、本人发的），也能通过 `search 花骨朵 --artist 缪尔Miru` 搜到」
2. 「过滤功能作为可选参数可以开启或关闭，默认开启」
3. 「想搜 `明前奶绿 文静 老公天下第一 第一次` 这种多关键词」

## 2. 目标

### 2.1 多关键词（整串不拆）

- 解析：`search` 之后、遇到第一个 `--flag` 之前的所有 token，**用单个空格拼成一个关键词**。
- 引号规则不变（`"a b"` 仍是一个 token，但拼接结果相同）。
- **不再报「参数过多」**。
- 传给源的 query = 整串（B 站自己分词）。

### 2.2 过滤开关

```
search <关键词…> [--artist <名>] [--no-filter] …
```

- `--no-filter`：**关闭 artist 过滤与标题关键词约束**，返回源原始结果（仍套用默认条数与来源限制）。
- 与 `--artist` 同时给 → `--artist` 仍参与**查询构造**，但不做结果过滤（即"搜这个人相关的东西，全部给我看"）。
- 默认**开着**（不加参数即过滤）。

### 2.3 四条召回通道（B 站，按序，够数就停）

| 顺序 | 通道 | query | 何时发 |
|---|---|---|---|
| 1 | A | 关键词 | 总是 |
| 2 | B | `艺人 关键词` | A 过滤后 < limit 且有 `--artist` |
| 3 | **D** | **UP 空间检索**（`recArchivesByKeywords(mid, 关键词)`） | A+B 仍 < limit、**且 `--artist` 能解析出唯一 mid** |
| 4 | **C** | 仅 `艺人` | **D 解析不出 mid 时**的兜底（别名/组合名等） |

**D 优先于 C 的原因**（产品给的反例）：低播放的正主投稿**标题里可能没有艺人名**（例：标题 `花骨朵`、作者 `缪尔Miru`）。
此时搜艺人名（C）返回不到，而 D 把"她的频道"作为范围再按歌名过滤，**不依赖标题含名字**。

- D 只发一次，412 不重试；解析不到 mid 时**必须明说**"未能解析到该艺人对应的 UP，已退回普通搜索"，不静默降级。
- C 的过滤：artist 命中（上传者或标题）**且**标题含关键词。
- **每通道结果按 `(source, source_id)` 去重**后合并。
- 只给 `--artist` 不给关键词时不走本流程（保持现状）。

### 2.4 延迟上限

- 最坏路径 A+B+C+D ≈ 4 次网络请求 + 1 次解析。
- **实测若 > 2.5s，停下来报告**，不要自行砍通道。

## 3. 非目标

- 不改网易云（它的 `artists` 字段精确，不加通道）。
- 不做关键词拆分的 OR 语义（产品选了"整串"）。
- 不做搜索缓存（除已有的 mid 1h / (mid,keywords) 30s）。

## 10. 风险

- **C 通道会显著增加请求**（每通道 2 个 duration 桶）。若实测延迟超标，**优先砍 B 桶的 duration 拆分**（只用一个桶），而不是砍通道。
- **D 有风控**：只在 A+B+C 都不够时发一次；412 直接提示，不重试。
- 多关键词整串发给 B 站，**分词结果不可控**（可能把"老公天下第一"当一个词）。过滤按"每个词都出现"能兜住一部分，但不是全部——**如实报告实际命中效果**。
- `--no-filter` 会让结果变脏，这是用户要的，**不要在文案里劝阻**，但要如实显示条数。
