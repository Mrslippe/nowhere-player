## 0. 事实基线

| 文件 | 行数 |
|---|---:|
| **`main.rs`** | **3003** |
| `theme.rs` | 393 |
| `audio.rs` | 364 |
| `launcher.rs` | 351 |
| `tray.rs` | 218 |
| 其它 | 更小 |
| 合计 | 4812 |

**一个文件占 62%**，导致两个后果：

1. 代理每次改动都要读大段内容（context 成本）；
2. 所有界面卡都改同一个文件 → **只能串行**。

---

## 1. 目标：按职责拆分

```
crates/np-tui/src/
  main.rs         入口、终端初始化、事件循环骨架   <300 行
  app.rs          App 状态与 update（现有结构）     ~500
  layout.rs       三区/沉浸/降级的 Rect 计算        ~300
  render.rs       Output → 控件、状态栏、帮助覆盖   ~600
  input.rs        输入行、历史、补全弹层、按键映射   ~500
  player_bar.rs   播放器条（进度/视觉区/控制）       ~300
  splash.rs       启动页（大字/主题选择）            ~250
  theme.rs / audio.rs / launcher.rs / tray.rs / glyphs.rs / fft.rs / instance.rs（不动）
```

### 1.1 硬要求

1. **纯搬移**：不改变任何行为、不改函数签名语义；
2. **每个模块有自己的 `mod tests`**，测试跟着代码走；
3. `main.rs` 只保留：`fn main`、终端初始化、主循环、模块声明；
4. **不留 `pub(crate)` 大杂烩**：按需最小暴露。

## 2. 非目标

- 不做 TEA 重构（已裁决延后）；
- 不改布局算法、键位、主题；
- 不新增依赖。

## 3. 授权路径

```
crates/np-tui/src/**
```

**禁止**：其它 crate、`docs/**`

## 4. 验收标准

- [ ] `cargo test --workspace` **全绿**，且 **698 通过**（搬移不改变测试数） `[数字]`
- [ ] `cargo clippy --all-targets -- -D warnings` 通过 `[数字]`
- [ ] `main.rs` **< 300 行** `[数字]`
- [ ] 每个新模块 **< 700 行** `[数字]`
- [ ] `NP_TUI_SELFTEST="library list --limit 3"` 输出与搬移前**逐字节相同** `[数字]`
- [ ] 播放四项判据仍通过 `[数字]`
- [ ] 启动页仍正常（`NO_SPLASH` 未设时） `[图]`
- [ ] 二进制体积变化 ≤ ±2% `[数字]`

## 5. 测试要求

- 搬移后测试分布在各模块；**总数必须仍为 698**（不是"不少于"），因为这卡不增删功能。

## 6. 风险

| # | 风险 | 缓解 |
|---|---|---|
| 1 | 搬移时误改行为 | 分 3–4 次提交，每次跑全量；`SELFTEST` 输出逐字节对比 |
| 2 | `pub(crate)` 扩散导致耦合依旧 | 每步只暴露被外部真正用到的符号 |
| 3 | 测试夹具路径变化 | 用 `CARGO_MANIFEST_DIR` 相对定位 |

## 7. 为什么这张卡值得先做

| 收益 | 说明 |
|---|---|
| **token** | 代理改一个模块只读几百行，而不是 3000 行 |
| **并行** | 不同卡改不同文件，**`np-tui` 单点约束解除** |
| **评审** | diff 更聚焦，评审者不用读整文件 |
