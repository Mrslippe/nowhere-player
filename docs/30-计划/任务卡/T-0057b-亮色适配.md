## 0. 事实基线

| 项 | 当前值 |
|---|---|
| `color-scheme` | **硬编码 `dark`**（所有主题） |
| 窗口外框 | `--np-border-window` = 白色渐变 `.10 → .04` |
| `tui-paper` | 亮色主题，底色 `#f2efe9` |
| 亮色下表现 | 窗口**无外框**（白环不可见）；原生滚动条**仍是深色** |

---

## 1. 问题

「亮色主题」不是换 14 个颜色就完成——还有**两处系统性假设**没跟上：

1. **窗口边缘高光是白色的**（假设深色底）；
2. **`color-scheme: dark` 写死**（影响滚动条、输入框、选择等原生控件）。

`tui-paper` 因此"界面是对的，窗口是破的"。

## 2. 目标

### A. 自动推导 scheme

`theme-loader` 应用主题时，按 `bg` 的**相对亮度**推导并写入：

```html
<html data-scheme="dark">   <!-- 亮度 < 0.5 -->
<html data-scheme="light">  <!-- 亮度 >= 0.5 -->
```

- 用 WCAG 相对亮度公式（`0.2126R + 0.7152G + 0.0722B`，线性化后）。
- **不新增主题字段**，不要求用户声明"我是亮色"。
- 同时设置 `color-scheme: light | dark`，让原生控件跟随。

### B. 两套窗口边

```css
[data-scheme="dark"]  { --np-border-window: linear-gradient(to bottom, rgba(255,255,255,.10), rgba(255,255,255,.04)); }
[data-scheme="light"] { --np-border-window: linear-gradient(to bottom, rgba(0,0,0,.12), rgba(0,0,0,.05)); }
```

- 深色：白环（现状，不动）。
- 亮色：**墨环**（顶部深、底部浅），模拟纸张边缘。

### C. 首屏默认

`ensureDefaultStructure()` 里同步写 `data-scheme="dark"` 与 `color-scheme: dark`。

## 3. 非目标

- 不做自动跟随系统深浅（那是 `mode: system`，M7 后）。
- 不改 `tokens` 契约。

## 4. 授权路径

```
apps/web/src/shared/theme-loader.ts
apps/web/src/design/**
```

**禁改**：`crates/**`、`apps/desktop/**`、`docs/**`

## 5. 验收标准

- [ ] `graphite`（暗）→ `data-scheme="dark"`、`color-scheme: dark` `[数字]`
- [ ] `tui-paper`（亮）→ `data-scheme="light"`、`color-scheme: light` `[数字]`
- [ ] 亮色下窗口边缘可见：截图量边框像素与纸底 RGB 差 ≥ 20 `[数字]`
- [ ] 亮色下滚动条为浅色（截图或 computed） `[图]`
- [ ] 深色主题的窗口边**完全不变**（与 T-0052 截图 SHA 相同） `[数字]`
- [ ] 阈值边界：`bg=#808080` 这类灰的判定有单测 `[数字]`

## 6. 文档影响

- 回报给出：亮度公式与阈值、两套边的色值。
- 主线更新 DES-001（窗口边）与 DES-004（scheme 推导）。

## 7. 风险

- **亮度阈值定在 0.5 可能误判中灰主题**：要求边界用例（`#808080`）有明确行为并在回报里写明。
- `color-scheme` 影响原生控件渲染，**改完要实际看滚动条**，不能只断言属性。
