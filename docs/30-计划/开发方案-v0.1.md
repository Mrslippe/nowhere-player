# Nowhere Player 初步开发方案 v0.1

> ⚠️ **历史文档（2026-11-13 标注）**：Tauri / React / WebView 架构已废弃，见 [ADR-0006](../20-架构/adr/ADR-0006-TUI宿主与渲染栈.md)。
> 产品范围、音源边界与部分交互设想仍可参考；**技术选型、目录结构、IPC 方案不要照此实现**。

> 状态：待评审 · 日期：2026-11-08 · 不含实现代码
> 一句话：一个常驻桌面的极简播放器小窗，配一个纯 CLI 风格的配置窗；好看、流畅是第一位，性能是第二位的护栏。

---

## 0. 本版决策摘要

| # | 决策 | 结论 | 影响 |
|---|---|---|---|
| D1 | 桌面外壳 | **Tauri v2（2.12.x 稳定版）** | 美观与迭代速度最优；内存按 120–160 MB 做预算 |
| D2 | 前端 | **React 19 + TypeScript + Vite** | 两个窗口共享设计系统 |
| D3 | 配置窗渲染 | **结构化终端（自绘块）**，不用 xterm.js | 本版重要修订，见 2.2 |
| D4 | 音频 | **symphonia + cpal + rubato**，自建 PlayerActor | 纯 Rust，可控，便于做淡入淡出与无缝切歌 |
| D5 | 音源 | 本地库 + **网易云（匿名）** + **B站** + **yt-dlp** | 三者统一在 `MusicSource` 抽象下 |
| D6 | 数据 | SQLite（本地库/队列/历史）+ TOML（用户配置） | 配置可手改，符合 CLI 气质 |
| D7 | 命令层 | **Command Registry 即公开 API** | 终端窗、托盘、未来真 CLI 共用一套 |
| D8 | 主题 | 内置 3 套（Graphite / Amber / Ice）+ 跟随封面取色 | 见 3.4 |

**与上一轮相比的变更**：优先级从"性能优先"改为"美观流畅优先"，因此 (a) 锁定 Tauri 而非自绘框架；(b) 配置窗放弃 xterm.js 改用结构化渲染，因为 xterm 的排版/装饰上限会直接限制"好看"；(c) 内存从硬指标降为预算护栏。

## 1. 需求基线与优先级

### 1.1 产品一句话

> 一个不需要打开的设置面板的音乐播放器——所有配置和操作都在一个像终端一样的窗口里，用打字完成。

### 1.2 优先级排序（本版确认）

1. **好看**：视觉完成度要对得起"极简"二字，不能被系统控件拉低质感。
2. **流畅**：60fps、无跳变、无白屏、动效克制但有质感。
3. **好用**：命令可发现（补全/帮助/报错友好），播放不中断。
4. **性能**：在 1–3 达标的前提下尽量省；不作为否决项。

### 1.3 v1 范围

**做**：本地文件夹扫描与播放、播放列表/队列、网易云/B站/YouTube 搜索与添加、无边框美化小窗、CLI 配置窗、托盘、媒体键、开机自启、单实例、自动更新。

**不做**（明确排除）：歌词滚动、EQ/可视化、Spotify/Apple Music/QQ 音乐、移动端、多语言、插件市场、音频独占/位完美。

### 1.4 目标用户假设

- 单机、单人、本地曲库 1k–20k 首。
- 愿意打字，但不背命令——必须靠补全和 `help` 引导。
- 桌面常驻，不占任务栏（可配置）。

## 2. 技术选型（锁定）

### 2.1 选型表

| 层 | 选型 | 版本基线 | 理由 |
|---|---|---|---|
| 外壳 | Tauri | 2.12.x | 安装包 5–15 MB；系统 WebView 保证 CSS 表现力；插件齐全 |
| 前端框架 | React + TypeScript | 19 / 5.x | 生态、可维护性、团队熟悉度 |
| 构建 | Vite | 7.x | 冷启动快，HMR 好 |
| 样式 | 原生 CSS + CSS 变量 + CSS Modules | — | 不引运行时；设计 token 集中管理；避免 Tailwind 类名污染自绘终端 |
| 状态 | Zustand | 5.x | 1 KB，够用，不做全局大 store |
| 动效 | CSS transition + Web Animations API | — | 只在必要时引 `motion`（≤ 30 KB） |
| 图标 | Lucide（按需引入） | — | 线性图标与极简气质一致 |
| 终端渲染 | **待定**：结构化自绘 / xterm.js | — | M0 并行验证，见 2.2 |
| 音频 | symphonia + cpal + rubato | 0.6 / 0.16 / 0.16 | 纯 Rust，格式覆盖够用 |
| 标签/封面 | lofty | 0.22 | FLAC/MP3/MP4/OGG 全支持，含内嵌封面 |
| 数据库 | rusqlite（bundled） | 0.3x | 单文件，无外部依赖 |
| HTTP | reqwest（rustls） | 0.12 | 不依赖系统 OpenSSL |
| 媒体键 | souvlaki | 0.8.x | MPRIS/SMTC/NowPlaying 一套搞定 |
| 系统集成 | tauri-plugin-{single-instance, autostart, updater, global-shortcut, window-state, store} | 2.x | 官方维护 |
| 打包 | tauri-action | — | NSIS / DMG / AppImage + deb |

### 2.2 配置窗：双方案并行验证（M0 决策点）

配置窗有两种做法，本版**不下结论**：在 M0 用同一份数据各做一版，看完实际效果再定。

| 维度 | A. xterm.js | B. 结构化自绘 |
|---|---|---|
| 排版控制 | 受限于字符网格（等宽、逐行） | 自由（行内混排、卡片、缩略图） |
| 输出表现力 | 仅 ANSI 颜色与字符画 | 表格可悬停/可点击、进度条、内嵌封面 |
| 真实感 | 100%（就是真终端） | 95%（像终端，但不是） |
| 选区/复制 | 现成、成熟 | 需自己实现（中等工作量） |
| 中文输入 | 成熟（原生 IME） | 需自证（textarea + 自绘光标） |
| 体积 | +约 300 KB | 0（复用 React） |
| 后续加富输出 | 需字符画或另开 DOM 层 | 改组件即可 |

**两套共用同一个输出模型**（ARCH-005）：命令层只产出 `Block` / `Output`，渲染层分叉。

- B 方案：`Output` → React 组件。
- A 方案：`Output` → ANSI 序列 writer（表格降级为列对齐，缩略图降级为省略）。

**决策规则**（详见 M0 任务清单（已删除） §3）：五个维度加权打分，差距 ≥ 15% 直接采用，< 15% 选长期成本更低者。结论写进 `docs/20-架构/adr/ADR-0002-终端渲染方案.md`；落选方案用 feature flag 关闭，但代码保留。

### 2.3 被否方案（记录理由，避免反复）

| 方案 | 否决理由 |
|---|---|
| Electron | 150 MB 体积 + 200–400 MB 内存，与"极简"定位冲突 |
| Slint / egui 自绘 | 内存能到 40–60 MB，但 UI 表现力与迭代速度显著落后，与"美观优先"冲突 |
| 纯 Web（浏览器） | 无法常驻桌面、无托盘/媒体键/全局快捷键 |
| 让播放走 `<audio>` 标签 | 采样率被钳制、无法做无缝/淡入淡出、无法接本地解码 |

## 3. 产品与交互设计

### 3.1 两个窗口的职责边界

| | 播放器小窗 | 配置窗 |
|---|---|---|
| 常驻 | 是（默认开机就在） | 否，按需唤起 |
| 尺寸 | 340×120（可缩放 300×104 ~ 520×160） | 900×560（可缩放） |
| 装饰 | 无边框、圆角、可透明 | 无边框 + 自定义标题栏 |
| 输入 | 只有鼠标（点按/拖拽/滚轮调音量） | 键盘为主 |
| 唤起方式 | 开机自启 / 托盘 / 全局快捷键 | 双击小窗、托盘菜单、快捷键、命令行 `nowhere` |
| 关闭行为 | 最小化到托盘 | 真正关闭（隐藏即释放 webview，见 10.3） |

### 3.2 播放器小窗规格

**布局（340×120）**

```
┌──────────────────────────────────────────────┐
│  ┌────────┐   标题（15px / 600）              │
│  │ 封面   │   艺人 · 专辑（12px / muted）      │
│  │ 64×64  │                                  │
│  └────────┘   ━━━━━━━━━━━━━━━━━━━━━  01:23/04:05 │
└──────────────────────────────────────────────┘
```

**元素**

- 封面：64×64，圆角 12，`object-fit: cover`，异步解码，缺图时按专辑名生成确定性渐变（同一张专辑永远同一色）。
- 标题：单行省略，超长时**悬停才滚动**（Marquee），不自动跑。
- 副标题：艺人 · 专辑，12px，对比度 60%。
- 进度条：2px，悬停变 4px 并出现拖拽手柄；拖拽时进度条上方浮出 `02:14` 气泡。
- 时间：10px，`font-variant-numeric: tabular-nums`，播放时显示已播/总长，悬停进度条时切换为剩余时间。
- 控制键：默认隐藏，悬停淡入（120ms）；上一首 / 播放暂停 / 下一首，16px 线性图标。

**状态机**

| 状态 | 表现 |
|---|---|
| 空闲 | 显示"未在播放"+ 最近播放入口，整体降透明度 |
| 加载中 | 封面骨架微光 + 进度条不确定态动画 |
| 播放中 | 进度条 accent 色；可选"呼吸"微光（极弱，2% 透明度脉动） |
| 暂停 | 整体饱和度降 15%，播放键变 ▶ |
| 错误 | 右上角小红点 + 悬停显示原因；不弹窗 |
| 拖动中 | 窗口阴影加深，位置吸附屏幕边缘（12px 阈值） |

**交互**

- 任意空白处拖拽移动窗口；双击打开配置窗。
- 滚轮 = 音量 ±2%；按住 Shift 滚轮 = 快进/快退 5s。
- 右键 = 原生菜单（置顶/隐藏/打开配置/退出）。
- 中键 = 播放/暂停。
- 悬停 1.5s 无操作，控制键淡出。

### 3.3 配置窗规格

**结构（900×560）**

```
┌──────────────────────────────────────────────┐
│ ● ● ●   nowhere://config          — □ ×     │  ← 自定义标题栏 36px
├──────────────────────────────────────────────┤
│                                              │
│  nowhere player v0.1.0                       │  ← 启动 banner
│  输入 help 查看命令，tab 补全                 │
│                                              │
│  › search 周杰伦 --source netease            │  ← 已完成块（输入行变暗）
│  ┌────────────────────────────────────────┐  │
│  │ 1  晴天          周杰伦   320k   ▶ 可播 │  │  ← 结果表
│  │ 2  稻香          周杰伦   VIP 试听45s   │  │
│  │ 3  ...                                  │  │
│  └────────────────────────────────────────┘  │
│  3 条结果 · 输入 add 1-2 加入队列             │  ← 提示行
│                                              │
│  › add 1-2                                   │  ← 当前输入行（光标闪烁）
│  ▏                                           │
├──────────────────────────────────────────────┤
│ tab 补全 · ↑↓ 历史 · ctrl+k 面板 · ctrl+l 清屏│  ← 状态栏 24px
└──────────────────────────────────────────────┘
```

**块模型（Block）**

每条命令产生一个块，块由三部分组成：

1. **输入行**：提示符 `›` + 命令原文 + 完成时间（右侧灰色小字）。执行中显示旋转指示器，完成后变暗。
2. **输出区**：一个或多个"输出原语"（见下）。
3. **尾注**：提示下一句能做什么（`输入 add 1-2 加入队列`），只在有明确后续动作时出现。

**输出原语（v1 只需 6 种）**

| 原语 | 用途 | 视觉 |
|---|---|---|
| `text` | 普通文本、键值对 | 等宽 13px，行高 1.6 |
| `table` | 搜索结果、队列、库列表 | 列对齐，行悬停高亮，可点击 |
| `progress` | 扫描、下载 | 原地刷新的单行进度条 |
| `error` | 失败 | 红点 + 错误码 + 一句话原因 + 建议命令 |
| `hint` | 补全建议 / 纠错 | `did you mean 'play'?`，按 tab 采纳 |
| `media` | 封面/专辑缩略图 | 48×48 圆角小图，仅在 `info` 类命令出现 |

**键盘**

| 键 | 行为 |
|---|---|
| Tab | 补全（命令 → 子命令 → 参数 → 动态值：歌单名/路径/设备） |
| ↑ / ↓ | 历史（按前缀过滤，像 shell） |
| Ctrl+R | 反向搜索历史 |
| Ctrl+K | 命令面板（模糊搜索所有命令 + 用法） |
| Ctrl+L | 清屏 |
| Ctrl+C | 取消当前输入 / 中断长任务 |
| Esc | 关闭补全 / 取消 |
| Enter | 执行 |

**其他细节**

- 滚动：默认贴底；用户上滚后出现"↓ 3 条新输出"悬浮按钮，按 End 回到底部。
- 回滚缓冲上限 2000 行，超出丢弃最旧块（防止内存膨胀）。
- 复制：拖选后可 Ctrl+C；块右上角悬停出现"复制输出"小按钮。
- 窗口失焦时，光标停止闪烁（省电、少打扰）。

### 3.4 设计语言

**颜色（Graphite 主题示例）**

| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#0B0C0E` | 主背景（近黑但不纯黑） |
| `--bg-elev` | `#141619` | 卡片/表格底 |
| `--fg` | `#E8EAED` | 主文本 |
| `--fg-muted` | `#8B9096` | 次要文本 |
| `--fg-faint` | `#4A4F55` | 禁用/装饰 |
| `--accent` | `#7C9EF5` | 主强调（可被封面取色替换） |
| `--accent-soft` | `rgba(124,158,245,.14)` | 悬停/选中底 |
| `--danger` | `#F2707A` | 错误 |
| `--warn` | `#E8B45C` | VIP/受限提示 |
| `--line` | `rgba(255,255,255,.07)` | 分隔线 |

**字体**

- UI：`Inter` / `SF Pro` / `Segoe UI`（系统栈），数字用 `tabular-nums`。
- 终端：`JetBrains Mono` / `Maple Mono` / `SF Mono` / `Cascadia Code`（自选其一，随包或回退系统等宽）。
- 字号阶：10 / 12 / 13 / 15 / 20（终端 13，UI 12–15）。

**间距与圆角**

- 4pt 网格；窗口内边距 16；块间距 12。
- 圆角：窗口 18（Win11 可交给 DWM），卡片 10，按钮 8，封面 12。

**动效**

| 场景 | 时长/曲线 |
|---|---|
| 窗口出现 | 160ms，`cubic-bezier(.2,.8,.2,1)`，透明度 0→1 + scale .98→1 |
| 控件淡入 | 120ms ease-out |
| 切歌 | 文本 80ms 淡出 → 120ms 淡入（交叉） |
| 命令块出现 | 120ms 上移 4px + 淡入 |
| 进度条 | 位置用 CSS transform，不用 width（避免重排） |

统一遵守 `prefers-reduced-motion`：全部降级为即时切换。

### 3.5 主题与毛玻璃降级

| 平台 | 播放器小窗背景 | 配置窗背景 |
|---|---|---|
| Windows 11 | Acrylic（`window-vibrancy`），失败回退半透明纯色 | 不透明 + 1px 内描边 |
| Windows 10 | Blur 或纯色 | 同上 |
| macOS | Vibrancy（`NSVisualEffectView`） | 同上 |
| Linux | **纯色 + 噪点纹理 + 极弱渐变**（伪装玻璃） | 同上 |

判定方式：启动时探测平台与合成器能力，能力不足自动降级，并在 `config` 里暴露 `ui.transparency = auto|on|off`。

### 3.6 空态 / 加载 / 错误

- **空库**：终端 banner 后直接给一条可复制的命令：`library add ~/Music`。
- **扫描中**：进度行 + 已扫数量，可 `Ctrl+C` 中断（已入库的部分保留）。
- **网络失败**：不弹窗，输出 `error E_NET_TIMEOUT 连接超时（8s）· 重试: search 周杰伦`。
- **不可播**：结果表里直接标 `版权受限`，点/回车时提示"该曲目在网易云已下架，试试 --source bilibili"。

## 4. 系统架构

### 4.1 进程与线程模型

```
┌──────────────────────── 主进程（Tauri / Rust）────────────────────────┐
│  UI 线程（tao 事件循环）                                              │
│    └─ 只做窗口/托盘/菜单，不做业务                                    │
│                                                                      │
│  Core Runtime（tokio 多线程）                                         │
│    ├─ CommandService   命令解析/分发/补全（无状态，可并发）           │
│    ├─ PlayerService    播放状态机（单任务 actor，串行）               │
│    ├─ LibraryService   扫描/索引（可取消的长任务）                    │
│    ├─ SourceService    netease / bilibili / ytdlp 适配器              │
│    └─ EventBus         向 UI 广播（合并、节流）                       │
│                                                                      │
│  Audio Thread（独立 OS 线程，非 tokio）                               │
│    └─ 解码 → 重采样 → 混音 → cpal 回调（无锁环形缓冲）                │
└──────────────────────────────────────────────────────────────────────┘
         │ IPC：invoke（请求/响应） + emit（事件）
┌────────▼─────────────────────────────────────────────────────────────┐
│ WebView（两个窗口，同一份前端包，按路由分）                            │
│    /player   播放器小窗                                              │
│    /terminal 配置窗                                                  │
└──────────────────────────────────────────────────────────────────────┘
```

**原则**：UI 线程不阻塞；音频线程不分配内存、不加锁、不做字符串格式化；所有跨线程通信走消息通道。

### 4.2 模块划分

```
nowhereplayer/
├─ crates/
│  ├─ np-core/          领域模型、Command 定义、事件定义、错误码（零 UI 依赖）
│  ├─ np-audio/         解码/重采样/输出/播放状态机
│  ├─ np-library/       扫描、标签、封面缓存、SQLite、检索
│  ├─ np-sources/       MusicSource trait + local / netease / bilibili / ytdlp
│  └─ np-system/        托盘、媒体键、单实例、自启、窗口控制
├─ apps/
│  ├─ desktop/          Tauri 壳（src-tauri）：命令注册、IPC 适配、能力配置
│  └─ web/              React：design-system / player / terminal / shared
├─ docs/                本方案、命令手册、架构决策记录（ADR）
└─ .github/workflows/   三平台构建与发布
```

**硬性约束**：`apps/desktop` 里只允许"参数转换 + 调用 crate"，不允许出现业务逻辑。这条约束保证未来若真要换 Slint/egui，只重写 `apps/`。

### 4.3 IPC 契约

**请求（invoke）**——少量、语义化：

| 通道 | 入参 | 出参 |
|---|---|---|
| `cmd.exec` | `{ input, blockId }` | `{ blockId, ok, usage? }`（输出通过事件流回） |
| `cmd.complete` | `{ input, cursor }` | 候选列表（含类型、说明、替换区间） |
| `cmd.history` | `{ prefix, limit }` | 历史条目 |
| `player.snapshot` | — | `PlaybackState`（首帧用） |
| `player.play` | `{ path? }` | 有 `path` 则入队（不在队列中则追加）并播放；无参为继续 |
| `player.pause` | — | `PlaybackState` |
| `player.next` / `player.prev` | — | `PlaybackState`；空队列返回 `E_UNSUPPORTED` |
| `player.seek` | `{ positionMs }` | `PlaybackState` |
| `player.volume` | `{ volume }` | `PlaybackState` |
| `player.mode` | `{ mode: { repeat, shuffle } }` | `PlaybackState` |
| `queue.list` | — | `{ tracks: string[], index: number \| null }`；`index` 是**游标**（0 基），空队列为 `null`；"是否在播"看 `status`，不看 `index` |
| `queue.add` | `{ paths: string[] }` | `{ tracks, index }`；**不校验文件存在性** |
| `queue.remove` | `{ index }` | 同上；删当前项 = 停止播放、指针指向下一首、不自动播 |
| `queue.jump` | `{ index }` | 同上；跳转并自动播放 |
| `queue.clear` | — | 同上；队列空则 `index = null`、`status = idle` |
| `library.addRoot` | `{ path }` | 根目录数量；已存在则 `E_CMD_ARG` |
| `library.scan` | `{ full?, blockId? }` | 立即返回「已受理」；给 `blockId` 才推 `terminal:block` 进度 |
| `library.list` | `{ limit? }` | `Track[]`（camelCase） |
| `library.search` | `{ keyword, limit? }` | `Track[]`，上限 100 |
| `library.stats` | — | `{ tracks, albums, artists, totalDurationMs, lastScanAt }` |
| `library.trackByPath` | `{ path }` | `Track \| null`（精确匹配） |
| `library.coverUrl` | `{ key }` | 绝对路径；前端 `convertFileSrc` 转换。key 必须是 16 位小写 hex，否则 `E_CMD_ARG` |
| `window.toggle` | `{ which }` | — |

**事件（emit）**——高频、合并后推送：

| 事件 | 频率 | 载荷 |
|---|---|---|
| `player:state` | 4 Hz（状态变化时立即） | 曲目、状态、音量、模式 |
| `player:position` | 4 Hz | `positionMs`（UI 侧用 rAF 插值到 60fps） |
| `terminal:block` | 按需 | 命令块的增量输出（追加/替换某行） |
| `library:scan` | 5 Hz | 已扫/总数/当前文件 |
| `ui:toast` | 按需 | 轻提示（切歌、错误摘要） |

> **命名约束**（T-0013 实测）：Tauri 2.12 的事件名校验只允许字母数字与 `-` `/` `:` `_`，**点号非法**（`IllegalEventName`）。因此事件统一用 `模块:事件` 形式，不要用 `evt.player` 这类写法。命令名（`invoke` 通道）不受此限制。

**错误码**（进 CLI 输出，直接面向用户）：

| 码 | 含义 | 建议动作 |
|---|---|---|
| `E_CMD_UNKNOWN` | 未知命令 | 附 `did you mean` |
| `E_CMD_ARG` | 参数错误 | 附 usage |
| `E_NET_TIMEOUT` | 网络超时 | 重试 |
| `E_SRC_GEO` | 地区限制 | 换源 |
| `E_SRC_VIP` | 需要会员 | 试听或换源 |
| `E_SRC_REMOVED` | 版权下架 | 换源 |
| `E_SRC_AUTH` | 登录态失效 | `source login netease` |
| `E_DECODE` | 解码失败 | 跳过 |
| `E_DEVICE_LOST` | 音频设备拔出 | 自动切默认设备 |
| `E_TOOL_MISSING` | yt-dlp 未安装 | 附安装提示 |

### 4.4 状态同步与渲染节流

- **单一真值在 Rust**：前端不维护"自己以为的播放状态"，只做投影。
- **位置**：Rust 每 250ms 推一次；前端用 `requestAnimationFrame` 插值，保证进度条 60fps 且不抖。
- **列表**：队列变化推全量快照（v1 队列 < 5000，JSON 足够）；库列表走分页查询。
- **节流**：所有事件在 EventBus 侧合并（同一帧内多次变化只发最后一次）。

## 5. 音频子系统

### 5.1 管线

```
解码线程（阻塞 IO） → 重采样（rubato，仅在采样率不匹配时） → 混音/增益 → 无锁环形缓冲 → cpal 回调
        ↑
   预读下一首（gapless）
```

### 5.2 关键行为

| 行为 | 实现要点 |
|---|---|
| 无缝切歌 | 提前 3s 解码下一首并预置到缓冲；切歌点做样本级拼接 |
| 淡入淡出 | 播放/暂停/切歌 8–15ms 线性斜坡，消除爆音 |
| 音量 | 感知曲线（三次方映射），滚轮步进 2% |
| Seek | 关键帧定位 + 丢弃到目标点，UI 立即反馈（乐观更新） |
| 设备热插拔 | 监听默认设备变化，暂停 → 重建流 → 恢复（失败则提示 `E_DEVICE_LOST`） |
| 网络流 | 环形缓冲 8–15s，弱网降级为"边下边播"，卡顿超 5s 报错 |

### 5.3 格式支持（v1）

FLAC / MP3 / AAC(M4A) / ALAC / WAV / OGG-Vorbis / AIFF。DSD、APE、WavPack、Opus 明确不在 v1（需要额外解码器，见风险 R6）。

## 6. 音源子系统

### 6.1 统一抽象

每个音源实现四件事：**搜索**、**解析播放地址**、**取封面**、**取歌词（v1 只存不展示）**。

统一结果结构（概念）：

| 字段 | 说明 |
|---|---|
| `key` | 全局唯一：`local:<hash>` / `nc:<id>` / `bili:<bvid>:<cid>` / `yt:<videoId>` |
| `title` / `artist` / `album` | 元数据 |
| `duration` | 毫秒 |
| `cover` | 本地路径或远程 URL |
| `playability` | `ok` / `trial` / `vip` / `geo` / `removed` / `unknown` |
| `quality` | 展示用（`320k` / `flac` / `1080p-audio`） |

### 6.2 本地

- 扫描：递归遍历 + 扩展名白名单 + 跳过隐藏目录；按 `(size, mtime)` 做增量。
- 标签：lofty 读 title/artist/album/track/disc/year；缺失时用文件名兜底（`艺人 - 标题`）。
- 封面：优先内嵌图，其次同目录 `cover.jpg/folder.jpg/front.jpg`；统一转成 512px webp 缓存。
- 播放：直接文件路径，无网络。

### 6.3 网易云（匿名）

| 能力 | 实现路径 | 备注 |
|---|---|---|
| 搜索 | linuxapi 云搜索为主，weapi 经典搜索兜底 | 分型：歌曲/专辑/歌手/歌单 |
| 取链 | weapi `/song/enhance/player/url` | 匿名免费歌 320k；VIP 歌 45s 试听；下架返回 404 |
| 歌词 | 匿名 GET 接口 | v1 仅落库，不展示 |
| 歌单 | weapi v6 详情 + 批量详情 | 大歌单分批（500/批） |
| 登录 | **v1 不做**（只做匿名） | 留接口位，v1.5 加扫码 |

**要点**：三套加密（weapi/linuxapi/eapi）必须自带实现，不引 Node 运行时；直链 20 分钟过期，解析结果做短缓存并校验 `expiresAt`；请求统一带 `Referer: https://music.163.com/` 与桌面 UA。

### 6.4 B 站

| 步骤 | 说明 |
|---|---|
| 搜索 | `/x/web-interface/wbi/search/type`，需 **wbi 签名**（`img_key`/`sub_key` + 混淆表算 `w_rid` + `wts`） |
| 取流 | `/x/player/wbi/playurl`，`fnval=4048` 取 DASH，从 `audio[]` 里挑最高码率 |
| 播放 | **必须带 `Referer: https://www.bilibili.com`**，否则 403 |
| 音质 | 未登录 64–132k；登录后可达 192k（v1 先做匿名） |
| 元数据 | 标题清洗（去 `【】`、`MV`、`4K` 等噪声），频道名当艺人 |

**要点**：wbi 签名算法会变更，做成独立模块 + 单元测试（固定输入/输出向量），出问题只改一处；搜索结果是"视频"不是"歌曲"，UI 上要标 `视频音轨`。

### 6.5 yt-dlp（外部依赖）

| 用途 | 方式 |
|---|---|
| 搜索 | `ytsearch10:<关键词>` + `--dump-json`（一次拿 10 条元数据） |
| 取流 | `-f bestaudio -g <url>` 拿直链 |
| 探测 | 启动时 `--version`，缺失则 `source status` 里标红 |

**要点**：子进程管理（超时 20s、可取消、异常退出兜底）；解析失败给出可执行建议（`yt-dlp 版本过旧，运行 yt-dlp -U`）；不做自动下载/更新（安全与体积考虑）。

### 6.6 可播性判定与降级

搜索阶段就拿到 `fee/privilege` 等字段，**提前**算出 `playability` 并在表格里标注，避免"点了才知道播不了"。播放失败时的降级顺序：

1. 同一首歌换音源（netease → bilibili → youtube）。
2. 仍失败 → 输出错误块 + 自动跳下一首（可在 config 关闭）。

## 8. 命令语言规范

### 8.1 语法

```
命令    := 动词 [子命令] [位置参数...] [--标志 [值]...]
动词    := 小写英文单词，可用前缀缩写（唯一前缀即合法）
位置参数 := 数字（序号） | 区间（1-5） | 字符串 | 路径 | URL
标志    := --source=netease | --json | --limit=20 | --force
```

- 前缀缩写：`lib` → `library`，`q` → `queue`，但 `s` 有歧义（`search`/`source`），必须写全或给别名。
- `/关键词` 是"快速搜索"的语法糖（等价 `search 关键词`）。
- `?` 或 `help` 打开帮助；`help <命令>` 给用法与示例。

### 8.2 命令表（规划版）

> 实际已实现的命令与分词规则见 [命令表](命令表.md)（T-0017 起以那份为准，本节只保留早期规划供对照）。

| 播放 | `seek <±秒\|mm:ss>` `vol <0-100\|±N>` `mute` | |
| 模式 | `shuffle on\|off` `repeat off\|one\|all` | |
| 队列 | `queue` `queue add <序号\|关键词>` `queue rm <序号>` `queue clear` `queue move <from> <to>` | `queue` 无参即展示 |
| 队列 | `now` | 当前曲目详情（含封面缩略图） |

### 8.3 补全策略

| 位置 | 候选来源 |
|---|---|
| 动词 | Registry 全量 + 历史高频 |
| 子命令 | 该动词的 spec |
| `--source` | 已启用的音源 |
| 路径参数 | 文件系统（异步，防卡顿） |

## 9. 关键流程

### 9.1 首次启动

1. 小窗出现（无曲目态），300ms 内可交互。
2. 托盘图标就位，注册媒体键。
3. 若检测到 `~/Music` 存在，小窗底部提示"按 Ctrl+Shift+P 打开配置窗"。
4. 首次打开配置窗时，banner 下方给一行 `library add ~/Music` 的可点击建议。

### 9.2 添加并播放一首本地歌

`library add ~/Music` → 扫描（进度行）→ `search 晴天` → 结果表 → `play 1`（或 `queue add 1-5`）。

要求：搜索 1 万首库 < 150ms；`play` 到出声 < 300ms（本地）。

### 9.3 在线搜索并播放

`search 晴天 --source netease` → 结果带可播性 → `play 1` → 解析直链（<800ms）→ 播放；若 VIP/下架，直接标红并给替代建议。

### 9.4 播放失败降级

解码/网络失败 → 小窗红点 + 终端输出错误块 → 自动尝试下一音源 → 仍失败则跳下一首（可配置为暂停）。

### 9.5 退出

托盘"退出"或 `quit`：保存队列与播放位置 → 停止音频 → 释放 webview → 退出。下次启动恢复队列但**不自动播放**（避免惊吓）。

## 10. 性能预算与流畅度策略

### 10.1 预算（护栏，不是目标）

| 指标 | 预算 |
|---|---|
| 冷启动到小窗可交互 | ≤ 800ms（温启动 ≤ 400ms） |
| 安装包 | ≤ 12 MB |
| 内存（仅托盘） | ≤ 80 MB |
| 内存（小窗常驻） | ≤ 160 MB |
| 内存（双窗） | ≤ 210 MB |
| 空闲 CPU | ≤ 0.5% |
| 播放 CPU | ≤ 3%（1080p 音频解码 + 界面） |
| 命令响应 | 本地操作 ≤ 50ms |
| 动画 | 稳定 60fps，不掉帧 |

### 10.2 前端流畅度规则

- 只动 `transform` / `opacity`；禁止动画 `width/height/top/left`。
- 进度条用 `transform: scaleX()`，配合 `will-change` 谨慎使用。
- 长列表虚拟化（队列/搜索结果/回滚缓冲）。
- 图片：`loading="lazy"` + `decoding="async"` + 固定尺寸占位（防 CLS）。
- 事件订阅按窗口拆分，小窗不订阅库扫描进度。
- React：播放状态用 `useSyncExternalStore` 订阅切片，避免整树重渲染。

### 10.3 内存策略

- 配置窗**关闭即销毁**（不是隐藏），下次打开重建（约 300ms）。省 30–60 MB。
- 回滚缓冲上限 2000 行；封面缓存上限 200 张（LRU）。
- 音频环形缓冲 8–15s，切歌后释放上一首解码器。

### 10.4 启动策略

- 首屏不扫库、不联网、不加载大图。
- 库统计读缓存表，后台异步刷新。
- Rust 侧延迟初始化：只在第一次用到时建 SQLite 连接池。

## 13. 里程碑与排期

> 前提：单人，业余 15–20 h/周。若全职投入，总工期约 ÷2.5。

| 阶段 | 内容 | 工期 | 验收标准 |
|---|---|---|---|
| **M0 设计定稿 + 骨架** | 设计 token、两窗静态原型（假数据）、Tauri 骨架、CI、托盘 | 1 周 | 原型可在真机上看两窗；`pnpm dev` 一键起；CI 绿 |
| **M1 播放器小窗可用** | 音频管线、小窗 UI、托盘、媒体键、单实例、自启 | 2 周 | 拖入一个 FLAC 能播；进度条 60fps；媒体键可用；关窗驻留托盘 |
| **M2 命令窗可用** | 结构化终端渲染器、Registry、解析、补全、历史、帮助 | 2 周 | 不碰鼠标完成"播放/暂停/调音量/看队列/改主题" |
| **M3 媒体库** | 扫描、标签、封面缓存、SQLite、搜索、队列持久化 | 2 周 | 1 万首首扫 < 90s；`search` < 150ms；重启恢复队列 |
| **M4 网易云** | 三套加密、搜索、取链、可播性、短缓存 | 1.5 周 | 匿名可搜可播免费歌；VIP/下架有明确提示；直链过期自动重取 |
| **M5 B站 + yt-dlp** | wbi 签名、DASH 选流、Referer、子进程管理 | 1.5 周 | B站能搜能播；yt-dlp 缺失时提示清晰；解析失败可换源 |
| **M6 打磨发布** | 主题、动效、透明降级、更新器、三平台打包、README | 2 周 | 三平台安装→播放→更新跑通；内存/启动达标 |

**合计 ≈ 12 周**。关键路径：M0 → M1 → M3 → M4；M2 可与 M1 并行（前端 vs 音频）。

**垂直切片原则**：M1 结束时产品就"能听"；每个里程碑结束都必须是可用状态，不留半成品。
