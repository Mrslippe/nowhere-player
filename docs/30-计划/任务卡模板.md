# 任务卡模板

> 用法：复制本模板到 `docs/30-计划/任务卡/T-00xx-短横线标题.md`，填完再交给实现者。
> **卡片是主线与实现者之间唯一的信息载体**——实现者看不到对话历史。
> 2026-11-13 修订：去掉 Web/Tauri 注册点；新增“删除/重构卡”与“收口清单”。

---

## 元信息

| 字段 | 值 |
|---|---|
| 卡号 | `T-0087` |
| 标题 | 示例：清理某子系统 |
| 类型 | 功能 / 修复 / 删除 / 重构 / 文档 / 实验 |
| 里程碑 | M9 / 质量收口 |
| 依赖 | 前置卡号，或“无” |
| 预估 | 1 天 |
| 时间预算 | 墙钟 6 小时（80% 主线介入，100% 强制判定） |
| 并行 | 可并行卡 / 必须串行 |
| 负责人 | 角色名（见 PLAN-007） |

---

## 0. 事实基线（**以本节为准，覆盖上下文记忆**）

> 只写“本卡依赖的、近期变过的”事实。稳定事实（项目结构、构建命令）不写。
> 代理读到上下文冲突时，**以本节为准**。

| 项 | 当前值 | 已作废 |
|---|---|---|
| 例：播放器面板 | 运行时高度，`clamp(8, 12)` | ~~固定 10 行~~ |
| 例：缓存命令 | `cache clear [streams\|all]` | ~~`covers` 类别~~ |
| … | … | … |

**写卡人职责**：改过两次以上的东西，必须出现在这张表里。

---

## 1. 背景（≤ 3 句）

为什么现在做这件事；不做会怎样；与哪个产品决定/ADR 相关。

---

## 2. 目标（可验证）

- 写“结果”，不写“实现方式”；
- 每条都能被命令、观察或测试证明；
- 目标不超过 5 条，超出拆卡。

---

## 3. 非目标（明确排除）

- 本卡明确不做什么；
- 防止实现者“顺手加三个功能”。

---

## 4. 输入

必读（按顺序，≤ 5 个）：

1. `docs/30-计划/当前状态.md`
2. 相关设计/架构文档（只给路径与要点）
3. 已冻结契约（全文）

**不要**把整段对话历史塞进卡里。

---

## 5. 授权路径

**可写**：

```
crates/np-tui/src/**
crates/np-tui/Cargo.toml
```

**禁改**（常见越界点）：

```
crates/np-core/**            ← 契约层，改动需另开卡
crates/np-app/**             ← 命令执行器
crates/np-audio/**           ← 播放链路
Cargo.toml（workspace）       ← 仅主线可改
docs/**                      ← 文档由主线维护
```

### 5.1 注册点核对（写卡时逐项填，不适用写“否”）

| 注册点 | 是否需要改 | 对应文件 | 已列入授权路径 |
|---|---|---|---|
| 依赖清单 | 是 / 否 | `Cargo.toml` / crate `Cargo.toml` | ☐ |
| 模块声明 | 是 / 否 | `lib.rs` / `mod.rs` / `main.rs` | ☐ |
| 命令注册 | 是 / 否 | `np-core/command/registry.rs` | ☐ |
| 错误码映射 | 是 / 否 | `np-core` / `np-app` | ☐ |
| 配置键 / 默认值 | 是 / 否 | `np-core/settings.rs` / `np-app` | ☐ |
| CI / 脚本入口 | 是 / 否 | `.github/workflows/` / `scripts/` | ☐ |

> 漏注册点的代价：实现者要么停工等你，要么越界。写卡时 5 分钟，返工 1 小时。

### 5.2 文件所有权（**并行时必须填**）

| 文件 | 读/写 | 与在跑的卡冲突？ |
|---|---|---|
| `crates/np-tui/src/app.rs` | 写 | 是 → **串行** |
| … | … | … |

**规则**：只要有一行“是”，两张卡就必须串行，或由一个代理连做。
**`np-tui` 同一时间只允许一张卡**（见 SPEC-001 §5.1）。

---

## 6. 验收标准（逐条可执行）

> **每条后面必须标证据类型**：`[数字]`（可测量）/ `[图]`（必须人眼看）/ `[人工]`（必须人操作）。
> 标 `[图]` 的要说明为什么不能量化；标 `[人工]` 的写清谁来验、怎么验。
> 标 `[数字]` 的条目交截图视为未完成。

**本卡必须有至少一条可复现命令**：

```bash
# 例：cargo test -p np-tui
# 例：NP_TUI_SELFTEST="search 晴天;play 2" target/release/np-tui.exe
```

- [ ] `cargo test --workspace` 全绿 `[数字]`
- [ ] 新增/修改行为有对应单测，或写明豁免理由 `[数字]`
- [ ] `NP_TUI_SELFTEST="<命令>"` 输出包含期望文本 `[数字]`
- [ ] 布局/颜色项给出可测量断言（不是“看起来对”） `[数字]`
- [ ] 必须人眼/人耳的项：写明谁在什么设备上验 `[人工]`

---

## 7. 测试要求

- 单测：纯逻辑（状态机、解析、过滤、迁移）必须覆盖。
- 渲染：用 `TestBackend` / 金标文件断言，不要求截图。
- 真机：用 `NP_TUI_SELFTEST`；截图只用于视觉项。
- 网络：用夹具/假 `Transport`，**不得访问真实平台**。
- 数据库：空库 + 旧版本库两条迁移路径都要测。

---

## 8. 删除 / 重构卡补充（类型 = 删除/重构时必填）

> 删除卡的失败模式不是“删不掉”，是“删一半”。完成条件必须比功能卡更硬。

- [ ] 被删功能的**入口**全部消失：命令、帮助、补全、错误码、配置键。
- [ ] 被删功能的**数据**有迁移/清理方案（schema 版本、备份、旧目录）。
- [ ] 被删功能的**依赖**从 `Cargo.toml` / `Cargo.lock` 移除。
- [ ] `cargo clippy` 不新增 `#[allow(dead_code)]`；被删模块无残留 `pub` 项。
- [ ] 残留词扫描为零（`rg` 关键词），allowlist 必须写原因和到期日。
- [ ] 文档、命令表、ADR 同步；破坏性变更必须有新 ADR。
- [ ] 测试数量下降要说明“删了哪些子系统”，不能只写“≥N”。

---

## 9. 文档影响

| 文档 | 动作 |
|---|---|
| `docs/30-计划/当前状态.md` | 里程碑/欠账变化时更新 |
| `docs/30-计划/命令表.md` | 命令/参数变化时更新 |
| `docs/20-架构/数据模型.md` | schema/迁移变化时更新 |
| `docs/20-架构/adr/` | 契约/依赖/结构变更时新增 ADR |
| `README.md` | 用户可见行为/构建方式变化时更新 |
| `CHANGELOG.md` | 每个合并卡加一行 |

**没有“文档影响：无”的卡**：至少要在 CHANGELOG 留一行；确实无影响要写“仅内部重构，无用户可见变化”。

---

## 10. 收口清单（合并前逐项勾）

- [ ] 全量门禁绿：fmt / clippy / test / docs。
- [ ] `git status` 干净；没有临时文件、截图、调试输出。
- [ ] 授权路径内文件全部改完；越界文件为零。
- [ ] 新依赖为零，或已有批准的“依赖申请”。
- [ ] 文档/ADR/CHANGELOG 已同步。
- [ ] 删除/重构卡完成 §8。
- [ ] 卡尾写 review verdict（PASS / PASS-WITH-NITS / BLOCK）与验收人。
- [ ] 基线 tag / 合并提交已打。

---

## 11. 回报格式（缺项视为未完成）

```
## 变更摘要
（改了什么，为什么这样改，关键取舍）

## 验证结果
| 命令 | 结果 |
|---|---|
| cargo test --workspace | ✅ N passed |
| cargo clippy --all-targets | ✅ |
| NP_TUI_SELFTEST="…" | ✅ 输出包含 … |
| 截图（如适用） | 路径 + 一句话说明 |

## 未决 / 风险
- 需要决策：xxx
- 已知限制：xxx

## 文档影响
- 需更新：xxx（由主线执行）
```

---

## 12. 风险与备注

- 不要自创与冻结契约冲突的字段名；先查 `np-core`。
- TUI 动效/布局项先 dump 字符网格或 `TestBackend`，截图只用于字体/颜色。
- 任何“以后可能要用”的保留字段/分支，默认删掉；要保留必须写 ADR。

---

## 附：常见退回原因

| 原因 | 后果 |
|---|---|
| 验收标准写成“界面美观” | 无法判定，必然返工 |
| 授权路径写成“相关文件” | 越界不可避免 |
| 没写非目标 | 实现者顺手加功能 |
| 依赖 `draft` 状态文档 | 依据不可信 |
| 卡片超过 2 天工作量 | 中途失控，拆卡 |
| 删除卡只写“删掉 X” | 必然留死代码/旧文档 |
