## 1. 背景（≤ 3 句）

M0 需要用假数据把两个窗口的样子定下来，先看效果再写逻辑。
播放器小窗是产品的主界面，它的完成度直接决定第一印象。

---

## 2. 目标（可验证）

- 小窗在 340×120 尺寸下完整呈现：封面、标题、副标题、进度条、时间、控制键。
- 覆盖 6 种状态：空闲 / 加载 / 播放 / 暂停 / 错误 / 拖拽。
- 悬停时控制键 120ms 淡入；移开 1.5s 后淡出。
- 所有数据来自本地 mock，不接 IPC。

---

## 3. 非目标（明确排除）

- 不接真实播放状态（M1 再做）。
- 不做窗口拖拽/置顶/透明（T-0002 负责窗口能力）。
- 不做超长标题的 Marquee 动效（M6 打磨）。

---

## 5. 授权路径

**可写**：

```
crates/np-tui/src/**
crates/np-tui/Cargo.toml
```

**禁改**（常见越界点）：

```
crates/np-core/**            ← 契约层，改动需另开卡
crates/np-app/**             ← 命令执行器
crates/np-audio/**           ← 播放链路
apps/**                      ← 已删除（2026-11-12）
Cargo.toml（workspace）       ← 仅主线可改
docs/**                      ← 文档由主线维护
```

> **写授权路径时必须逐项过一遍"注册点"**（M1 里四次踩坑，全是漏这个）：
>
> | 注册点 | 文件 |
> |---|---|
> | 依赖清单 | `Cargo.toml` / `package.json` |
> | 模块声明 | `lib.rs` / `mod.rs` / `index.ts` |
> | 命令注册 | `generate_handler!` / `invoke_handler` |
> | 入口/路由 | `vite.config.ts` / 前端入口文件 |
>
> 少写一个，实现者要么停工等你，要么偷偷越界——两种都在浪费一轮。

### 5.1 注册点核对（写卡时逐项填，不适用写"否"）

| 注册点 | 本次是否需要改 | 对应文件 | 已列入授权路径 |
|---|---|---|---|| 依赖清单 | 是 / 否 | `Cargo.toml` / `package.json` | ☐ |
| **运行时能力开关** | 是 / 否 | Cargo features / Tauri 权限 / 协议注册 / CSP | ☐ |
| 模块声明 | 是 / 否 | `lib.rs` / `mod.rs` / `index.ts` | ☐ |
| 命令注册 | 是 / 否 | `generate_handler!` / `invoke_handler` | ☐ |
| 入口 / 路由 | 是 / 否 | `vite.config.ts` / 前端入口 | ☐ |

> 这张表在 M0–M1 期间漏过 **5 次**（T-0011 的 `index.ts`、T-0013 的 `Cargo.toml`、T-0015 的 `lib.rs`、T-0016 的 `lib.rs` 再漏一次）。
> 漏了不是"小疏忽"——实现者要么停工等你一轮，要么越界后提心吊胆。

---

### 5.2 文件所有权（**并行时必须填**）

> 教训（T-0045 阶段 3 × T-0047）：两张卡都改 `command_exec.rs`，写卡的人没发现，
> 结果一个代理的未提交改动和另一个代理的中间态混在同一文件里，两边都得停下来等。

列出**本卡会写的每一个文件**（不是目录），派发前与在跑的卡逐条比对：

| 文件 | 读/写 | 与在跑的卡冲突？ |
|---|---|---|
| `apps/desktop/src-tauri/src/command_exec.rs` | 写 | 是 → **串行**，不要并行 |
| … | … | … |

**规则**：只要有一行"是"，两张卡就必须串行，或者由一个代理连做。
**同一个文件装不下两个并行的写入者**——这不是文件锁能解决的，是人要提前发现的。

## 6. 验收标准（逐条可执行）

> **每条后面必须标证据类型**：`[数字]`（可测量）/ `[图]`（必须人眼看）/ `[人工]`（必须人操作）。
> 标 `[图]` 的要说明**为什么不能量化**；标 `[人工]` 的写清**谁来验、怎么验**。
> 标 `[数字]` 的条目交截图视为未完成。

**本卡必须有至少一条可复现命令**（填在下面），否则验收只能靠口述：

```bash
# 例：cargo test -p np-tui
# 例：NP_TUI_SELFTEST="search 晴天;play 2" target/release/np-tui.exe
```

- [ ] 播放链路四项判据仍通过（status=Playing / 位置推进 / 非静音文件 / 无 E_AUDIO） `[数字]`。
- [ ] 布局在 140×40 与 100×30 两种窗口下不错位 `[图]`。

## 10. 风险与备注

- 如果 mock 数据结构和未来真实 `PlaybackState` 差异过大，会在 M1 造成返工——请参照 `开发方案 §4.3` 的事件字段命名，不要自创字段名。
- 动效一律用 `transform` / `opacity`，禁止动画 `width`。

---

## 附：常见退回原因（写卡时自查）

| 原因 | 后果 |
|---|---|
| 验收标准写成"界面美观" | 无法判定，必然返工 |
| 授权路径写成"相关文件" | 越界不可避免 |
| 没写非目标 | 实现者顺手加了三个功能 |
| 依赖了一篇 `draft` 状态的文档 | 依据不可信 |
| 卡片超过 2 天工作量 | 中途失控，拆卡 |
