# 流程改进空间（token 与准确度）

> 基于本会话真实发生过的失败，不写泛泛而谈的"最佳实践"。
> 每条都给**证据**（哪次出过问题）、**做法**、**预计收益**、**成本**。

---

## 1. 准确度：四类反复出现的失败

### 1.1 用了旧构建（发生 2 次）

| 场合 | 后果 |
|---|---|
| T-0056b 截图用了旧二进制 | 我报了两个"bug"，实际是上一个提交前的行为 |
| 单实例验证 | 把"命令没执行"当成"执行了且结果正确" |

**做法**：`scripts/verify.ps1` 每次先 `cargo build --release`，并把 **git HEAD 短 hash + 构建时间戳**写进产物（截图文件名或报告头）。
**收益**：消灭"证据与代码不对应"这一整类错误。
**成本**：2 小时。

### 1.2 命令静默失败被当成成功（发生 1 次，代价很大）

我发出启动第二实例的命令，执行器返回 `EXECUTOR_UNAVAILABLE`，随后我查进程数=1 就下了结论。

**做法**：验证脚本必须**断言副作用**（进程数、文件存在、退出码），而不是只看"看起来对"。
**收益**：高——这类错误会污染整份验收报告。
**成本**：0（写进规范即可）。

### 1.3 "逻辑对、显示错"（发生 3 次）

| 现象 | 为什么单测没抓住 |
|---|---|
| 候选首次出现不重绘 | 状态对，没触发绘制 |
| 高亮每帧被重置 | 单测只按一次键 |
| `Tab` 采纳没尾部空格 | `search` 与 `search ` 都能通过断言 |

**做法**：给 `Output → 渲染` 加**快照测试**（`TestBackend` 缓冲区逐格断言），把"渲染结果"变成可 diff 的文本。
**收益**：高。这类 bug 现在只能靠人看截图发现。
**成本**：1 天（先做 5 个关键块：表格/错误/候选/播放器条/状态栏）。

### 1.4 文档与代码脱节（发生多次）

删了 `apps/web` 后，`np-core` 仍 `include_str!` 引用它；删了设计文档后，多处链接悬空。

**做法**：门禁加两步
1. **悬空链接检查**：`docs/**/*.md` 里的相对链接必须存在；
2. **路径引用检查**：文档里出现的 `apps/`、`src-tauri` 等已删路径 → 警告。

**收益**：中高，纯自动。
**成本**：半天。

## 2. token：三个最大的浪费源

### 2.1 代理反复读大文件

`np-tui/src/main.rs` 已 **2800+ 行**。代理每次改一处都要读大段。

**做法**：按职责拆分
```
main.rs      入口/事件循环（<300 行）
layout.rs    三区布局与计数
render.rs    Output → 控件
input.rs     输入行与补全弹层
player_bar.rs 播放器条
theme.rs     已有
```
**收益**：**读上下文成本降一个数量级**；同时解锁并行（不同卡改不同文件）。
**成本**：1.5 天（纯搬移，测试护航）。**这是目前 ROI 最高的一件事。**

### 2.2 报告里塞长输出

代理常把整段 `cargo test` 输出贴进回报。

**做法**：约定**只报结论行**（`721 passed`），完整输出写 `tmp/report/<card>.log`，报告里给路径。
**收益**：单次回报从数百 token 降到几十。
**成本**：0（规范约束）。

### 2.3 一张卡反复返工

本会话 T-0049 改了 3 轮、T-0064 改了 2 轮。每轮都重读上下文。

**做法**：**卡里直接给出可执行验证命令**（已写进模板）+ **一次只验一个点**，不要一次改三处再统一验。
**收益**：返工轮次可减半。
**成本**：写卡时多花 10 分钟。

## 3. 建议的落地顺序

| 顺序 | 项 | 收益 | 成本 | 为什么排这个位置 |
|---|---|---|---|---|
| **1** | ~~拆分 ~~ **✅ 已完成** | token ⬆⬆ / 并行 ⬆⬆ | 1.5 天 | 3003 → 226 行 |
| **2** | `scripts/verify.ps1` + 构建戳 | 准确度 ⬆⬆ | 0.5 天 | 消灭"旧构建"这类错误 |
| **3** | 渲染快照测试 | 准确度 ⬆⬆ | 1 天 | 消灭"逻辑对显示错" |
| **4** | 文档链接/路径检查进门禁 | 准确度 ⬆ | 0.5 天 | 纯自动，防脱节 |
| 5 | 报告只报结论行 | token ⬆ | 0 | 规范即可 |

---

## 4. 不建议做的

| 想法 | 为什么不做 |
|---|---|
| 给代理加"自动读全部文档" | 更贵且更容易污染；按需读才对 |
| 引入向量检索/RAG 找代码 | 代码库不大（约 2 万行），grep 足够；引入成本远高于收益 |
| 全自动 e2e（点 UI） | 我们已经踩过"抢不到焦点"，投入产出比差；**headless 自检已经更好** |
| 每卡都写设计文档 | 文档会变成新的维护负担；**卡 + 代码注释足够** |

---

## 5. 一句话

> 当前最大的两个浪费：**大文件逼代理反复读**，和**验证只能靠人看**。
> 前者用"拆文件"解决，后者用"快照 + 无头自检"解决。

## 6. 两个由我造成的卡内矛盾（2026-11-12 修正）

### 6.1 删除类卡不能沿用"测试数不减"

**T-0079** 要求 `cargo test --workspace` ≥723，但它删除了整个封面子系统。
结果：**695 通过**，被判定"未达标"。

这是指标设计错误：**删除功能必然减少测试**，用"数量不减"衡量删除卡，等于逼实现者造假。

**规则修正**：

| 卡类型 | 验收口径 |
|---|---|
| 新增功能 | 测试数**只增不减** |
| **删除/重构** | **测试结果全绿 + 报告删了多少、属于哪些子系统**；数量下降是预期的 |
| 修 bug | 补回归测试，数量只增不减 |

### 6.2 降级规则要有优先级，不能并列

**T-0080** 同时写了：
- 高度 < 20 → 跳过启动页；
- 60×18 → 降级单行 NOWHERE。

**18 行同时满足两条**，代理只能二选一。实现选了"跳过"（正确），但卡本身是矛盾的。

**规则修正**：**降级条件必须按优先级排序，且互斥**：

```
1. height < 20          → 跳过启动页（最高优先）
2. width < 60, height ≥20 → 单行 NOWHERE
3. 其它                  → 完整大字
```

写卡时凡是"多个降级规则"，都要标序号并说明谁先命中。
