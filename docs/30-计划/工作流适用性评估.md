# 工作流适用性评估（Ratatui 迁移后）

> 问题：转向纯 Rust + Ratatui 后，我们的开发工作流还适用吗？
> 结论：**骨架仍然适用（约 70%），但有四处已经过时**，需要改。

---

## 1. 仍然有效的（不动）

| 机制 | 为什么仍然成立 |
|---|---|
| **卡 → 实现 → 自检 → 评审 → 集成** | 与语言/UI 技术无关 |
| **门禁 G1–G5** | fmt/clippy/test、无新依赖、文档同步——纯 Rust 更依赖这套 |
| **卡模板 §5.2 文件所有权** | 并行安全的核心；迁移期间它救过我们多次 |
| **验证者永远新开** | 与实现者同源会顺着找证据 |
| **§6 事实基线（卡里写死关键事实）** | 迁移后更多"旧决定"，更需要 |
| **§15 疑难杂症先查社区** | DECSET 2026 就是这么找到的 |
| **红线**：不新增依赖 / 不改冻结契约 / 不越界 | 全部保留 |

---

## 2. 已经过时的（必须改）

### 2.1 花名册有两个角色已无代码

| 角色 | 现在 | 处理 |
|---|---|---|
| **UI / 设计**（76610bdd） | CSS/skin/视觉回归——**没有 CSS 了** | 改为「**界面层**」：`np-tui` 布局/渲染/交互 |
| **桌面 / IPC**（6395e9db） | `src-tauri`、窗口、托盘——**已删除** | **注销**（能力并入界面层） |
| **库 / 扫描**（6f3a34e6） | 含「封面」——**已移除** | 职责改为「库/音源」 |
| **播放 / 音频**（cbf6134d） | 仍然准确 | 保留 |
| **验证者** | 仍然准确 | 保留 |

### 2.2 派发规则里的例子失效

> 「`apps/web` 的交给 UI/设计」

`apps/web` 不存在了。规则本身（范围变化=换角色）对，**例子要换**：
`crates/np-tui` → 界面层；`np-core/audio/library/sources` → 各自域。

### 2.3 §14「前端卡收敛规则」的动机消失了

当时写它的原因是：**前端要截图、截图最贵**。现在：

| 验证方式 | 成本 | 适用 |
|---|---|---|
| `NP_TUI_SELFTEST` 文本输出 | **极低** | 命令、播放、搜索、主题等**事实类** |
| 截图 | 高 | 布局、配色、字符画等**视觉类** |
| 人工 | — | 听声音、按媒体键、托盘点击 |

**结论**：规则不该删，但**要改写**——从"量替代看"升级为"**文本替代截图**"，并明确三档证据的优先级。

### 2.4 并行度实际上塌缩了

之前：`crates/**` 与 `apps/web/**` 天然可并行。
现在：**几乎所有 UI 卡都改 `np-tui`** → 同一文件区域，**并行必撞**。

这是新约束，必须写进规则。

## 3. 建议的修订（5 条）

| # | 修订 | 落在哪 |
|---|---|---|
| 1 | **花名册重设**：界面层 / 音频 / 库·音源 / 验证者；注销桌面层 | PLAN-007 §1 |
| 2 | **派发例子换新**（`np-tui` 替代 `apps/web`） | PLAN-007 §2 |
| 3 | **§14 改名为「TUI 卡收敛规则」**，核心改为三档证据优先级 | SPEC-001 §14 |
| 4 | **新增并行规则**：`np-tui` 单点串行；`np-core/audio/library/sources` 可并行 | SPEC-001 §5 |
| 5 | **新增验收入口**：每张卡必须写明"验证方式 = headless / 截图 / 人工"，并给出可复现命令 | 卡模板 §6 |

---

## 4. 一条值得强调的新原则

> **能打印成文本的，就不要截图。**

`NP_TUI_SELFTEST` 让"命令执行结果"变成可 diff 的文本——**这是迁移带来的最大流程红利**：验证成本从"千 token 的图"降到"几十 token 的字"。

以前我们靠"量替代看"（读像素），现在可以更进一步：**"字替代图"**。
