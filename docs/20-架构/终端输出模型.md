# 终端输出模型

> 一句话：命令层只产出**结构化数据**，不产出字符串；渲染层决定它长什么样。
> 这是让"xterm.js / 结构化自绘"两套方案可对比的前提——否则比较的是两套功能，不是两种呈现。

---

## 1. 为什么要有这层

如果命令层直接吐字符串，那：
- 换渲染器 = 重写所有命令；
- 表格、进度、错误提示无法复用；
- `--json` 输出与界面输出会各写一遍。

所以定义一层**与呈现无关**的输出模型：命令 → `Block` → 渲染器。这层一旦冻结，两套渲染器可以并行开发。

---

## 2. 数据形状

### 2.1 Block

一条命令 = 一个 Block。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 稳定标识，用于增量更新（进度条改写同一块） |
| `input` | string | 用户原始输入（含参数） |
| `startedAt` | number | 毫秒时间戳 |
| `durationMs` | number? | 结束时填充；运行中为 null |
| `status` | `pending` \| `running` \| `done` \| `error` \| `cancelled` | 驱动输入行的指示器 |
| `outputs` | Output[] | 输出区，按顺序渲染 |
| `footer` | string? | 尾注，如"3 条结果 · 输入 add 1-2 加入队列" |

### 2.2 Output（六种原语）

| 类型 | 字段 | 用途 | 结构化渲染 | xterm 渲染 |
|---|---|---|---|---|
| `text` | `spans: Span[]`, `tone` | 普通文本、键值行 | 段落，保留行内样式 | 逐 span 转 ANSI |
| `table` | `columns`, `rows`, `selectable` | 搜索结果、队列、库列表 | 真表格，行可悬停/点击 | 列对齐字符画，列宽按字符数计算 |
| `progress` | `label`, `current`, `total`, `unit` | 扫描、下载 | 进度条 + 百分比 | 单行 `\r` 重写 + 字符条 |
| `error` | `code`, `message`, `hint?`, `actions?` | 失败 | 红色卡片 + 可点击建议 | 红色文本 + `hint` 另起一行 |
| `hint` | `text`, `suggestion?` | 补全建议、纠错 | 灰色小字 + "按 tab 采纳" | 灰色文本 |
| `media` | `kind: cover\|thumb`, `ref`, `size` | 封面缩略图 | 图片（48×48） | **降级为文字占位** `[cover]` |

### 2.3 Span（行内样式）

| 字段 | 取值 | 说明 |
|---|---|---|
| `text` | string | 内容 |
| `bold` `dim` `italic` | boolean | 字重/明暗 |
| `color` | `accent` \| `danger` \| `warn` \| `success` \| `muted` \| null | **语义色**，不写具体色值 |

语义色到实际颜色的映射由渲染器负责（见 §4）。命令层永远不说"这是 #F2707A"。

### 2.4 约束

1. **不含 HTML、不含 ANSI 转义**：样式只有语义标记。
2. **不含布局信息**：不写"第 3 列宽度 120px"，宽度由渲染器决定。
3. **可序列化**：整套模型必须能直接 `JSON.stringify`，因为要跨 IPC 传给前端。
4. **增量友好**：`progress` 通过 `id` 原地替换，不追加新块。

---

## 3. 宽度与截断规则

| 场景 | 规则 |
|---|---|
| 表格列宽 | 按内容宽度分配，总宽超出时从最右列开始截断，加 `…` |
| 单元格最大宽 | 40 字符（结构化）/ 按终端列数（xterm） |
| 长文本换行 | 结构化：按单词换行；xterm：按终端列宽硬换行 |
| 窄窗口（< 640px） | 表格降级为"每行一条"的列表形态 |

---

## 4. 语义色映射

| 语义 | 结构化（CSS 变量） | xterm（ANSI 256） |
|---|---|---|
| `accent` | `var(--accent)` | 111（浅蓝） |
| `danger` | `var(--danger)` | 203 |
| `warn` | `var(--warn)` | 179 |
| `success` | `var(--success)` | 114 |
| `muted` | `var(--fg-muted)` | 244 |
| `null` | `var(--fg)` | 252 |

主题切换只改 `--accent` 等变量；xterm 主题通过 `terminal.options.theme` 设置，两者由同一份 token 生成。

---

## 5. 版本与兼容

- 模型带 `schemaVersion`（当前 1）。新增字段属兼容变更，删除/改语义属破坏变更，需 ADR。
- 渲染器必须忽略未知字段（向前兼容），遇到未知 `Output.type` 时降级成 `text` 输出 `[unsupported]`。

## 7. v1 冻结细节（T-0005 实现补充，2026-11-08）

契约原文只规定了字段语义、未规定具体类型；以下是 T-0005 落地时确定的值，**自本版起视为契约的一部分**，两套渲染器（T-0006 / T-0007）按此实现。

### 7.1 字段类型

| 字段 | v1 类型 | 说明 |
|---|---|---|
| `text.tone` | `Tone \| null` | `null` = 默认前景色 |
| `table.columns` | `string[]` | 列标题 |
| `table.rows` | `string[][]` | 单元格为纯文本，**不带 Span 样式**（需要样式时用 `text` 或其他原语） |
| `error.actions` | `string[] \| null` | 仅按钮文案；点击行为由后续命令层约定，v1 不定义 |
| `media.size` | `u32`（像素边长） | 正方形；若将来要 `{w,h}` 需 ADR |
| `hint.suggestion` | `string \| null` | 纯文本建议，如 `did you mean 'play'?` |
| 可选字段 | 序列化**恒输出 `null`**，反序列化允许缺省 | 不用"省略字段"表达可空 |

### 7.2 命名

- **wire（序列化结果）一律 `camelCase`**：`startedAt`、`durationMs`、`schemaVersion`。
- Rust 内部字段名照常 `snake_case` + `#[serde(rename_all = "camelCase")]`。
- 枚举 `type` 标签用 `snake_case`。
- 任务卡 T-0005 §6.1 中"字段名 snake_case"的表述**作废**，以本节为准。

### 7.3 未知值降级表

| 位置 | 未知值处理 |
|---|---|
| `Output.type` | 降级为 `text`，内容 `[unsupported]` |
| `block.status` | `pending` |
| `tone` / `span.color` | `null`（默认前景） |
| `media.kind` | `cover` |
| 未知字段 | 忽略（不报错） |

理由：跨版本兼容时，宁可显示一条占位也不能让整块反序列化失败——否则一条命令的输出可能拖垮整个终端历史。

### 7.4 参考实现

- 权威实现：`crates/np-core/src/terminal.rs`
- 前端镜像：`apps/web/src/shared/terminal-model.ts`
- 形状样例：`apps/web/src/shared/fixtures/terminal-demo.json`（覆盖 6 种原语，Rust 侧有往返测试）

## 8. `Block.actions`（T-0045 增补，向后兼容）

> 目的：错误块可以带**可点击的恢复动作**，而不是只有一行字。

```ts
type BlockAction = { label: string; input: string };

interface Block {
  // ...原有字段
  actions?: BlockAction[];   // 可选；缺省即"无动作"
}
```

### 8.1 规则

| 项 | 约定 |
|---|---|
| 字段位置 | **块级** `Block.actions`，不是 `Output::Error.actions`（后者标 legacy，UI 不再渲染；**下一个破坏性版本移除**） |
| 序列化 | `#[serde(default, skip_serializing_if = "Option::is_none")]`，**缺失时序列化省略**，不写 `null` |
| `input` | 点击后要执行的**命令原文**（含引号的引用规则与输入框一致） |
| 点击路径 | 走与输入框完全相同的 `cmd.exec`，不另开 IPC 捷径 |
| 历史 | 动作执行**不进** ↑/↓ 历史（它不是用户敲的） |
| 键盘 | 原生 `<button>`：Tab 可聚焦、Enter/Space 触发、`title` 显示将执行的命令 |
| `schemaVersion` | **仍为 1**（新增可选字段向后兼容） |
| 前端容错 | `actions` 非数组 / 元素缺 `label` 或 `input` → 整块降级为无动作，**不隐藏块本体** |

### 8.2 当前产出规则

| 错误类型 | 动作 |
|---|---|
| 一般命令错误 | 只有「重试」= 原命令 |
| `search` 失败（非 `--local`、关键词非空） | 「重试」+ 「只用本地搜索」= `search <关键词> --local` |
| 其它（如无对应命令可恢复） | 只有「重试」 |

**不产出"跳过该目录"之类的假按钮**——命令不存在时，一个按下去会报错的按钮比没有按钮更糟。
