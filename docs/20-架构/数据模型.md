# 数据模型

> M3 的契约：**表结构不定，扫描与搜索都没法写**。
> 归属：`crates/np-library`（SQLite 只在这一个 crate 里出现，其他 crate 不直接依赖 rusqlite）。

---

## 1. 基本约定

| 项 | 约定 |
|---|---|
| 引擎 | SQLite（`rusqlite`，bundled），**WAL 模式** |
| 位置 | 应用数据目录 `library.db`（Windows `%APPDATA%/com.nowhere.player/`） |
| 时间 | 全部存 **Unix 毫秒**（INTEGER），不存字符串日期 |
| 主键 | 全部 `INTEGER PRIMARY KEY`（rowid 复用） |
| 文本 | UTF-8；路径存**绝对路径**，不做相对化 |
| 迁移 | `PRAGMA user_version` 递增；每次升级前自动备份 `.db.bak` |
| 外键 | 开启 `PRAGMA foreign_keys = ON`，但**不做级联删除**（手动清理，避免误删） |

## 2. 表

### 2.1 `tracks`（核心表）

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | |
| `kind` | TEXT | `local` / `remote`（v1 只有 local） |
| `path` | TEXT | 绝对路径；远程为空串 |
| `source` | TEXT | `local` / `netease` / `bilibili` / `yt` |
| `source_id` | TEXT | 远程 ID；本地为空串 |
| `title` | TEXT | 缺失时用文件名兜底 |
| `artist` | TEXT | 多艺人用 `,` 连接（v1 不建 artist 关联表） |
| `album` | TEXT | |
| `album_artist` | TEXT | |
| `track_no` | INTEGER | 0 表示未知 |
| `disc_no` | INTEGER | 0 表示未知 |
| `year` | INTEGER | 0 表示未知 |
| `duration_ms` | INTEGER | 0 表示未知 |
| `sample_rate` | INTEGER | |
| `channels` | INTEGER | |
| `bitrate` | INTEGER | |
| `codec` | TEXT | `flac` / `mp3` / `aac` … |
| `cover_key` | TEXT | 封面缓存键（见 §3），空串表示无封面 |
| `size_bytes` | INTEGER | 文件大小，增量扫描用 |
| `mtime_ms` | INTEGER | 文件修改时间，增量扫描用 |
| `added_at` | INTEGER | 首次入库时间 |
| `last_seen_at` | INTEGER | 最近一次扫描见到的时间（判断文件是否消失） |

**唯一约束**：`UNIQUE(kind, path)`（本地）、`UNIQUE(source, source_id)`（远程，`source_id` 非空时）。

**索引**：
- `idx_tracks_title (title COLLATE NOCASE)`
- `idx_tracks_artist (artist COLLATE NOCASE)`
- `idx_tracks_album (album COLLATE NOCASE)`
- `idx_tracks_path (path)`（唯一约束已隐含）
- `idx_tracks_last_seen (last_seen_at)`

> v1 **不建 albums / artists 关联表**——一万首以内，按文本字段分组足够快；关联表等到需要"专辑封面/艺人页"时再加（会是一次 migration）。

| 列 | 类型 | 说明 |
|---|---|---|
| `key` | TEXT PK | |

### 2.5 队列（**不入库**）

T-0015 的队列是内存结构。持久化留到 M4，届时新增 `queue_items(position, track_id)`；本版不预留空表。

## 3. 封面缓存

| 项 | 约定 |
|---|---|
| 位置 | `<appdata>/covers/` |
| 命名 | `cover_key` = 内容哈希（首 16 位 hex） |
| 格式 | 512px 长边、WebP（quality 80） |
| 来源优先级 | 内嵌图 > 同目录 `cover.jpg` / `folder.jpg` / `front.jpg` |
| 清理 | 无引用（无 track 指向）的封面在扫描结束时删除 |

`cover_key` 为空串 = 无封面，前端用确定性渐变兜底（DES-002）。

---

## 4. 扫描语义

| 规则 | 说明 |
|---|---|
| 遍历 | 递归，跳过隐藏目录、`node_modules`、`.git` |
| 扩展名白名单 | `flac mp3 m4a aac ogg opus wav aiff aif` |
| 增量 | `(size_bytes, mtime_ms)` 都未变 → 跳过解析，只更新 `last_seen_at` |
| 消失 | 本次扫描未见到的旧记录：`last_seen_at < 本次开始时间` → **不删**，标记为"缺失"（前端可过滤） |
| 失败 | 单个文件解析失败 → 记录错误、继续；不中断整轮 |
| 取消 | 扫描任务可取消，已入库的部分保留 |
| 并发 | 解析用 `rayon`，但**写库单线程**（避免 SQLite 锁争用） |

## 5. 查询契约（给命令层用）

| 用途 | 语义 |
|---|---|
| `search(keyword, limit)` | 在 title / artist / album 上 `LIKE %kw%`（不区分大小写），按 title 排序 |
| `list_recent(limit)` | 按 `added_at DESC` |
| `list_by_album(album)` | 精确匹配 album |
| `stats()` | 曲目数、总时长、最近扫描时间 |

> **v1 不上 FTS5**：一万首以内 `LIKE` 足够；FTS5 放到 M4，届时加虚表 + 触发器，`search` 语义不变。

---

## 6. 边界（明确不做）

- 不做多用户/权限。
- 不做网络库（Subsonic 等）。
- 不做标签写回（只读）。
- 不做播放列表持久化（M4）。
- 不做跨设备同步。
