# 主题表达力边界与用户自定义

> 问题不是"设计一个 TUI 主题"，而是两个架构问题：
> 1. **在当前主题架构下，能做出多原汁原味的 TUI？**
> 2. **这种主题，用户能不能自己做出来？**

---

## 1. 当前架构能表达什么（准确清单）

| 层 | 内容 | 用户可改 |
|---|---|---|
| `tokens` | **14 个颜色**：bg / bgElev / bgHover / fg / fgMuted / fgFaint / accent / accentSoft / accentFg / danger / warn / success / line / lineStrong | ✅ 任意 |
| `skin` | **2 个枚举**：`plain` / `phosphor`（圆角、边框、阴影、字体、密度、出血） | ❌ 只能选 |
| 公开契约 | 12 个选择器 + 14 个颜色变量 | ✅ 名义上 |

**一句话**：用户能改**颜色**，不能改**结构**。

---

## 2. 逐条对照：原汁原味 TUI 需要什么

| TUI 要素 | tokens 能表达 | 现有 skin 能表达 | 缺什么 |
|---|---|---|---|
| 深色 / 浅色底 | ✅ | ✅ | — |
| 单一强调色 | ✅ | ✅ | — |
| 等宽字体 | ❌ | ✅ | — |
| 紧凑密度 | ❌ | ✅ | — |
| **整行反白选中** | ❌ 无 `selectionFg` | ❌ 组件只画左侧条 | 新 token + 组件分支 |
| **框线嵌标题** | ❌ | ❌ | 结构（box-drawing） |
| **字符块进度** | ❌ | ❌ | 组件渲染分支 |
| **全大写标签** | ❌ | ⚠️ 只能硬编在 skin 里 | 排版轴 |
| **斑马纹表格** | ❌ 无 stripe token | ❌ | 新 token |

**结论**：颜色层面能表达约 **60%**，结构层面接近 **0%**。
**只靠 tokens，做不出任何"原汁原味"的 TUI**——这也是第一版草案"大同小异"的根本原因。

---

## 3. 给用户开放结构能力的三条路

| 方案 | 表达力 | 成本 | 风险 |
|---|---|---|---|
| **A. 结构参数枚举**（structure 块） | 高（覆盖已知 TUI 语法） | 3–4 天 | 轴设计错了要返工 |
| B. 用户 CSS（ADR-0003 的 L2） | 无限 | 2 天 + 长期契约维护 | 布局可被写坏；升级即碎 |
| C. 每个 TUI 变体做成内置 skin | 高 | 每个 1–2 天，不可组合 | 用户无法自己扩展 |

**推荐 A**，理由：

- B 的表达力是"能改一切"，但**用户要的是"做出好看的 TUI"，不是"能写 CSS"**；
- C 把成本转嫁给我们，且用户永远只能等我们发版；
- A 是"给乐高块，不给刀"——**枚举轴保证结果一定成立**。

---

## 4. 推荐的 structure 轴（8 个）

```jsonc
"structure": {
  "radius":    "none | subtle | soft",        // 0 / 2px / 6px
  "border":    "none | hairline | box",       // 无 / 1px 高光 / 1px 实线框
  "density":   "compact | normal | relaxed",  // 行高 20 / 24 / 28
  "progress":  "line | blocks | bracket",     // 细线 / ▰▱ / [■■□□]
  "selection": "bar | reverse | bg",          // 左条 / 整行反白 / 仅底色
  "labels":    "sentence | upper",            // 原样 / 全大写+字距
  "stripe":    "off | on",                    // 表格斑马纹
  "font":      "mixed | mono"                 // 界面无衬线 / 全等宽
}
```

每个轴映射到一组 **CSS 变量 + `data-*` 属性**，**不开放任意 CSS**。

### 4.1 表达力验证：能否拼出三种 TUI

| 方向 | radius | border | selection | progress | labels | stripe |
|---|---|---|---|---|---|---|
| **T1 块面** | none | none | **reverse** | blocks | upper | on |
| **T2 线框** | none | **box** | bg | blocks | upper | off |
| **T3 票据**（亮色 token） | none | box | **reverse** | **bracket** | upper | off |

**三种都能拼出来**——说明这 8 个轴对"已知 TUI 语法"是够用的。

### 4.2 这些轴对现有两套 skin 的影响

- `plain` = radius soft、border hairline、density normal、progress line、selection bar、labels sentence、stripe off、font mixed
- `phosphor` = radius none、border none、density compact、progress line、selection bg、labels sentence、stripe off、font mono

**现有 skin 变成"结构预设"**，而不是硬编码的 CSS 文件。这是本次架构改造的核心。

---

## 5. 用户能不能自己做（直接回答）

| 阶段 | 用户能做什么 |
|---|---|
| **今天** | 改 14 个颜色 + 选 2 个 skin 之一 → **做不出 TUI** |
| **加了 structure 之后** | 改 14 个颜色 + 选 8 个轴 → **能做出上面三种 TUI** |
| 还缺什么 | ① 轴的校验与降级 ② 预览方式 ③ 编辑入口 |

**编辑入口现状**：`theme export <id>` 导出样例 JSON，用户改完放回 `themes/` 目录即生效——**这条路已经通了**，缺的是文档和校验。

---

## 6. 对 ADR-0003 的修订

原模型：

```
L1 tokens（开放） → L3 skin（我方，枚举）
```

新模型：

```
L1   tokens     开放            14 个颜色
L1.5 structure  开放（枚举）     8 个结构轴      ← 新增
L2   user CSS   推迟            任意样式
L3   skin       我方            结构预设 = structure 的一组取值
```

**L1.5 的位置很关键**：它比 token 表达力强，比 CSS 安全，**让"原汁原味 TUI"成为用户可达的目标，而不是我们独有**。

## 9. 一句话结论

> **不是"我们做一个 TUI 主题"，而是"把结构能力从 skin 里拆出来，变成用户可组合的 8 个轴"。**
> 做完之后，TUI 主题只是这套轴的第一个组合，**用户能自己做出它，也能做出我们没想到的**。

## 10. 技能复核（frontend-design，2026-11-11）

用 `frontend-design` 的反模板清单复核本方案，**发现三处直接冲突**。

### 10.1 冲突一：全大写标签（`labels: upper`）

技能原文把「**Using all caps for labels**」列为生成页最常见的破绽之一。

**判断**：在终端语境里全大写是**行话**（htop 的 F 键条、mc 的菜单、收据的字段名），属于"brief 指定的视觉方向"。
但若不加约束，它会变成"到处都是小大写标签"的装饰。

**修订**：
- `labels` 轴保留，但**默认 `sentence`**；
- 只在 `tui` 预设里用 `upper`；
- **禁止用在装饰性眉标上**（例如播放器的 `NOW PLAYING`），只用在内置的**字段名/表头**——它们本来就需要和内容区分。

### 10.2 冲突二：朱红强调色（T3 票据）

技能清单第 2 条：「近黑底 + 单一亮绿或**朱红**强调」是 AI 生成感最强的组合之一。
我原方案给 T3 配的 `#c0392b` 正是朱红。

**修订**：T3 改成**纯单色墨**——没有强调色。

```
纸 #f2efe9  /  墨 #1a1815（唯一文字色）
强调靠：字重、反白块、双线分隔
错误：仅用反白 + 前缀 `!!`
```

**理由**：收据本来就不印彩色；**去掉强调色反而更像真票据**，也彻底避开 tell。

### 10.3 冲突三：T1 的彩色选中

技能第 2 条同样针对"近黑 + 单一亮色"；我原方案让选中行用 `accent` 实心块，等于把强调色铺满整行。

**修订**：T1 的选中改成**反白（inverse video）**，不是彩色：

```
选中行：背景 = fg，文字 = bg（纯反白）
accent 只保留给：进度填充、状态点、提示符
```

**理由**：这恰恰是 htop/mc/vim 的做法——**选中是最强的对比，不是最艳的颜色**。也更符合 skills 的"亮色只在一处"。

### 10.4 复核后仍然成立的部分

| 技能要求 | 本方案 |
|---|---|
| Ground in subject matter | ✅ TUI 语法来自"字符网格"这个题材本身 |
| Structure is information | ✅ 框线/反白/斑马纹都编码"分区/当前/交替"，不是装饰 |
| Spend boldness in one place | ⚠️ **需要收**：每个 TUI 预设只允许一个"大胆"手法（T1=反白，T2=框线，T3=单色墨） |
| Restraint | ✅ 8 个轴是枚举，不是无限自由 |

### 10.5 修订后的轴表

| 轴 | 值 | 默认 |
|---|---|---|
| `radius` | none / subtle / soft | soft |
| `border` | none / hairline / box | hairline |
| `density` | compact / normal / relaxed | normal |
| `progress` | line / blocks / bracket | line |
| `selection` | bar / **reverse** / bg | bar |
| `labels` | **sentence** / upper | **sentence** |
| `stripe` | off / on | off |
| `font` | mixed / mono | mixed |

**变化**：`selection` 新增 `reverse`（反白），`labels` 默认改为 `sentence`。

### 10.6 三个预设修订后

| | radius | border | selection | progress | labels | stripe | accent 用在哪 |
|---|---|---|---|---|---|---|---|
| T1 块面 | none | none | **reverse** | blocks | upper | on | 仅进度与状态点 |
| T2 线框 | none | **box** | bg | blocks | upper | off | 仅焦点框 |
| T3 票据 | none | box | **reverse** | bracket | upper | off | **无强调色** |

### 10.7 一条新的验收标准

**任一预设中，反白块（或框线）必须只有一种用途**。
如果同时出现"反白选中 + 反白表头 + 反白状态栏"，那是把对比度当装饰用完——**技能里叫 spends boldness everywhere**。

## 11. 轴值的设计决定（2026-11-11，产品要求"现有观感也不完美"）

> 依据 `frontend-design`：结构即信息（structural devices encode information）、亮色只在一处、避开生成感清单。
> **T-0056 的"零变化"约束作废**：改为"有意的改动，逐条说明"。

### 11.1 现状的四个问题

| # | 问题 | 判据 |
|---|---|---|
| 1 | **行高 28px + 正文 13px 偏松** | 这是一个终端优先的产品；28px 行高是网页表格的密度，不是终端的 |
| 2 | **`labels: upper` 对中文无效** | 中文没有大小写，`text-transform` 是空操作。**用英文的语法套中文，等于没有这个轴** |
| 3 | **琥珀被用在"进度"上** | 我们自己定的规则是「琥珀只做信号」。进度是状态，不是信号——**自相矛盾** |
| 4 | **`box` 边框作用域不清** | 窗口已有一圈 1px 渐变边；再给窗口套框会双重描边 |

### 11.2 逐轴定值

| 轴 | 值 | 定值理由 |
|---|---|---|
| `radius` | `none / subtle(2) / soft(6)` | **soft 从 14 降到 6**：14px 圆角属于移动端卡片语言，桌面工具偏 6。播放器窗保持 14（它是"挂件"，需要软） |
| `border` | `none / hairline / box` | `box` **只作用于块与表格**，不作用于窗口（窗口边由 1px 渐变边负责） |
| `density` | `compact(20) / normal(26) / relaxed(30)` | 终端默认 `normal` 从 28 改 **26**；播放器窗不受此轴影响（固定 120 高） |
| `progress` | `line / blocks / bracket` | 保持；`blocks` 在 `font=mixed` 时回退 `line` |
| `selection` | `bar / reverse / bg` | 保持。**`reverse` 只用于"当前播放行"与候选当前项**，不用于所有可点行 |
| `labels` | **`sentence / tracked`**（原 `upper` 改名） | **`tracked` = 字距 `.06em` + 字重 500 + `text-transform: uppercase`**。大写对中文无害，字距与字重才是对中文有效的部分 |
| `stripe` | `off / on` | 保持。**与 `selection=reverse` 互斥**：一行不能同时"反白"和"斑马" |
| `font` | `mixed / mono` | 保持 |

### 11.3 琥珀的使用修正（重要）

| 用途 | 现在 | 改后 |
|---|---|---|
| 进度填充 | ✅ 琥珀 | ❌ 改为 `fg-muted`（进度是状态） |
| 播放头 | ✅ 琥珀 | ✅ 保留（它是"当前位置"这个信号） |
| 选中左缘条 | ✅ 琥珀 | ✅ 保留 |
| 焦点条 | ✅ 琥珀 | ✅ 保留 |
| 错误 | ❌ 红 | ✅ 红（信号） |

**理由**：一条 5 分钟的进度条如果一直是琥珀色，**琥珀就不再是"注意这里"了**——它变成了背景。这正是"亮色只在一处"的反例。

### 11.4 轴间互斥规则（必须写进校验）

1. `selection=reverse` + `stripe=on` → **stripe 强制 off**（一行不能两种底色信号）
2. `progress=blocks|bracket` + `font=mixed` → **progress 回退 line**
3. `border=box` → 窗口级不套框（仅块与表格）

### 11.5 修订后的预设

| 轴 | `plain`（改良） | `phosphor` | `tui`（T-0057） |
|---|---|---|---|
| radius | soft(6) | none | none |
| border | hairline | none | box |
| density | normal(26) | compact(20) | compact(20) |
| progress | line | line | blocks |
| selection | bar | bg | reverse |
| labels | sentence | tracked | tracked |
| stripe | off | off | off |
| font | mixed | mono | mono |

**`plain` 的三处有意变化**：圆角 14→6、行高 28→26、进度色琥珀→`fg-muted`。
