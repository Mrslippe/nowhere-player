# 音频架构与预留

> 一句话：v1 只做共享模式，但**接口按"将来可能换成独占/位完美"来设计**，换后端时不改上层。

---

## 1. 数据流

```
Decoder（symphonia，阻塞 IO 线程）
   │  f32 交错帧
   ▼
ProcessingPlan（是否重采样）
   └─ Resampler（rubato，仅当采样率不匹配）
   ▼
RingBuffer（无锁 SPSC，300ms）
   │
   ▼
Gain + Fade（在 sink 回调内，仅当 plan.gain）
   │
   ▼
AudioSink（trait，v1 = CpalSharedSink）
```

> **为什么 Gain 在 RingBuffer 之后**（T-0012 实测修正）：音量与暂停淡出必须**一个回调周期内**生效；若放在 ring 之前，改音量要等缓冲排空（最多 300ms），体验上是"按了没反应"。
> 代价是位完美场景要显式 `plan.gain = false` 旁路——这正是 `ProcessingPlan` 存在的意义。

**铁律**：`AudioSink` 的回调里不做分配、不加锁、不做格式化字符串。

---

## 2. 三个 trait（预留的扩展点）

| trait | 职责 | v1 实现 | 将来 |
|---|---|---|---|
| `AudioSink` | 打开设备、写入样本、报告延迟 | `CpalSharedSink` | `WasapiExclusiveSink` / `CoreAudioHogSink` / `AlsaHwSink` |
| `AudioSource` | 产出解码后的 f32 帧、是否可 seek | `FileSource` / `LiveAudioSource` | 更多在线源 |
| `DeviceProvider` | 枚举设备、查询能力 | `CpalDevices` | 独占模式下要额外暴露 "支持的采样率列表" |

**换后端 = 换一个 `AudioSink` 实现**，`PlayerActor` 与前端一行不改。这是本文件的核心约束。

直播源（ADR-0008）：`Player::open_source_with_ring(..., 150)`，`duration_ms=None`、`is_seekable=false`；普通文件仍用 300ms ring。直播不可 seek，停止后不自动下一首。`np-live` 内部另有 direct AAC 有界队列（target 900ms / max 1400ms / min 500ms）。

---

## 3. 位完美 / 独占的预留点

v1 不做，但必须现在留口子：

| 预留点 | 做法 | 不预留的后果 |
|---|---|---|
| **格式协商** | `AudioFormat { sample_rate, channels, sample_format }` 贯穿全链路，设备能力单独查询 | 现在写死 48k/立体声，将来改不动 |
| **旁路开关** | `ProcessingPlan { resample: bool, gain: bool }`，两者都为 false 时即"位完美直通" | 重采样器与增益器深度耦合，拆不开 |
| **样本格式** | 内部统一 f32，但 `AudioSink::preferred_format()` 允许设备要求 i16/i32 | 独占模式常要求设备原生格式 |
| **设备能力上报** | `DeviceCaps { formats: Vec<AudioFormat>, exclusive: bool }` | 前端无法展示"这个设备支持 24bit/96k" |
| **DSD 标记** | `Codec::Dsd` 枚举值 + `AudioSink::supports_dsd()` 默认 false | 将来加 DSD 要改解码器签名 |
| **音量归属** | 软件音量 = `gain: true`；独占模式应改用硬件音量（`gain: false` + 系统音量） | 独占下软件音量会破坏位完美 |

## 4. 线程模型

| 线程 | 职责 | 约束 |
|---|---|---|
| `AudioThread`（OS 线程，非 tokio） | 驱动 sink 回调、消费环形缓冲 | 无分配、无锁、无日志格式化 |
| `DecodeThread`（可多个） | 解码、重采样、填入环形缓冲 | 阻塞 IO 放这里 |
| `PlayerActor`（**单线程 actor**） | 状态机：播放/暂停/seek/切歌；对外发事件 | 串行处理命令，不并发改状态 |
| UI 线程 | 只收事件、渲染 | 不直接碰音频 |

> **修正（T-0013 实测）**：`np_audio::Player` 不是 `Send`（内部 `Engine` 持有 `Box<dyn AudioSink>`，trait 无 `Send` 约束；把 actor 移入 `thread::spawn` 实测 `E0277`）。
> 因此 actor **不能**是 tokio 任务，也**不能** `spawn_blocking` 返回它。
> v1 定为：`std::thread` + `std::sync::mpsc::recv_timeout(250ms)`，同一循环里处理命令与 4 Hz tick——零新增依赖，语义仍是单任务串行。
> 若将来 `AudioSink` 收紧为 `Send`，可换回 tokio 任务，actor 的对外契约不变。

**切歌**：预解码下一首 → 在样本边界拼接（gapless）；`ProcessingPlan` 在切歌时重算。

## 5. 事件（对上层）

| 线上事件名 | 频率 | 载荷（v1 已冻结） |
|---|---|---|
| `player:state` | 状态变化时 + 4 Hz | `PlaybackState`：`status`（idle/playing/paused/ended/error）、`trackId`、`positionMs`、`durationMs`、`volume`、`mode{repeat,shuffle}`、`error`（`{code,message} \| null`）、`queueLength`（`number \| null`）、`queueIndex`（`number \| null`） |
| `player:position` | 4 Hz，仅 Playing | `{ positionMs }` |

- `TrackEnded` **不单独开通道**，以 `player:state` 的 `status: "ended"` 表达（边沿去重）。
- `error` 字段是 T-0013 的契约扩展：异步失败（解码线程死亡、设备丢失）没有对应的命令返回，只能靠状态快照推送；命令失败仍走 `{code,message}` 直接返回。

> **边界（T-0025 定）**：`PlaybackState` **不携带媒体库元数据**（封面、艺人、专辑、歌词）。
> 播放器只知道"在播哪个文件"（`trackId` = 绝对路径），元数据由前端经 `library.trackByPath` 回库查询。
> 理由：否则每加一个元数据字段都要改 `np-core` + actor + 事件契约，音频层与库层耦合。

位置用 4 Hz + 前端 rAF 插值，不逐帧发。

> **命名约束**：Tauri 2.12 的事件名只允许字母数字与 `-` `/` `:` `_`，**点号非法**（`evt.player` 会得到 `IllegalEventName`，T-0013 实测）。统一用 `模块:事件`。

---

## 6. v1 边界（明确不做）

- 独占模式、位完美、DSD、ASIO。
- 硬件音量、多设备同时输出。
- EQ、可视化、淡入淡出之外的 DSP。

## 7. 未决

| # | 问题 | 状态 |
|---|---|---|
| 1 | 环形缓冲容量 | ✅ 已定 **300ms**（48k/2ch ≈112.5KB，实测 underruns=0） |
| 2 | 切歌交叉淡化是否 v1 就做 | 未定（M1 结束看体验） |
| 3 | 设备热插拔 | ✅ 已解决（T-0016）：tick 每 4 次（≈1s）比较「设备名+通道数」签名，变化则重开当前曲 → seek 回原位置 → 恢复原状态；失败 `E_DEVICE_LOST` |
| 4 | 输出延迟实测 | 未做环回测量；名义 12ms 斜坡 + 1 个回调周期 |
| 5 | 解码线程死亡后的恢复 | ✅ 已解决（T-0016）：tick 检测 `last_error` 且 playing → 重开一次并 seek 回位，预算在下一个健康 tick 复位；再失败 `E_DECODE` |
| 6 | 设备探测的误报率 | ⚠️ 待观察：驱动改名理论上已被「名称+通道数」复合判据挡住，但需真实使用数据 |
