# 音频架构与预留

> 一句话：v1 只做共享模式，但**接口按"将来可能换成独占/位完美"来设计**，换后端时不改上层。

---

## 1. 数据流

```
Decoder（symphonia，阻塞 IO 线程）
   │  f32 交错帧
   ▼
ProcessingPlan（是否重采样）
   └─ Resampler（rubato，仅当采样率不匹配）
   ▼
RingBuffer（无锁 SPSC，300ms）
   │
   ▼
Gain + Fade（在 sink 回调内，仅当 plan.gain）
   │
   ▼
AudioSink（trait，v1 = CpalSharedSink）
```

> **为什么 Gain 在 RingBuffer 之后**（T-0012 实测修正）：音量与暂停淡出必须**一个回调周期内**生效；若放在 ring 之前，改音量要等缓冲排空（最多 300ms），体验上是"按了没反应"。
> 代价是位完美场景要显式 `plan.gain = false` 旁路——这正是 `ProcessingPlan` 存在的意义。

**铁律**：`AudioSink` 的回调里不做分配、不加锁、不做格式化字符串。

---

## 2. 三个 trait（预留的扩展点）

| trait | 职责 | v1 实现 | 将来 |
|---|---|---|---|
| `AudioSink` | 打开设备、写入样本、报告延迟 | `CpalSharedSink` | `WasapiExclusiveSink` / `CoreAudioHogSink` / `AlsaHwSink` |
| `AudioSource` | 产出解码后的 f32 帧、可 seek | `FileSource` | `HttpStreamSource`（在线音源） |
| `DeviceProvider` | 枚举设备、查询能力 | `CpalDevices` | 独占模式下要额外暴露 "支持的采样率列表" |

**换后端 = 换一个 `AudioSink` 实现**，`PlayerActor` 与前端一行不改。这是本文件的核心约束。

---

## 3. 位完美 / 独占的预留点

v1 不做，但必须现在留口子：

| 预留点 | 做法 | 不预留的后果 |
|---|---|---|
| **格式协商** | `AudioFormat { sample_rate, channels, sample_format }` 贯穿全链路，设备能力单独查询 | 现在写死 48k/立体声，将来改不动 |
| **旁路开关** | `ProcessingPlan { resample: bool, gain: bool }`，两者都为 false 时即"位完美直通" | 重采样器与增益器深度耦合，拆不开 |
| **样本格式** | 内部统一 f32，但 `AudioSink::preferred_format()` 允许设备要求 i16/i32 | 独占模式常要求设备原生格式 |
| **设备能力上报** | `DeviceCaps { formats: Vec<AudioFormat>, exclusive: bool }` | 前端无法展示"这个设备支持 24bit/96k" |
| **DSD 标记** | `Codec::Dsd` 枚举值 + `AudioSink::supports_dsd()` 默认 false | 将来加 DSD 要改解码器签名 |
| **音量归属** | 软件音量 = `gain: true`；独占模式应改用硬件音量（`gain: false` + 系统音量） | 独占下软件音量会破坏位完美 |

## 4. 线程模型

| 线程 | 职责 | 约束 |
|---|---|---|
| `AudioThread`（OS 线程，非 tokio） | 驱动 sink 回调、消费环形缓冲 | 无分配、无锁、无日志格式化 |
| `DecodeThread`（可多个） | 解码、重采样、填入环形缓冲 | 阻塞 IO 放这里 |
| `PlayerActor`（tokio task，单任务） | 状态机：播放/暂停/seek/切歌；对外发事件 | 串行处理命令，不并发改状态 |
| UI 线程 | 只收事件、渲染 | 不直接碰音频 |

**切歌**：预解码下一首 → 在样本边界拼接（gapless）；`ProcessingPlan` 在切歌时重算。

---

## 5. 事件（对上层）

| 事件 | 频率 | 载荷 |
|---|---|---|
| `PlayerStateChanged` | 状态变化时 | `{ track_id, status, position_ms, duration_ms, volume, mode }` |
| `PositionTick` | 4 Hz | `position_ms` |
| `TrackEnded` | 每次结束 | `{ track_id, reason: natural \| error }` |
| `DeviceChanged` | 设备热插拔 | `{ device_id, caps }` |

位置用 4 Hz + 前端 rAF 插值，不逐帧发。

---

## 6. v1 边界（明确不做）

- 独占模式、位完美、DSD、ASIO。
- 硬件音量、多设备同时输出。
- EQ、可视化、淡入淡出之外的 DSP。

---

## 7. 未决

| # | 问题 | 状态 |
|---|---|---|
| 1 | 环形缓冲容量（200ms 还是 500ms） | ✅ 已定 **300ms**（48k/2ch ≈112.5KB，实测 underruns=0） |
| 2 | 切歌交叉淡化是否 v1 就做 | 未定（M1 结束看体验） |
| 3 | 设备热插拔的恢复策略 | ✅ v1 只上报 `DeviceLost`，不自动重建（M1 后期再补） |
| 4 | 输出延迟实测 | 未做环回测量；名义 12ms 斜坡 + 1 个回调周期 |
