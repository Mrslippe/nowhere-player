# ADR-0004 在线音源适配层

> 目标：让 `search` 能搜到在线曲目，`play` 能播放它们，而不破坏现有"本地文件即播"的模型。

---

## 1. 三个源，三种难度

| 源 | 接入方式 | 主要风险 |
|---|---|---|
| **B 站** | HTTP + `wbi` 签名（md5） | 签名参数会变；音轨需从视频流里挑 |
| **网易云（匿名）** | HTTP + `weapi` 加密（AES/RSA） | 加密算法随版本变；接口可能限流 |
| **yt-dlp** | 子进程 | **依赖外部二进制**，用户可能没装 |

三者共同点：**都不需要登录**。这是刻意的——不做账号体系，不存 cookie。

## 2. 关键决定：先下载再播放

`symphonia` 是从**文件/Reader** 解码的，不是流式的。要在现有 `np-audio` 上播在线音频，只有两条路：

| 方案 | 代价 |
|---|---|
| **A. 下载到临时文件再播**（选它） | 首次播放有 1–4s 延迟；占磁盘；实现简单、复用现有 Player |
| B. 改成流式解码 | 要改 `np-audio` 的 Source 抽象、缓冲、seek 语义——**等于重做音频层** |

**选 A。** 理由：M1 的 Player API 已经稳定且真机验证过，为流式重做音频层的风险远大于几秒延迟。yt-dlp 和 B 站本来就是"整段下载"，只有网易云支持 Range 请求——**为一个源做流式不值得**。

下载缓存目录：`<cache>/streams/<source>-<source_id>.m4a`，保留 7 天，超过 500MB 按 LRU 清理。

## 3. 适配层形状

```rust
pub trait AudioSource: Send + Sync {
    fn id(&self) -> SourceId;                       // netease | bilibili | ytdlp
    fn search(&self, query: &str, limit: usize) -> Result<Vec<SourceTrack>>;
    /// 取可下载地址（可能在几分钟后过期）
    fn resolve(&self, track: &SourceTrack) -> Result<ResolvedStream>;
}
```

- `SourceTrack` 字段与本地 `Track` **刻意不同**：没有 `path`，多一个 `(source, source_id)` 二元组。
- 命令层 `search` 返回的结果行带**来源标记**（`[网易云]` / `[B站]` / `[yt-dlp]`），用户能一眼看出播的是什么。
- `play <n>` 遇到远程结果时：resolve → 下载 → 用本地路径调 `player.play`。**播放器不知道"远程"这回事。**

> 这条边界很重要：`np-audio` 只认文件。所有"远程"逻辑止步于 `np-sources` + 命令层。

## 4. 网络策略

| 项 | 约定 |
|---|---|
| HTTP 客户端 | `reqwest`（rustls，不用 OpenSSL），**无 cookie jar** |
| 超时 | 连接 5s / 整体 15s |
| 重试 | 只对 5xx 与连接错误重试 1 次 |
| 并发 | 搜索串行（避免风控）；下载最多 2 个并发 |
| UA | 固定桌面 UA，不随版本变 |
| 频率 | 同一源两次请求间隔 ≥ 300ms |

**不做**：不做登录、不存 cookie、不做推荐流、不抓取用户数据。所有请求只带搜索关键词。

## 5. 测试策略（硬约束）

AGENTS.md 红线 #5：**测试不得访问真实平台**。

- 每个源都有 `fixtures/<source>/*.json`：录制的真实响应（脱敏后）。
- `Source` 实现接受注入的 `Transport` trait（`get(url) -> Result<Bytes>`），测试用夹具返回。
- 夹具里必须包含**至少一个失败样本**（限流/签名错/空结果）。

## 6. 失败降级

| 情况 | 行为 |
|---|---|
| 某源搜索失败 | 该源结果为空，**其它源照常**；终端里给一条 `hint` |
| 三个源全失败 | 返回 `E_SRC_UNAVAILABLE` |
| resolve 失败 / 地址过期 | 重新 resolve 一次，仍失败则报错 |
| 下载中断 | 删除半截文件；报 `E_SRC_DOWNLOAD` |
| yt-dlp 不存在 | 该源标记为不可用，搜索时跳过并提示如何安装 |

## 7. 依赖申请

| crate | 用途 | 备注 |
|---|---|---|
| `reqwest` | HTTP | features：`rustls-tls`、`json`、**`blocking`**；关掉 `default-features`（不要 `stream`，我们不流式播） |
| `md5` | wbi / weapi 签名 | 纯 Rust |
| `aes` + `cipher` | weapi 加密 | RustCrypto |
| `base64` | 同上 | |
| `serde_json` | 解析响应 | np-core 已有同样需求，一并放开 |

**不引**：`tokio` 作为显式依赖（用 reqwest 自带的 runtime，或阻塞 API）。**不做异步**——命令层本来就是同步的，用 `reqwest::blocking` 更贴合现有结构。

## 8. 为什么不做异步

Tauri 的 IPC 命令可以是 sync；音频 actor 是独立线程；扫描也是线程。引入 async 会让"下载→播放"这条链多一层运行时，收益只有并发度——而我们把并发限死在 2。

**结论：全同步 + 线程池。** 如果将来要并发拉多个源，用 `std::thread::scope` 就够。
