# ADR-0007 移除封面子系统与 schema v3

> 状态：**已接受**（2026-11-13 补记；实现发生在 T-0078 / T-0079，2026-11-12）
> 取代：[`ADR-0005`](ADR-0005-设置存储与命令族.md) 中与封面缓存相关的 `cache` 约定。

---

## 1. 背景

TUI 迁移后，播放器条只保留「名称 + 作者 + 进度 + 控制」，终端不再显示封面。T-0078 先删除了 `np-tui` 侧的封面渲染与 `ratatui-image` / `image` 依赖；T-0079 随后处理数据管线。

当时存在三条路：

1. 保留 `covers/` 与数据库 `cover_key`，只是不再显示；
2. 停止新写入，但保留列与缓存目录；
3. 彻底移除封面子系统，删除列与目录，清理依赖。

产品裁决是第 3 条：**“全部删掉，保证项目纯净，以后要用再加回来。”**

---

## 2. 选项与取舍

| 选项 | 优点 | 代价 |
|---|---|---|
| 保留列与缓存 | 未来恢复零迁移 | 扫描仍提取/写盘；数据库与文档长期背着死字段；用户看不到却付 IO/CPU |
| 只停止新写入 | 风险小 | 旧缓存与列继续存在，删除卡永远不闭环；代码里到处是“曾经有封面”的分支 |
| **彻底移除** | 扫描更快、依赖更少、契约清晰；删除卡可验收 | 需要破坏性迁移 v3；恢复要重写迁移；旧封面不可就地恢复 |

**选择彻底移除。** 理由：封面是“显示能力”，不是“播放正确性”的一部分；为一个不显示的功能保留数据管线，违反项目“能删就删”的文档/代码原则。

---

## 3. 决定

### 3.1 数据

- `tracks.cover_key`、`albums.cover_key` 在 schema v3 中删除；
- 迁移前照常复制 `<db>.bak`；迁移是**破坏性**的，不再遵守“只增不改”；
- `covers/` 旧目录在启动时清理一次（只删内容，不阻塞启动，不打印到库层）；
- `cover_key` 删除后不能就地恢复；要恢复只能从 git 历史取回旧代码，并新增 v4 迁移。

### 3.2 命令与缓存

- `cache stat` 只统计 `streams`；
- `cache clear` 只接受 `streams` / `all`；
- 删除 `covers` 枚举、帮助文案、统计字段与测试；
- `library stat` 不再输出封面缓存行。

### 3.3 代码与依赖

- 删除 `np-library` 的封面提取/编码/缓存模块与 `image` 依赖；
- 删除 `np-app` 的封面下载、`CoverStore`、封面目录字段；
- 删除 `np-tui` 的封面渲染与 `ratatui-image`；
- `np-app` 不再向 stderr 打印封面清理日志。

### 3.4 删除的完成条件

删除卡必须同时满足：

- `cargo clippy` 不新增 `allow(dead_code)`；
- 残留词扫描为零（允许“清理旧 covers 目录”这类明确例外）；
- 文档、命令表、ADR 同步；
- 空库 / v2 旧库两条迁移路径都有测试；
- 报告删除了哪些测试、哪些依赖，而不是只报“测试数不减”。

---

## 4. 后果

**接受：**

- 二进制更小，扫描少做封面解码/写盘；
- `cache` / `library stat` 契约变窄；
- 数据库 v3 不可逆，旧库升级前必须有备份；
- 未来恢复封面要重新设计数据模型，不能只加一列。

**不再接受：**

- 以“以后可能要用”为理由保留死字段、死目录、死分支；
- 删除卡只改一半，把剩余部分留给“以后清理”。

**重新考虑的条件：**

- 产品重新需要封面，且终端具备稳定的图形能力；
- 有明确的用户需求与新的 ADR（预计 ADR-0008+）。
