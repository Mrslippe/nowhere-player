# ADR-0009 B站扫码登录与凭证存储

> 状态：**已接受**（2026-11-18）。真机：room 23197314 扫码成功，DPAPI 凭证可解密，登录后 playurl `current_qn=10000`。
> 关系：ADR-0004 的“匿名音源”边界不变；登录态只用于 B站直播 API/取流。

---

## 1. 背景

ADR-0008 的直播链路默认匿名请求 `only_audio=1`。实测匿名 API 即使请求 `qn=10000` 仍降级为 `current_qn=250`，与登录浏览器 qn10000 的 CDN/转码不同；同源 URL 对比 app/浏览器差约 0.2s，而匿名 qn250 与登录 qn10000 可差到 1s。

用户要求扫码登录，并明确：

- 终端内扫码；
- 凭证加密存储；
- 可撤销；
- 不复用已泄露的旧 cookie。

## 2. 决策

### 2.1 QR 协议

```text
GET https://passport.bilibili.com/x/passport-login/web/qrcode/generate
GET https://passport.bilibili.com/x/passport-login/web/qrcode/poll?qrcode_key=...
```

poll：

```text
86101 未扫码
86090 已扫码待确认
86038 过期
0     成功，Set-Cookie
```

成功后保存：

```text
SESSDATA
bili_jct
DedeUserID
DedeUserID__ckMd5
sid
buvid3（如响应有）
refresh_token（如响应有）
```

### 2.2 Transport 窄接口

`np-sources` 增加：

```rust
pub struct HttpResponse {
    pub status: u16,
    pub headers: Vec<(String, String)>,
    pub body: Vec<u8>,
}

fn get_with_headers(&self, url: &str, headers: &[(&str, &str)]) -> Result<HttpResponse>;
```

- 默认实现回退 `get`（status 200、headers 空）；
- 生产 `ReqwestTransport` 回传真实状态/全部响应头/body；
- 不改变 `get`/`get_to`/`open_stream` 语义；
- 保留多个 `Set-Cookie`，不合并、不吞逗号。

### 2.3 登录入口

TUI-only：

```text
/login bili
/logout bili
```

不注册 `np-core` 命令族，避免命令表冻结契约变更。登录弹窗：

```text
QR
状态：等待扫码 / 已扫码待确认 / 成功 / 过期
Esc 取消，R 刷新
```

QR 用终端 Unicode 半块渲染；编码器 vendored 自 Project Nayuki `qrcodegen`（MIT），因为构建环境 crates.io 不可达。文件保留完整 MIT 许可头，不新增运行时依赖。

### 2.4 凭证存储

Windows：

```text
%APPDATA%\com.nowhere.player\bili-auth.bin
CryptProtectData / CryptUnprotectData（当前用户）
```

- 加密后原子写（同目录临时文件 + rename）；
- 文件不存在 → `Ok(None)`；
- 空/损坏/DPAPI 失败 → 可读错误，不 panic；
- `/logout bili` 删除文件；
- 非 Windows 第一版只保存在进程内存，不落盘；
- 日志、Display、Debug 不输出 cookie/QR URL。

### 2.5 登录态注入

- `np-live::api::fetch_play_info_with_auth` 在 playurl 请求带 `Cookie` 与 `Referer`；
- `np-live::prepare_default_auth` 接收 `Option<&BiliAuth>`；
- `TuiAudio` 在首次 `/live` 时从 AuthStore 懒加载，登录成功后立即使用；
- cookie 只用于 `api.live.bilibili.com` playurl，不用于音乐源、搜索、下载 CDN。

## 3. 行为

- 未登录：匿名 qn250，仍可播放；
- 登录有效：qn10000，`current_qn` 由真实响应验证；
- 登录失效/接口拒绝：回退匿名并提示，不阻塞播放；
- 退出登录：删除凭证，下一次 `/live` 匿名。

## 4. 安全边界

- 二维码本身是登录凭证；不截图、不写日志、不放剪贴板；
- cookie 只存 DPAPI 密文；
- 不复用旧 cookie；旧会话需用户自行撤销；
- 不实现账号密码登录；
- 不做 cookie 云同步；
- 不在测试中访问真实账号；真实扫码只由人工 T3 执行。

## 5. 兼容性

- `Transport::get_with_headers` 有默认实现，现有假实现不需要改；
- `prepare`/`prepare_default` 保持原签名，新增 `prepare_auth`/`prepare_default_auth`；
- TUI-only 命令不进入 `np-core` 命令表；
- Windows-only DPAPI 通过 `cfg(windows)` 隔离。

## 6. 验证

```text
AuthStore DPAPI roundtrip    通过
QR 86101/86090/86038/0 状态  通过（假 HTTP）
多 Set-Cookie 解析            通过
cookie_header/uid             通过
/qn10000 真实登录             current_qn=10000
LIVE 真机                     LIVE 1173ms
```
