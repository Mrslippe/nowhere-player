# 提交与分支规范

> 目标：任何一次提交都能回答“属于哪张卡、为什么改、验证过什么”。
> 本项目以 trunk-based 为主，不强制 PR；但**提交信息与收口产物**必须可审计。

---

## 1. 分支

| 场景 | 分支 |
|---|---|
| 默认 | `master` 直接开发（trunk-based） |
| 需要隔离的实验 | `spike/<主题>`，不合并，结论写文档 |
| 多步改动 | `t/00xx-短横线`，生命周期 ≤3 天 |
| 禁止 | 长期 `develop`、`release` 分支（当前阶段不需要） |

派发前打基线 tag：`base/T-XXXX`；合并/验收后打里程碑 tag。

---

## 2. 提交信息

格式：

```
<type>(<scope>): <中文摘要> (T-XXXX)
```

| 字段 | 规则 |
|---|---|
| type | `feat` / `fix` / `docs` / `test` / `refactor` / `chore` / `perf` / `ci` / `revert` |
| scope | crate 或领域：`core` / `audio` / `library` / `sources` / `app` / `tui` / `docs` / `ci` |
| 摘要 | ≤50 字，写“做了什么”，不写“update” |
| 卡号 | 有卡必须带 `(T-XXXX)`；纯文档/CI 可省 |
| 正文 | 非显然改动写“为什么/取舍/验证命令”；revert 必须写原因 |

示例：

```
fix(app): 移除 covers 残留并拒绝旧缓存目标 (T-0079)
docs(arch): 补 ADR-0007 与 schema v3 说明
```

**禁止**：`update`、`fix bug`、`wip` 进主干（`wip` 只允许中间提交，合并前 squash/改写）。

---

## 3. 提交粒度

- 每完成一个可验证的小步提交一次；一次提交只做一件事。
- 单卡 ≤400 行；删除/迁移卡可例外，但必须在卡里说明。
- 不允许“下次再修”的中间态进主干；编译不过不提交。
- 不提交生成物：`target/`、`tmp/`、截图临时文件、真实数据库/配置。

---

## 4. 提交前检查

```bash
git status --short          # 只应包含本卡文件
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
python scripts/check-docs.py
python scripts/check-contracts.py
python scripts/check-hygiene.py
```

- 工作区必须干净（或只剩明确说明的 WIP）。
- 不得 `git add -A` 卷入别人的改动；按路径 add。
- 文档/ADR/CHANGELOG 与代码同提交，不拆成“下次补”。

---

## 5. 合并与回滚

| 动作 | 规则 |
|---|---|
| 合并 | 先跑全量门禁，再合并；合并后更新当前状态 |
| 回滚 | 用 `git revert`，保留历史；正文写原因与影响 |
| 基线 | 每卡合并前打 `base/T-XXXX`，回滚有落点 |
| 里程碑 | 打 `vX.Y.Z-*` tag，CHANGELOG 与版本同步 |

---

## 6. 评审记录

- 每卡卡尾写 `review: PASS / PASS-WITH-NITS / BLOCK`，以及验收人/日期。
- 评审问题不修完不得打 base tag；NITS 可延后但要写卡号。
- 同一模型自审不算独立评审；关键卡（契约/删除/迁移/发布）尽量换人或外部 review。
