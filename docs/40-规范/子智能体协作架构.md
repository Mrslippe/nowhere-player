# 子智能体协作架构

> 一句话：**主线只编排、验收、合并；不同复杂度的实现交给 fresh 子智能体。**
> 目的：避免长会话里用 18～40 个工具步骤做几行改动；同时不把契约/质量问题外包掉。

---

## 1. 三条原则

1. **复杂度决定拓扑，不决定是否走完整发布流程。**  
   C0 不跑全量门禁；C3 才跑 T3。
2. **默认 `subagent`（fresh），不用 `subagent_fork`。**  
   fork 会继承当前长会话；fresh 只带任务卡。只有“必须继承设计上下文”时才 fork。
3. **executor 不跑全量门禁，verifier 只跑一次。**  
   避免重复构建、重复测试和主线读大日志。

---

## 2. 复杂度分级

| 级别 | 判定 | 例子 | 拓扑 |
|---|---|---|---|
| **C0 微改** | ≤2 文件、≤30 行、无契约/行为风险 | 键位、颜色、文案、单测 | 1 个 micro agent |
| **C1 小改** | 3～6 文件、单 crate | 局部 UI、单模块修复 | 1 个 executor |
| **C2 功能** | 跨 crate 或用户可见行为 | 面板、播放流程、搜索 | executor + verifier |
| **C3 架构/契约** | 新模块、schema、命令族、ADR、>6 文件 | 输入层重构、数据模型 | scout + 2 executor + verifier |
| **C4 审阅/调研** | 只读、多角度 | 产品审阅、架构评估、审计 | workflow 3～5 个 scout |

规则：

- 拿不准就升一级。
- 改 `np-core` 契约、`np-app` 命令族、schema、ADR → 至少 C3。
- 只改文档 → C0/C1，只跑文档检查，不跑代码测试。

---

## 3. 角色

| 角色 | 职责 | 权限 |
|---|---|---|
| **Orchestrator（主线）** | 分类、拆卡、分配、验收、合并、最终答复 | 可提交、可改胶水；不替 executor 铺全部实现 |
| **Scout** | 定位文件、符号、测试、风险、建议 diff | 只读 |
| **Executor** | 在授权路径内实现代码/测试/文档，跑定向验证 | 不提交、不发布、不越界 |
| **Verifier** | 独立验收：需求、越界、测试质量、契约、门禁 | 只读 |
| **Release/PTY** | release 构建、启动、截图/PTY 验收 | 仅 C2/C3 需要时 |
| **Docs/Contract** | 文档、索引、ADR、契约检查 | 授权文档路径 |

硬规则：

- 同一文件同一时间只允许一个 agent 写。
- 子智能体不提交、不合并、不发布。
- 契约/schema/命令族变化必须停下来报告；不得顺手改。

---

## 4. 任务卡

```text
级别：C0/C1/C2/C3
目标：
授权路径：
禁止：
验收条件：
验证级别：T0/T1/T2/T3
最大步骤：
返回格式：STATUS / FILES / TESTS / RISKS
```

子智能体 prompt 必须自包含，只带相关文件；不允许“先读整个仓库”。

---

## 5. 执行流程

```text
请求
  ↓
主线分类 C0-C4
  ↓
写最小任务卡
  ↓
spawn fresh subagent
  ↓
executor 实现 + 定向验证
  ↓
verifier 独立验收（C2/C3）
  ↓
主线看 diff/证据 → 合并/提交
  ↓
最终汇报
```

主线不逐行读子智能体完整日志，只看：

- `git diff --stat`
- 定向测试/门禁结果
- verifier 结论

---

## 6. 验证级别

| 级别 | 内容 |
|---|---|
| **T0** | `cargo check -p np-tui` + 1～2 个定向测试 |
| **T1** | crate tests + clippy |
| **T2** | workspace tests + fmt + clippy + docs/contracts |
| **T3** | `check.ps1` + release 构建 + 真机/PTY 验收 |

对应：

```text
C0 → T0
C1 → T1
C2 → T2
C3 → T3
C4 → 无
```

全量门禁（G1～G6）在 C2/C3 完整执行；C0/C1 按级别裁剪，但**红线不裁剪**：不越界、不新增依赖、不改契约、不提交敏感数据。

---

## 7. 并行与 worktree

- **C0/C1/C2**：默认串行，不开 worktree，避免合并成本。
- **C3**：
  - 打 `base/T-XXXX` tag；
  - 两个 executor 各用独立 worktree；
  - 主线只接收 diff/摘要；
  - verifier 在集成后的主工作区跑 T3；
  - 冲突由主线解决，不自动合并。
- **C4**：workflow 并行 scout；只读，不写工作区。

---

## 8. Token 边界

1. 默认 fresh `subagent`，不 fork 长会话。
2. 子智能体只读授权文件，不扫全仓。
3. 微改不截图、不重建 release、不重启应用、不跑全量门禁。
4. 多个微改合并成一次请求，由同一个 micro agent 批量做。
5. 超过最大步骤没有产出就中断，不让 agent 漫游。
6. 主线最终答复只给摘要、验证数字、commit/build/PID；不复述 agent 日志。

## 9. 示例

| 任务 | 级别 | 分配 |
|---|---|---|
| `,` / `.` 全半角键位 | C0 | 1 个 micro agent；T0 |
| 五键播放控制 | C1 | 1 个 executor；T1 |
| 输入层重构 | C3 | scout + executor + verifier；T3 |
| 产品/架构审阅 | C4 | workflow scout；主线汇总 |
| 状态栏颜色微调 | C0 | 1 个 micro agent；T0 |

---

## 10. 不外包的事

- 需求是否成立、范围如何取舍；
- 契约/schema/命令族决策与 ADR；
- 冲突解决、合并、提交；
- 最终验收与对用户的汇报；
- 跨任务的优先级排序。

---

## 11. 失败处理

| 情况 | 处理 |
|---|---|
| executor 无产出/超步骤 | `interrupt_agent`，收窄任务或换 agent |
| verifier 发现越界/契约变更 | 停止合并，补卡或回滚 |
| 两个 executor 冲突 | 主线按路径所有权解决；必要时重做 |
| 测试环境/构建锁失败 | 主线处理环境，不把失败当代码结论 |
| 需求本身不清 | 停下来问用户，不猜 |
