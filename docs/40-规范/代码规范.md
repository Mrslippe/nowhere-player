# 代码规范

> 只写本项目**额外**要求的规则；Rust 官方风格与 `rustfmt` 默认值不重复。
> 目标：让代码在 35k 行、单人/AI 主导的条件下仍然可读、可测、可删。

---

## 1. 分层与依赖

| 规则 | 说明 |
|---|---|
| 依赖方向 | `np-tui → np-app → np-library/np-sources → np-core`；`np-audio` 独立 |
| IO 位置 | SQLite 只在 `np-library`；HTTP 只在 `np-sources`；cpal 只在 `np-audio` |
| UI 不碰业务 | `np-tui` 不写 SQL、不拼协议、不判定“能不能播” |
| 库不打印 | `np-app` / `np-library` 不得 `println!/eprintln!`；需要诊断就返回错误或事件 |
| 端口 trait | 跨模块能力用 `PlayerApi` / `LibraryApi` / `OnlineApi` / `Transport`，不要在 UI 里直接 new 具体实现 |

---

## 2. 错误处理

- 库层用 `thiserror` 或自定义 `Error`；命令层用 `CmdError { code, message, hint }`。
- **用户能看到的错误必须有 `hint`**（用法、下一步、可重试建议至少一个）。
- 错误码是契约：新增/删除/改语义必须同步 `命令表` 与 ADR；不要在 UI 里硬编码 `E_*` 字符串。
- 禁止 `unwrap()` / `expect()` 处理外部输入、文件、网络、数据库；测试代码除外。
- Mutex 中毒：生产代码用 `unwrap_or_else(PoisonError::into_inner)` 或明确恢复策略；不要无理由 `unwrap()`。

---

## 3. 模块与文件预算

| 规则 | 说明 |
|---|---|
| 单文件目标 ≤800 行 | 超过在卡里写拆分理由 |
| 单文件硬上限 1,800 行 | 超过必须拆；测试文件上限 6,000 |
| 单函数目标 ≤80 行 | 超过优先抽小函数 |
| 一个文件一个主题 | 执行器、在线服务、库句柄、设置不要塞进同一个文件 |
| 测试独立 | 优先 `command/tests.rs`，不要 5,000 行内联测试 |

---

## 4. unsafe

- 默认不写 `unsafe`；需要 Win32 FFI 时，集中到 `np-tui` 的平台模块。
- 每个 `unsafe` 块必须有 `// SAFETY:`，写清指针/生命周期/线程/返回值假设。
- 能用安全封装就不用裸 FFI；新增 `windows-sys` 等依赖要先走“依赖申请”。
- `clippy::undocumented_unsafe_blocks` 作为目标 lint；暂时无法全仓开启时，至少人工 review。

---

## 5. 命名与注释

| 对象 | 规则 |
|---|---|
| crate | `np-` + kebab |
| 模块/函数/变量 | snake_case |
| 类型/枚举 | PascalCase，语义完整 |
| 常量 | SCREAMING_SNAKE_CASE |
| 注释 | 中文写“为什么/边界/坑”，不写“这行在赋值” |
| 过期注释 | 改行为必须改注释；删除功能必须删注释，不留“曾经有封面” |

---

## 6. 依赖与数据

- 新增 crate 必须走“依赖申请 + ADR”（见 AGENTS 红线）。
- 数据库迁移：只增不改是默认；破坏性迁移必须 ADR + 备份 + 测试。
- 文件写入：先 `.part` 再 rename；配置先 `.tmp` 再 rename；失败清理临时文件。
- 网络：必须设连接/整体/下载超时、节流、有限重试；测试用假 `Transport`，不访问真实平台。

---

## 7. 删除/重构

- 删除功能必须同时删：入口、帮助、补全、错误码、配置键、调用方、测试、文档。
- 不得用 `#[allow(dead_code)]` 掩盖残留；crate 级 allow 一律禁止。
- 删除卡完成条件见 [`ADR-0007`](../20-架构/adr/ADR-0007-移除封面子系统与schema-v3.md) §3.4。

---
