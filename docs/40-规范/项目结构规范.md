# 项目结构规范

> 目标：让“加一个功能”永远只动应该动的地方；让新人（或新智能体）十分钟内知道该去哪。
> 2026-11-13 修订：删除 `apps/`、Tauri、React、pnpm 相关内容；按纯 Rust + Ratatui 现状重写。

---

## 1. 三条总则

1. **单一职责**：一个 crate / 一个目录，只回答一个问题。
2. **单向依赖**：依赖只能从上往下流，禁止环、禁止反向。
3. **随时可运行**：主干任何时刻都能 `cargo build --workspace` 通过；半成品用 feature flag 挡住，不用注释挡住。

---

## 2. 目录结构

```
nowhereplayer/
├─ AGENTS.md                  # 智能体入口（必读）
├─ README.md                  # 人类入口（构建、运行、键位）
├─ CHANGELOG.md               # 版本变更
├─ LICENSE                      # MIT
├─ Cargo.toml                 # Rust workspace
├─ rust-toolchain.toml        # 工具链锁定
├─ .editorconfig / .gitattributes / .gitignore
│
├─ docs/                      # 全部文档，见 docs/README.md
├─ crates/                    # 纯 Rust
│  ├─ np-core/                # 领域模型、命令、错误码、终端输出、主题 schema、设置
│  ├─ np-audio/               # 解码、重采样、cpal 输出、播放状态机
│  ├─ np-library/             # 扫描、标签、SQLite、歌单、检索
│  ├─ np-sources/             # B 站 / 网易云适配、下载缓存
│  ├─ np-live/                # B 站直播 API、FLV→ADTS、直播 AudioSource
│  ├─ np-app/                 # 与宿主无关的命令执行器
│  ├─ np-tui/                 # Ratatui UI、事件循环、托盘/热键/启动器
│  └─ np-system/              # 空壳（历史遗留；见 §4）
├─ scripts/                   # check / verify / docs / tools
├─ spikes/                    # 一次性实验，不在 workspace 内
└─ .github/workflows/         # CI
```

**没有 `apps/`、没有 `package.json`、没有 pnpm、没有 Tauri。** 任何人重新引入这些，必须先提 ADR。

## 3. 依赖方向

```
        np-tui ──────────────▶ np-audio
          │
          ▼
        np-app ──────────────▶ np-core
        │     │
        │     └──────────────▶ np-sources
        └────────────────────▶ np-library
                    │
                    └────────▶ np-core
```

> 2026-11-17 新增 `np-live`：`np-tui -> np-live -> np-audio / np-sources`。`np-live` 不依赖 `np-tui`、`np-app`、`np-library`；直播只把 `AudioSource` 交给播放器，不反向依赖 UI。

| 规则 | 违反示例 |
|---|---|
| `np-core` 不依赖任何 `np-*` | core 里 `use np_audio::Player` ❌ |
| `np-*` 不依赖 `np-tui` | 库里 `use ratatui::...` ❌ |
| `np-library` / `np-sources` 不互相依赖 | `np-library` 直接调用 B 站 API ❌ |
| `np-audio` 不依赖 `np-library` / `np-sources` | 播放器里读 SQLite ❌ |
| `np-tui` 不直接写 SQL / 网络协议 | UI 里 `rusqlite::Connection` ❌ |
| `np-app` 不依赖 Tauri / Ratatui | 执行器里 `tauri::AppHandle` ❌ |

**跨模块通信只走两种方式**：`np-core` 里定义的类型/事件，或 `np-core` 里定义的 trait。`np-app` 的 `PlayerApi` / `LibraryApi` / `OnlineApi` / `ThemeApi` 就是端口。

## 4. crate 职责边界

| crate | 负责 | 明确不负责 |
|---|---|---|
| `np-core` | `Track`/`Queue`/`PlaybackState`、`Command`/`Spec`、错误码、配置结构、终端输出、主题 schema | 任何 IO、网络、音频设备、UI |
| `np-audio` | 解码、重采样、cpal 输出、播放状态机、位置上报、样本 tap | 网络、数据库、UI |
| `np-library` | 文件遍历、标签、SQLite、歌单、查询、迁移 | 播放、网络音源 |
| `np-sources` | 音源协议、wbi/签名、取流、下载缓存 | 播放、入库、UI |
| `np-live` | B 站直播 API、HTTP-FLV→ADTS、直播 `AudioSource` | UI、队列、弹幕输入、数据库 |
| `np-app` | 命令解析后的编排、会话上下文、后台任务、端口适配 | Tauri、Ratatui、直接持有 UI 状态 |
| `np-tui` | 布局、渲染、键位、模式、启动器、托盘、热键、单实例 | 业务规则、SQL、协议签名 |
| `np-system` | **当前为空壳** | 不再新增职责；见下 |

**`np-system` 的处理**：托盘、媒体键、单实例、自启已经并入 `np-tui`。保留空 crate 只是历史遗留。
要么在后续卡中删除它（需 ADR），要么把它变成真正的平台层（Windows/macOS/Linux 分支）。
在决定之前，**不要**往 `np-system` 里加新代码。

## 5. 命名

| 对象 | 规则 | 示例 |
|---|---|---|
| Rust crate | `np-` 前缀 + kebab | `np-audio` |
| Rust 模块 | snake_case | `playback_state.rs` |
| Rust 类型 | PascalCase，语义完整 | `PlaybackState`、`SourceId` |
| 函数 / 变量 | snake_case | `validate_theme_id` |
| 常量 | SCREAMING_SNAKE_CASE | `MAX_THEME_ID_LEN` |
| 文档 | `NN-分类/中文标题.md` | `10-设计/TUI交互模型.md` |
| 任务卡 | `T-00xx-短横线标题.md` | `T-0086-新布局P1.md` |
| 分支 | `t/00xx-短横线`（需要时） | `t/0087-cleanup` |
| 提交 | Conventional Commits + 卡号 | `fix(app): 移除 covers 残留 (T-0079)` |

## 6. 文件与模块预算

| 规则 | 说明 |
|---|---|
| **单文件目标 ≤ 800 行** | 超过要在 PR/卡里写拆分理由 |
| **单文件硬上限 1,800 行** | 超过必须拆；历史例外进 allowlist 并带到期日 |
| **单函数目标 ≤ 80 行** | 超过优先抽小函数；不是硬门禁 |
| **一个文件一个主题** | `command.rs` 不应同时放执行器、在线服务、库句柄、设置 |
| **测试可以独立文件** | `command/tests.rs` 比 5,000 行内联测试好 |

> 行数只是代理指标，不是目的；真正的判据是“读这个文件的人是否需要同时理解五个子系统”。

## 7. 迭代规则

| 规则 | 说明 |
|---|---|
| **主干开发** | trunk-based；分支生命周期 ≤ 3 天；不允许长期 `develop` |
| **小步提交** | 单卡 ≤ 400 行；删除/迁移卡可例外，但必须在卡里说明 |
| **每次提交可构建** | 不允许“下次再修”的中间态进主干 |
| **行为变更必带文档** | 同卡更新对应文档与 CHANGELOG |
| **数据库变更必带迁移 + ADR** | 迁移前自动备份；破坏性迁移必须 ADR |
| **未完成功能用 feature flag** | 默认关闭，不删代码、不注释 |
| **破坏性变更靠版本号** | `0.x` 允许破坏，但必须在 CHANGELOG 写清楚 |

## 8. 什么时候才允许“加一层”

过早抽象是本项目最大的结构性风险。判据：

| 动作 | 允许的前提 |
|---|---|
| 新增 crate | 现有 crate 的职责已经说不清，且有 ≥ 2 个明确使用方；先提 ADR |
| 抽 trait | **已知**有 ≥ 2 个实现（`AudioSource` / `Transport` 属于此类） |
| 加一层 service | 该逻辑同时被 ≥ 2 个入口调用 |
| 引入状态管理库 | 跨窗口/跨模块共享状态已经超过 3 处 |
| 引入 UI 组件库 | 自己写的基础组件超过 10 个且开始重复 |

**反模式（看到就打回）**：

- 为了“以后可能扩展”而预留的抽象层；
- `utils.rs` / `helpers.rs` 这种无主题的垃圾桶；
- 循环依赖靠“延迟 import”绕过；
- 一个文件超过 1,800 行还没有拆分理由；
- 在 UI 层做业务判断（“这首歌能不能播”应在 core/sources 判定）。

## 9. 目录的三条禁令

1. **不允许根目录堆文件**：根目录只放 `README`、`AGENTS`、`CHANGELOG`、`LICENSE*`、workspace 配置和 `docs/`、`crates/`、`scripts/`、`spikes/`、`.github/`。
2. **不允许 `misc/`、`temp/`、`test2/`**：临时文件进 `.gitignore` 的 `tmp/`，且 `tmp/` 不入库。
3. **不允许把文档放进代码目录**：所有文档在 `docs/`；代码目录里的 `README.md` 只允许写“这个 crate 干什么、入口在哪”（≤ 30 行）。
