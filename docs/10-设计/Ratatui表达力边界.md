# Ratatui 表达力边界

> 迁移到 Ratatui 后，"能做到什么、做不到什么"需要一份明确清单。
> 本文区分**终端物理边界**、**Ratatui 库边界**、**我们的产品边界**三层。

---

## 1. 物理边界：字符网格

终端的一切表达都建立在一个事实上：**画面是 M 列 × N 行的单元格，每个单元格只能有一组字符 + 前景色 + 背景色**。

| 后果 | 说明 |
|---|---|
| 分辨率 = 列数 × 行数 | 200×60 的终端是 12,000 个"像素"，且每个格子形状固定 |
| 没有亚格定位 | 文字不能放在格子中间，不能做字距/行距微调 |
| 没有合成层 | 只有绘制顺序，没有 z-index、透明、模糊、阴影 |
| 字形由终端渲染 | 抗锯齿、字重、连字全都不归我们管 |

**这一层不可突破。** 所有"看起来更精细"的手段都是**在格子内做文章**（见 §3）。

---

## 2. 能做到什么（按价值排序）

| # | 能力 | 说明 |
|---|---|---|
| 1 | **布局** | `Constraint`（百分比/长度/最小/最大）+ 嵌套。随窗口尺寸自动重排 |
| 2 | **边框与标题** | 三套边框字符集；标题嵌在上边框；可自定义字符集 |
| 3 | **逐 span 样式** | 前景/背景/粗体/暗淡/斜体/下划线/反白，可精确到字符 |
| 4 | **图像（Sixel/Kitty/iTerm2）** | `ratatui-image`：先问终端字体像素尺寸，再把图片精确映射到格子区域 |
| 5 | **Braille 画布** | 一个单元格 = 2×4 个点 → **分辨率提升 8 倍**，适合曲线/频谱/散点 |
| 6 | **表格 / 列表 / 图表** | `Table`（可滚动、可按列约束）/ `List` / `Chart` / `BarChart` / `Sparkline` |
| 7 | **真彩色** | 终端支持时可用 24 位 RGB |
| 8 | **鼠标** | crossterm 提供点击/滚轮/拖动事件（我们暂未启用） |
| 9 | **光标控制** | 形状 + 位置可控——**这就是中文输入法候选窗能正确定位的原因** |
| 10 | **备用屏幕 / 括号粘贴 / 焦点事件** | 终端提供的标准能力 |

### 2.1 我们已实测到的

| 项 | 实测 |
|---|---|
| Sixel 封面 | ✅ Windows Terminal 生效，可辨 |
| 内存 / 启动 | 15.2 MiB / 61 ms（含音频与封面初始化） |
| CPU | 播放 1.9% / 暂停 0.6% |
| 中文输入 | ✅ 候选窗位置正确 |

## 3. 做不到什么

### 3.1 物理不许

| 想要 | 为什么 |
|---|---|
| 圆角、阴影、模糊、渐变背景 | 没有合成层 |
| 平滑 60fps 全屏动画 | 每帧要重写变化的单元格，终端吞吐有限 |
| 任意排版（字距、行距、混排基线） | 格子是固定的 |
| 彩色 emoji | 取决于终端字体，**Windows Terminal 默认缺彩色 emoji 字形**（我们踩过） |
| 元素级交互（真正的按钮、滚动条、拖拽） | 都得自己画、自己判命中 |

### 3.2 Ratatui 库不许（但可以自己做）

| 缺什么 | 我们怎么补的 |
|---|---|
| 文本输入控件 | 自己写状态机（已做） |
| 补全弹层（浮层） | 固定区域绘制（已做） |
| 焦点/事件系统 | 自建（目前是单焦点） |
| 图像滚动 | `ratatui-image` 会跳过图像区域，滚动时可能闪 |
| 音频可视化 | 自己写 FFT + 画柱子（已做） |

## 4. 我们的产品边界（具体到功能）

| 功能 | 上限 |
|---|---|
| 常驻播放面板 | 28 列宽；封面约 26×12 格；频谱 4 行（面板高度所限） |
| 沉浸模式 | 整屏大封面（Sixel 可到 80×40 格 ≈ 640×800 px）+ 全宽频谱 |
| 列表/表格 | 与终端同宽，**每屏 40–50 行** |
| 进度条 | 字符或 Gauge；可逐秒刷新 |
| 频谱 | 当前：块字符柱（每段 1 格）；**可升级为 Braille 画布（8 倍分辨率）** |
| 歌词（未来） | 只能逐行显示，无法做卡拉 OK 式逐字高亮（除非用颜色 span 模拟） |

---

## 5. 三个"推高上限"的具体手段

| 手段 | 收益 | 成本 |
|---|---|---|
| **Braille 画布画频谱** | 纵向 8 倍分辨率，曲线更像曲线 | 半天；需要把 16 段柱状改成折线/面积图 |
| **沉浸模式封面放大** | Sixel 支持任意格子尺寸，大封面清晰度显著提升 | 已有 `ThreadProtocol`，改尺寸即可 |
| **精选 Unicode 字形** | `▁▂▃▄▅▆▇█` `░▒▓█` `⣿` `◐◑` 等，替代 emoji | 零成本，只需设计师挑一套 |

---

## 6. 一句话总结

> **Ratatui 的上限 = 终端的上限 = 字符网格。**
> 它能把"格子"用到极致（布局、边框、图像、Braille），
> 但**不可能给你 WebView 那种任意像素的控制**。
>
> 换来的东西很具体：**412 MB → 15 MB，秒级启动 → 61 ms，且与用户终端天然同色。**
