# 新界面布局方案

> 依据：产品手绘稿（2026-11-12）。
> 本文做三件事：**拆结构 → 映射控件 → 指出冲突与代价**，末尾列出需要产品拍板的问题。

---

## 1. 手绘稿的结构拆解

```
┌ NOWHERE PLAYER v0.0.1 ─────────────────────────── MilkyGreen ┐  ← 外框（带左右标题）
│ ┌ Choice ─────┐ ┌ List ───────────────────────────────────┐ │  ← 上半区：左树 + 右表
│ │ ▶ library   │ │ #  Title        Artist     Duration     │ │
│ │   queue     │ │ 1  Luv(Sic)-1   Nujabes    04:46        │ │
│ │   playlist  │ │ …                                       │ │
│ │     ├ Like  │ │                                         │ │
│ │     └ …     │ │                                         │ │
│ │   settings  │ │                                         │ │
│ └─────────────┘ └─────────────────────────────────────────┘ │
│              1 of 7                          total 4         │  ← 计数（在框线上）
│ ┌ Player ──────────────────────────────────────────────────┐ │  ← 大块抖动区
│ │ ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░ │ │
│ │                          Luv (Sic) — Nujabes  03:12/04:46│ │
│ └──────────────────────────────────────────────────────────┘ │
│ ▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬ │  ← 进度条（在 Player 框外）
│ ┌ Controller ──────────────────────────────────────────────┐ │  ← 输入区
│ │ > search Luv(Sic) --artist Nujabes                       │ │
│ └──────────────────────────────────────────────────────────┘ │
│ ▲▼ scroll   Tab switch focus   : controller   ? help   q quit │  ← 状态栏
└──────────────────────────────────────────────────────────────┘
```

**五个区域 + 一条状态栏**：Choice（树）、List（表）、Player（视觉）、Controller（输入）、Status（键位）。
**与现状对比**：现在是「左 22 列 + 中列表 + 底部播放器条 6 行 + 状态栏 1 行」，**没有 Controller 常驻、没有外框、没有面板标题**。

## 2. 高度预算（以 100×30 为例）

| 区域 | 行数 | 说明 |
|---|---:|---|
| 外框上下边 | 2 | `Block::bordered` |
| 状态栏 | 1 | |
| Controller | 3 | 边框 2 + 输入 1 |
| 进度条 | 1 | 手绘稿里在 Player 外 |
| Player | 9 | 手绘稿约 10 行 |
| **上半区剩余** | **14** | 30 − 2 − 1 − 3 − 1 − 9 = 14 |
| Choice / List 面板 | 14 | 含各自边框 2 → 内容 12 行 |

**结论：30 行窗口下，列表只有约 12 行可见。** 现在（无外框、无 controller 常驻、player 6 行）是 16 行。
**这是最直接的代价：列表可见行从 16 降到 12。**

## 3. 控件映射（Ratatui）

| 区域 | 实现 |
|---|---|
| 外框 + 左右标题 | `Block::bordered()` + `title(左)` + `title_bottom`/两段 title |
| Choice 树 | `List` + 手绘 `├ └ ▶` 前缀（**不用 `tui-tree-widget`**，避免新依赖） |
| List 表 | `Table` + `data-role` 列宽（现有实现可复用） |
| 面板底部计数 | `Block::title_bottom(Alignment::Right, "total 4")` |
| Player 视觉区 | 现有 Braille 画布扩容（**抖动区就是视觉区**，见 §5 问题 2） |
| 进度条 | `Gauge` 或自绘方括号条 |
| Controller | 输入行 + 候选弹层（弹层移到 Controller **上方**） |
| 状态栏 | `Paragraph`，键位随焦点变化 |

## 4. 与现有决定冲突的地方

| # | 冲突 | 现状 | 手绘稿 |
|---|---|---|---|
| 1 | **Controller 常驻 vs 模式化** | DES-012 规定 `:` 才出现，Normal 隐藏 | **一直可见** |
| 2 | 外框 | 无 | **有**（嵌套两层边框） |
| 3 | 面板标题 | 无 | **每个面板都有** |
| 4 | 进度条位置 | 在播放器条内 | **在 Player 框外单独一行** |
| 5 | 主题名 | 状态栏 | **外框右上角** |
| 6 | 计数 | 无（列表底部有 footer） | **"1 of 7" / "total 4" 在框线上** |

**其中 #1 是产品决策**：常驻输入框更像"终端提示符"，模式化更像 vim。两者都能做，但影响所有键位说明。

---

## 5. 需要产品确认的问题

1. **Player 里的抖动区是什么？**
   - (a) 视觉区（频谱/波形/矢量）放大；
   - (b) 封面改成的字符画（我们刚删了封面）；
   - (c) 纯粹装饰底纹。
   **这决定 Player 需要几行、以及视觉区还要不要单独存在。**

2. **进度条为什么在 Player 框外？**
   是刻意让它横跨整宽（像传送带），还是画的时候顺手放外面了？

3. **Controller 常驻吗？**
   常驻 = 任何时候都能直接输入；模式化 = `:` 才出现。**前者少一次按键，后者省 3 行。**

4. **"MilkyGreen" 是主题名还是产品名？**
   手绘稿是深色底，而我们的 MilkyGreen 是浅色（奶白底）。**这块是画稿示意，还是要求 MilkyGreen 改成深色？**

5. **左树里的 `settings` 要展开成什么？**
   主题/音源/缓存都放进去？还是保持命令控制？

---

## 6. 建议的实施顺序（确认后）

| 阶段 | 内容 | 估 |
|---|---|---|
| P1 | 外框 + 面板标题 + 高度重排（Choice/List/Player/Controller/Status） | 2 天 |
| P2 | Choice 树（含歌单子节点、计数） | 1 天 |
| P3 | Controller 常驻 + 候选弹层改位 | 1.5 天 |
| P4 | Player 视觉区扩容 + 进度条外移 | 1 天 |
| P5 | 状态栏键位随焦点 + 金标更新 | 0.5 天 |

**≈6 天。** 建议 P1 先做，做完截图给产品看比例，再决定 P2–P5 细节。

## 7. 我的初步意见

- **外框 + 面板标题值得做**：它让界面"有骨骼"，比现在的一整块更像工具。
- **Controller 常驻我倾向赞成**：对"命令驱动"的产品，提示符一直在，心理模型更清楚；代价 3 行，可以通过**去掉 Player 的外框**省回来。
- **计数器（1 of 7 / total 4）有价值**：它回答了"我在哪、有多少"。
- **但列表从 16 行降到 12 行是真代价**，需要权衡：可以把 Player 从 9 行压到 6–7 行。
