# 终端宿主替代方案：Alacritty 评估

> 问题：能否用 Alacritty 替代 Windows Terminal 作为 `np-tui` 的宿主？

---

## 1. 结论先行

**技术上可行，但不划算。**

| 维度 | 结论 |
|---|---|
| 能不能用 | ✅ 能（Windows 有构建，走 ConPTY） |
| **封面质量** | ❌ **降级**：Alacritty 不支持 Sixel/Kitty 图形 → 回退半块字符 |
| 配置注入 | 🟡 无 fragment 机制，但可 `--config-file` 指定自己的配置（**这点其实比 WT 更干净**） |
| 工程成本 | 中等（启动器 + 配置生成 + 安装检测 + 回退） |
| 更好的替代 | **WezTerm**（Sixel/Kitty/iTerm2 全支持） |

---

## 2. 关键差异：图形协议

我们的封面用 `ratatui-image`，它会**自动探测**终端协议并选择：

| 终端 | Sixel | Kitty | iTerm2 | 实际效果 |
|---|---|---|---|---|
| **Windows Terminal** | ✅ | ❌ | ❌ | Sixel 真图（我们已实测） |
| **Alacritty** | ❌ | ❌ | ❌ | **回退半块字符**（`▀▄` 双色） |
| **WezTerm** | ✅ | ✅ | ✅ | 真图，协议最全 |
| Kitty / Ghostty | ❌/✅ | ✅ | ❌ | Kitty 图形 |

来源：[Terminal Compatibility Matrix](https://github.com/dicklesworthstone/frankentui/blob/0f5bd2444753d84ab9f5e2ac37033fcc8568d218/docs/reference/terminal-compatibility.md)（第三方矩阵，Alacritty 行：Sixel = No）。
**注意**：该矩阵对 Windows Terminal 的 DECSET 2026 标为 No，但我们自己实测**有效**——所以此类矩阵只能作参考，**必须自己验证**。

### 2.1 回退半块的代价

半块字符的分辨率 = **2 像素/格**（一格里上下两个颜色）。当前面板封面约 26×8 格：

```
Sixel   ≈ 208×160 像素
半块    ≈ 26×16 个色块，模糊到只能看出主色调
```

**对"播放器"这个产品，封面是核心识别物**，退化到认不出专辑就不值得。

---

## 3. 其他差异

| 项 | Windows Terminal | Alacritty |
|---|---|---|
| 标签页 | ✅ | ❌（设计上就不做） |
| 配置注入 | fragment 目录（官方机制） | `--config-file <path>`（**更直接**） |
| 背景图/亚克力 | ✅ | ❌（只有纯色 + 透明度） |
| 滚动条 | 可隐藏 | 无内置滚动条 |
| 中文字体 | 由 profile 指定 | 由 config 指定，回退依赖系统 |
| 输入法 | 成熟 | Windows 下一般，需实测 |
| 安装 | 系统自带（Win11） | **需用户自己装** |

**"需用户自己装"是硬伤**：我们现在的自举逻辑是 `wt.exe` 一定有；换成 Alacritty 就要处理"用户没装"的分支（要么随包分发，要么降级回 WT）。

---

## 4. 如果要换，应该换 WezTerm 而不是 Alacritty

| 需求 | WT | Alacritty | **WezTerm** |
|---|---|---|---|
| Sixel 封面 | ✅ | ❌ | ✅ |
| 跨平台一致 | ❌（Windows only） | ✅ | ✅ |
| 配置可注入 | ✅ fragment | ✅ `--config-file` | ✅ `--config-file` |
| 需另装 | 否 | 是 | 是 |
| 体积 | 系统自带 | 小 | 中 |

**WezTerm 是唯一"图形协议 + 跨平台 + 配置可控"三项齐全的选项。**

---

## 5. 换宿主的工程清单（无论选哪个）

| # | 工作 | 估 |
|---|---|---|
| 1 | 启动器改为可配置宿主（WT / WezTerm / Alacritty） | 1 天 |
| 2 | 生成对应格式配置（fragment JSON / TOML / Lua） | 2 天 |
| 3 | 安装检测与回退（找不到就回落 WT 或 conhost） | 1 天 |
| 4 | 图形协议能力探测 + UI 提示（"当前终端不支持图片封面"） | 1 天 |

**≈5 天**，且不解决任何当前痛点——**现在 WT 的 Sixel 是工作的**。

---

## 6. 什么时候才值得换

| 触发条件 | 是否成立 |
|---|---|
| WT 的 Sixel 在我们的场景下坏掉 | ❌ 未发生，实测正常 |
| 需要 macOS/Linux 一致的外观 | 🟡 成立，但那是**发布阶段**的事 |
| 用户抱怨 WT 不可用 | ❌ 暂无 |
| 想要无边框极简窗口 | 🟡 Alacritty/WezTerm 都不能给"无标题栏"，`--focus` 已经够用 |

**建议：暂不更换。** 等跨平台发布时再评估 WezTerm（它是那时候唯一合理的选择）。

---

## 7. 立即可做的一件小事

不管是哪个终端，**都应该加一条"图形能力探测与降级提示"**：

- 启动时 `ratatui-image` 的 `Picker` 已经告诉我们协议类型；
- 若回退到 `halfblock`，状态栏提示一行「当前终端不支持图片封面，已降级为字符」；
- 这样用户换终端时**知道发生了什么**，而不是觉得封面坏了。

**这条无论换不换宿主都有价值，成本半天。**
