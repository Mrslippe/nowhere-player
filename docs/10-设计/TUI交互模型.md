# TUI 交互模型

> 产品决定（2026-11-12）：**不再"一切皆命令"**。参考社区同类 TUI 的做法重新设计交互。
> 命令系统**保留**，但降级为"高级模式"，不再是唯一入口。

---

## 1. 社区参照

| 项目 | 学它的什么 |
|---|---|
| **lazygit** | 多面板 + **底部上下文键位条**（随焦点变） |
| **k9s** | 列表为主 + `/` 就地过滤 + `:` 命令 |
| **ncmpcpp** | 音乐播放器的**窗格模型**（库/播放列表/浏览器多窗口切换） |
| **spotify_player** | 页面式布局 + `keymap.toml` 可配键位 + `?` 帮助 |
| **ranger / yazi** | 三栏（父/当前/预览）的视觉结构 |

**共同点**：**焦点 + 上下文键位 + 就地过滤**，而不是"输入命令再执行"。

## 2. 新布局

```
┌ Nowhere Player ──────────────────────────────── 本地 18 首 ┐
│ ▸ 媒体库        │ 1  晴天          周杰伦     04:29        │
│   搜索结果      │ 2  稻香          周杰伦     03:43        │
│   队列          │ 3  最长的电影    周杰伦     04:31        │
│   歌单          │ …                                       │
│     · 安可      │                                         │
│     · 夜跑      │                                         │
├─────────────────┴───────────────────────────────────────┤
│ [封面]  晴天 · Jay Chou                                  │
│ ▮▮▮▮▮▮▮▯▯▯▯▯   00:10 / 04:29                          │
│ ◀◀  ▶  ▶▶        ⣀⣤⣶⣿⣶⣤⣀  (频谱/波形/矢量)          │
├─────────────────────────────────────────────────────────┤
│ / 搜索 · : 命令 · ? 帮助 · Tab 切焦点 · Space 播放       │
└─────────────────────────────────────────────────────────┘
```

### 2.1 三个区域

| 区域 | 内容 | 宽度 |
|---|---|---|
| **左栏** | 视图/歌单列表（可折叠） | 20–24 列，可 `Ctrl+B` 收起 |
| **中栏** | 当前视图的条目列表（唯一可获得行焦点的地方） | 剩余宽度 |
| **下部** | 播放器条（标题 + 进度 + 视觉区） | 固定 13 行 |

> 相比现在"右栏竖条"，**播放器改成横向条**——因为封面横着放更大，且不挤压列表宽度。

### 2.2 焦点

- `Tab` / `Shift+Tab` 在 **左栏 ↔ 中栏** 间切换（播放器条不可聚焦）。
- 当前焦点栏**边框高亮**，非焦点栏边框用 `faint`。
- 焦点在左栏时，`j/k` 切视图，`Enter` 进入该视图。

## 3. 模式

| 模式 | 进入 | 行为 |
|---|---|---|
| **Normal** | 默认 | vim 风格浏览；单键命令 |
| **Filter** | `/` | 就地过滤当前列表；`Esc` 退出过滤并保留结果 |
| **Command** | `:` | 打开命令输入行——**现有命令系统原样可用** |
| **Help** | `?` | 覆盖层：图示 + 全部键位（which-key 风格） |

**设计原则**：**常用操作单键，复杂操作命令**。
"播放选中"是单键，`play 3` 仍然可用；"导出主题"只有命令，不值得给键。

## 4. 键位表（Normal 模式）

> 本节保留最初的设计目标；**当前实现以 §11 为准**（焦点用 `←→`，`/` 是命令浮层，`?` 尚未实现）。

### 4.1 全局

| 键 | 动作 |
|---|---|
| `Space` | 播放 / 暂停 |
| `.` / `,` | 下一首 / 上一首（PlayList 根 `n` 仍为新建歌单） |
| `+` / `-` | 音量 ±5% |
| `Tab` | 切换焦点 |
| `/` | 过滤 |
| `:` | 命令模式 |
| `?` | 帮助 |
| `q` | 退出（播放中二次确认） |

### 4.2 中栏（列表）

| 键 | 动作 |
|---|---|
| `j`/`k`、`↑`/`↓` | 移动 |
| `gg` / `G` | 首 / 尾 |
| `Enter` | **播放选中项** |
| `a` | 加入队列 |
| `A` | 加入歌单（弹选择层） |
| `d` | 从当前歌单移除 |
| `f` | 循环切换视觉模式（频谱/柱状/波形/镜像/矢量/环形/星野） |
| `Ctrl+F` | 沉浸模式 |

### 4.3 左栏（视图）

| 键 | 动作 |
|---|---|
| `j`/`k` | 切视图 |
| `Enter` | 进入并聚焦中栏 |
| `D` | 删除当前歌单（二次确认） |

## 5. 与命令系统的关系

**命令不消失，只是降级**：

| 场景 | 用哪个 |
|---|---|
| 播放第 3 首 | `Enter`（选中）或 `play 3`（命令） |
| 搜索在线 | `/` 过滤本地；**在线搜索仍需命令** `search 晴天`（或后续加 `/` 的前缀约定） |
| 导出主题、切缓存、改设置 | 命令 |
| 脚本化 / 可测试 | **全部命令仍然可调**（`np-app` 的 `Executor` 未变） |

**新增一个约定**：`/` 输入以 `!` 开头时走命令（如 `!search 晴天`），一个键搞定"过滤或搜索"。

## 6. 美学要点（承接 DES-010/011）

- 焦点栏边框 `accent`，非焦点 `faint`——**用边框表达焦点，不用背景色**（终端背景不可靠）。
- 选中行**反白**（`Reverse`），只给"当前行"，不给整列表。
- 播放器条上方一条 `─` 分隔，不用整个方块边框（省空间）。
- 视觉区高度随窗口（72×24 下 10 行），七种模式共用；整个内容区最大 144×48，超出部分居中留背景。
- **键位条随焦点变化**（lazygit 的核心做法）。

## 9. 上下文状态栏（2026-11-16 实现）

状态栏不再显示固定键位，也不显示页面标题，而是按当前焦点和页面显示：

```text
状态消息 / 当前页面特有功能 / 导航 / 全局键
```

优先级：

```text
确认状态
→ 页面特有功能
→ 播放/打开
→ 导航
→ 全局命令
```

确认统一为：

```text
第一次键进入待确认
Enter 执行
Esc 取消
```

歌单根：

```text
n 新建 · d 删除 · Enter 打开 · ↑↓ 选择 · Esc 返回
```

歌单子项：

```text
a 添加 · r 移除 · Enter 播放 · ↑↓ 选择 · Esc 返回
```

Queue：

```text
r 移除 · Space 暂停 · Enter 播放 · n/p 切歌 · Esc 返回
```

创建歌单输入框为 38×3，位于 List 内容区居中；删除歌单需 Enter 二次确认。

## 10. Controller 按需浮层（2026-11-16）

Controller 不再常驻：

```text
默认：0 行
按 /：底部浮层 3 行
Esc：关闭并恢复原焦点
```

默认布局把原来的 3 行给 Player：

```text
顶部 9 / Player 13 / Controller 0
```

状态栏左右各留 1 格；页面提示优先显示特有功能。命令、补全、历史仍保留在浮层中。

Playback：

```text
[ 后退 5s
] 前进 5s
m 循环播放模式（写入 settings.json）
```

Settings 页增加分类：播放、界面、启动、音源、其他；包含 volume、mode、theme.id、ui.splash、tui.focusMode、startup.enabled、source.*、ui.visual。

## 11. 2026-11-16 交互收口

本节的优先级高于 §4 的历史键位表。

### 11.1 状态栏

- 只显示「当前页 2～4 个动作 + `/ 命令`」；不再追加 `[ ] ±5s`、`m 模式`、`Shift+Enter`。
- 状态消息用 accent 粗体显示；待确认状态用 warn 粗体。
- 状态栏文字结束处留 1 格空白，再接外框线；不再固定清除右侧倒数第二格。
- 长提示会被截断，不再留下没有内容的 ` · ` 分隔符。

### 11.2 Player 下边框

- 左侧常驻五个播放控制钮：`◀◀` 上一首、`<<` 后退 5s、播放/暂停、`>>` 前进 5s、`▶▶` 下一首。
- 左右两端各留 1 格空白；常规状态按钮之间间隔 1 格，只显示按钮不显示键名。
- 按住 Ctrl 时在按钮后显示键名：`,`、`[`、`Space`、`]`、`.`；组间间隔 2 格，松开即恢复。
- 不可用的上一首/下一首/后退/前进按钮用 faint + DIM 灰色；播放/暂停用颜色区分（暂停态播放键用 fg，播放态暂停键用 accent）。
- 按 `,` / `[` / `Space` / `]` / `.` 时，对应按钮反白 180ms 作为操作反馈。
- 右侧继续显示播放模式；顺序播放使用 `⇉`（两行右箭头），不再使用 `·`。
- 按钮不是鼠标控件，只作为键盘动作的视觉提示。

### 11.3 全局搜索

- 任意非输入状态按 `s` 打开 Search，聚焦输入框；已有结果会清空并回到输入态。
- Search 内按 `Tab` 循环：全部平台 → 网易云 → B站 → 全部平台。
- 换平台时若已有查询，立即用新平台重跑；旧请求由 `search_id` 丢弃。
- 当前平台显示在 **Key Words 输入框下边框右侧**，使用源短名 `all` / `netease` / `bilibili`；斜体 + faint，文字前后各留 1 格，再接右下角。
- Search 的 `total N` 保持在 List 下边框右侧，不再被平台标签占用。

### 11.4 Settings 分类树与可编辑（T-0128）

- Settings 改为两列「设置 / 值」的分类树：分类根显示 `▾ 播放 (2)` / `▸ 播放 (2)`，子字段缩进两格，
  例如 `  音量  100%`；分类根固定按 播放、界面、启动、音源、直播、其他 排列。
- 默认全部展开；折叠状态只保留在本次会话，不写 `settings.json`。
- `↑↓` 在可见行间移动；分类根 `Enter` 折叠/展开，状态栏提示「播放 已折叠 / 已展开」，
  不进入编辑态、不写设置。未知配置键收进「其他」根，只读；没有未知项时不显示该根。
- 子字段沿用可编辑行为：`Enter` 切换 Bool / 进入编辑，编辑态 `←→` 调整、`Enter` 提交、`Esc` 取消；
  `r` 重置当前字段。分类行上的调整/重置只提示，不 panic。
- 音量 5% 一步；播放模式按 `⇉ → ↻ → ↺ → ⇄` 循环；主题按 `theme.list()` 循环。
- 修改立即写 `settings.json` 并刷新树；刷新时按当前字段 key 找回选中行，折叠后行数变化也不会跳行。
- 界面分类含「音效主题」：`switch`（默认，沉闷扳动）→ `typewriter` → `soft` 循环，切换后立即试听并写回 `ui.soundTheme`；`ui.sound` 关闭时所有主题静音。
- 分类根用 accent + BOLD；被选中时仍用 selection 反白，并保留 BOLD。表头、总数、滚动沿用通用列表。

### 11.5 Controller 输入

- 输入不满时保持原样；输入到达内容区右边界且光标继续右移时，文本窗口整体左移，光标始终可见。
- 光标列按显示宽度计算，CJK 占两格。

### 11.6 焦点

- `←→` 在 Browse / List 间切换；`Esc` 从 List 回 Browse。
- `Tab` 只在 Search 的平台切换和 Controller 补全中使用，不再承担焦点切换。

### 11.7 专注模式（T-0125）

- 启动时读取 `tui.focusMode`（缺省关）；非 Live 页按 `Ctrl+F` 切换。
- 开启后只保留外框、占满 `layout_inner` 内区的 Player、Controller / 登录浮层和状态栏；不绘制 Browse/List。
- 状态栏第一项固定为 `Ctrl+F 退出专注`；窗口小于 50 列或 12 行时自动回退普通三区布局，提示仍然保留，不 panic。
- 切换写回 `tui.focusMode`，下次启动保持；Live 页解析 `Ctrl+F` 但忽略，并提示「直播中不可切换专注模式」。
- 设置页切换「专注模式」同样立即生效，不再提示“下次启动生效”；「动效」仍保留“下次启动生效”。
- 开机自启写 HKCU Run，不需要管理员；启动时按当前 exe 路径自愈，失败写入状态栏。

### 11.8 Player 视觉样式（T-0126 / T-0133 / T-0134 / T-0138 / T-0139）

- `f` 按固定顺序循环：频谱 → 柱状 → 波形 → 镜像 → 矢量 → 环形 → 星野 → 频谱；
  状态栏显示「视觉：柱状」等，并写回 `ui.visual`。
- `Ctrl+F` 仍只切换专注模式；`Ctrl+Shift+F` 不触发任何视觉动作，普通 `f` 也不会被
  Ctrl 表抢占。
- 启动时先读 `ui.visual`（缺省 `spectrum`），再由 `NP_TUI_VISUAL` 覆盖；环境变量
  支持全部 7 个 id，并兼容旧 `wave` / `vector` 别名。
- 设置页末尾追加「视觉样式」，`←→` 循环 7 种；未持久化时回退 App 当前模式，
  已持久化后优先显示 `ui.visual`。
- 新增样式只通过 `PaletteToken` 取色：柱状 / 镜像 / 环形 / 星野在 72×24 静音时
  给 faint 基线或星点，不黑屏；波形与矢量静音时降为 faint 线，有信号时行为不变。
- 柱状固定 2 格柱宽 + 1 格间隔，窗口变宽时增加柱数；16 段频谱线性插值到当前柱数。
- 默认频谱也改为 2 格柱 + 1 格间隔（66 列约 22 根），柱间留空，不再连续实心。
- 频谱分析：110Hz 一阶高通 + 50Hz 带起点、10kHz 高切；段内平均能量；最大输出 0.85 headroom；
  相对峰值低于 4% 归零；`next_spectrum` 每次最多回落 0.05，形成 gravity。
- 波形/镜像按峰值自动增益（目标 0.85，最高 6×）；`display_spectrum` 只做 `powf(0.9)` 轻微压缩。
- 音频 tap 在软件音量之前写入，因此调音量不再改变频谱/波形/矢量幅度；暂停 fade 仍作用于 tap。
- 矢量旋转 45° 并加入短延迟相位轴，单声道也能形成回环；环形 5 圈、32 段并整体旋转；
  星野 96 颗、低频驱动速度和拖尾，相位取 `status::now_millis()`，静音时静止。

### 11.9 Browse 直播页与历史（T-0127 / T-0131）

- Browse 树在「搜索」之后、「队列」之前新增「直播」节点；`NP_TUI_VIEW=live` 直接定位。
  页面初始态是居中 38×3 `Room ID` 输入框，下方最多 3 条历史（72×24 内区 7 行装得下）。
- 节奏与搜索页一致：Browse 选中「直播」后 `Enter` / `→` 只进 List，状态栏提示
  `Enter 输入 · ↑↓ 选择 · Esc 返回`，输入框边框用 `Border`、标题用 `Muted`，不显示光标。
- List 再按 `Enter` 才聚焦输入框：边框转 `Focus`、标题转 `Accent`、显示光标，状态栏提示
  `输入房间号 · Enter 开始 · ↑↓ 历史 · Delete 删除 · Esc 返回`。
- 输入态只接受数字（最多 12 位）：`Backspace` / `←→` 编辑，`↑↓` 选中历史并把房间号填进输入框，
  `Enter` 优先用输入框、空时用选中历史；成功后清空输入并退出输入态，失败保持输入态并可重试。
  `Delete` 删除选中历史。
- 输入态 `Esc` 只退出输入态（焦点仍留 List，提示「已退出直播输入」）；再按 `Esc` 才回 Browse。
  `Ctrl+*` 全部放行给全局键位（`Ctrl+F` 仍切专注模式）；其它普通字符吞掉，避免 `q` / `s` / `f`
  在输入房间号时误触。未激活时数字 / `Enter` / `Esc` 都不由本页接管，走全局键位。
- 历史格式 `主播名 · 房间号`；主播名未到时显示 `房间 房间号`，meta 到达后自动补名。
- 历史存 `<config>/live_history.json`：最多 20 条、按房间号去重、最近使用在前；写入先落
  `.tmp` 再 rename；坏文件忽略并在状态栏提示。`/live <房间号>` 命令与页面 `Enter` 都记录历史。
- 房间无效时保留历史并提示，可直接重试；两条入口都走同一个 `player.start_live`。

## 12. 输入映射与控制器（2026-11-17）

正常模式的输入不再直接写在 `event_loop` 的 `KeyCode` 分支里。

```text
KeyEvent + InputContext
        ↓  keymap::resolve
      Action
        ↓  controller::execute
   App / PlayerApi / LibraryApi / Settings
        ↓
   App 状态（status / transport_feedback / 数据变化）
```

- `keymap.rs`：唯一键位表；`,` / `.`（含全角 `，` / `。`）/ `p` / `n` 等只在这里绑定。
  - `InputContext` 只带聚焦区、当前视图等判断所需状态。
  - 不支持业务调用、不解析命令字符串。
- `controller.rs`：只接收 `Action`，执行播放、歌单、设置、搜索平台切换等。
- `player_bar.rs`：播放控制的键名从 `keymap::label(Action)` 读取，不再手写。
- `render.rs`：状态栏提示的 `s`、`/`、`n`、`d`、`a`、`r`、`Enter`、`Esc`、`Tab` 也从同一张表取。
- 专注模式属于 UI 状态（`App.focus_mode`），不是 Browse 视图；`Ctrl+F` 由 `keymap` 的 Ctrl 表解析，controller 写回 `tui.focusMode`，render 只负责布局切换。
- 视觉样式属于 UI 状态（`App.visual_mode`）；普通 `f` 由 `keymap` 解析为 `CycleVisual`，controller 写回 `ui.visual`，`visuals.rs` 只负责按 `PaletteToken` 绘制。
- `transport.rs`：播放控制按钮的可用性（上一首/下一首/后退/前进）只计算一次，灰显和执行守卫共用。
- 文本输入（Controller、Search 输入、New Playlist）仍由 `event_loop` 的输入模式处理，不进入业务分发。
- `np-app` 命令层保持独立：UI 使用类型化 `Action`，不把按键拼成 `"next"` / `"play"` 命令再解析。

新增键位时只改 `keymap.rs`；展示层的键名会自动跟随。

## 13. 直播音频（2026-11-17，B1）

- TUI-only 入口：`/live <room>` / `live <room>`，由 `np-tui` 在 `np-core` 解析前拦截；不进入命令注册表。
  Browse「直播」页（T-0127）是另一条入口，两者共用 `player.start_live` 与同一份历史。
- 直播独占：开始直播停止当前播放，但**不清空队列**；`next/prev/seek` 禁用，`Esc` 停止，直播结束不自动下一首。
- Player 时间区显示 `LIVE`；暂停时 `LIVE PAUSED <ms>ms`，继续缓存；断流时 `LIVE RECONNECTING n/6`；`r`/F5 本地裁到最新 300ms；直播 ring 150ms，普通文件仍 300ms。
- B1 不做断线重连、Live 页、弹幕；这些留 B2/B3。
