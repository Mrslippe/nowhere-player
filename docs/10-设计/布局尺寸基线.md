# 布局尺寸基线（72×24）

> 来源：2026-11-14 产品验收对话中的手绘标准。
> 本文件是布局尺寸的唯一基线；实现与此不一致时，以本文件为准。

```text
总览：
纵向 24 = 上框 1 + 顶部 9 + Player 13 + Controller 0 + 下框 1
横向 72 = 左框 1 + 左间距 1 + Browse 16 + 分隔线 1 + List 51 + 右间距 1 + 右框 1

详细：
1. Browse：
纵向 9 = 上框 1 + 条目区 7 + 下框 1
横向 16 = 左框 1 + 游标列 1 + 间距 1 + 条目内容 13

2. List：
纵向 9 = 上框 1 + 条目区 7 + 下框 1
横向 51 = 左间距 1 + 列表内容 48 + 右间距 1 + 右框 1
注：列表内容 48 内部列间间隔 1；标题栏为弹性栏，先排其他列，剩余宽度给标题；滚动条内嵌在右框线 1 格内，不占列表内容 48。

3. Player：
纵向 13 = 上框 1 + 频谱或空态 9 + 歌曲信息 1 + 进度 1 + 下框 1
横向 68 = 左空白 1 + 内容 66 + 右空白 1
注：Player 只有上框线和下框线，内容区 11 行不画左右竖线；左右各 1 格为空白内边距。音量条位于 Player 上框线内；Vol + 20 格 + 末尾 1 格空白；不占 Player 内容行。

4. Controller（按需浮层，不常驻）：
默认占 0 行；按 / 后在底部覆盖 3 行（上框 1 + 输入行 1 + 下框 1）。
横向 68 = 左框 1 + 提示符 1 + 间距 1 + 输入内容 64 + 右框 1
```

## 修复前偏差审计（2026-11-14）

以当前 `layout_72x24` 金标和 `crates/np-tui/src/{layout,render,player_bar}.rs` 为准：

| 项目 | 基线 | 实际 | 结果 |
|---|---:|---:|---|
| 总高度 | 24 | 24 | ✅ |
| 上框 / 顶部 / Player / Controller / 下框 | 1 / 9 / 10 / 3 / 1 | 1 / 9 / 10 / 3 / 1 | ✅ |
| 顶部条目区 | 7 | 7 | ✅ |
| List 条目区 | 7 | 7 | ✅ |
| Player 内容 | 8（6+1+1） | 8（6+1+1） | ✅ |
| Controller 输入行 | 1 | 1 | ✅ |
| 横向工作区 | 68 | 70 | ❌ 多 2 |
| 左/右间距 | 左 1 / 右 1 | 0 / 0 | ❌ 缺失 |
| Browse 框宽 | 16 | 20 | ❌ 多 4 |
| Browse 内容宽（旧基线 12） | 12 | 18 | ❌ 多 6 |
| List 框宽 | 51 | 51 | ✅ |
| List 内容宽 | 50（1+48+1） | 49（1+46+2） | ❌ 少 1 |
| List 表格宽 | 48 | 46 | ❌ 少 2 |
| List 默认 Title / Artist | 24 / 9 | 22 / 9 | ❌ 标题少 2 |
| List 滚动条 | 嵌右框线 | 嵌右框线 | ✅（位置随框右移 1） |
| Player 框宽 | 68 | 70 | ❌ 多 2 |
| Player 内容宽 | 66 | 68 | ❌ 多 2 |
| Player 左右边框 | 有 | 无（仅上下边） | ❌ |
| Controller 框宽 | 68 | 70 | ❌ 多 2 |
| Controller 内容宽 | 66 | 68 | ❌ 多 2 |
| 音量条 | Vol + 20 格 + 末尾 1 格 | Vol + 20 格 + 末尾 1 格 | ✅（在 70 宽顶边上） |

结论：

1. 纵向分区已经准确：`1 + 9 + 10 + 3 + 1 = 24`。
2. 横向整体缺少左右各 1 格间距，导致工作区变成 70 而不是 68。
3. Browse 宽度和内容宽度都被拉大：20/18，当时基线是 16/12（现已调整为条目内容 13）。
4. List 框宽虽然仍是 51，但内部被压成 `1 + 46 + 2`，表格少 2 格，Title 只剩 22。
5. Player / Controller 都被拉宽到 70，Player 还缺少左右边框。
6. 音量条内部结构已经符合新方案，但所在 Player 顶边宽度是 70，而不是 68。

下一轮应按以上 2～6 项改代码；本文件只记录基线，不把现有实现当作正确结果。

## List 分状态基线（2026-11-15）

```text
公共：
List 纵向 9 = 上框 1 + 条目区 7 + 下框 1
List 横向 51 = 左间距 1 + 表格区 48 + 右间距 1 + 右框线/滚动条 1
列间隔 = 1
滚动条在右框线，不占表格区 48
total N 在底边右对齐
```

### Playlist 根

```text
标题：PlayList
列宽：序号 4 / 名称 24 / 创建时间 12 / 数量 5
列间隔：1
表格区：48
创建时间：YYYY.MM.DD
可见：表头 1 + 数据最多 6，剩余滚动
```

### 歌单 / 媒体库 / 队列

```text
标题：歌单名 / 媒体库 / 队列
列宽：序号 4 / Title 24 / Artist 9 / Duration 8
列间隔：1
表格区：48
时长：MM:SS
可见：表头 1 + 数据最多 6，剩余滚动
```

### Search

```text
标题：Search
空态：48×7 内居中 Key Words 框，框 38×3，内宽 36
Key Words 可直接输入：关键词 [-artist 作者] [-source 平台]
两个参数都 optional；也接受 -a/-s 和 --artist/--source

Search 输入状态机：
  Browse 选中 Search
  → 右方向键切到 List
  → Enter 激活 Key Words（输入框高亮，接管左右方向键）
  → Esc 退出输入（取消方向键接管，焦点仍在 List）
  → Enter 执行搜索
  结果/失败态按 c 回到空态
搜索中：48×7 内居中 ◰ searching...，帧序列 ◰ ◳ ◲ ◱
失败态：48×7 内居中 ✘ no results
结果态：列宽 序号 4 / Title 24 / Artist 9 / Platform 8
total：空/搜索中/失败为 0，结果态为实际结果数
```

## UI 细节补充（2026-11-15）

```text
List 英文标题：
  Playlist 根：PlayList
  歌单子项：歌单名
  媒体库：Library
  队列：Queue
  Search：Search
  设置：Settings

Queue 当前项：
  游标 ▶ 放在 List 最左侧间距列
  # 列只显示序号
  Queue view 行时长来自 library.tracks_by_paths；缺失显示 —

Player 信息块：
  显示 标题 — 作者
  标题过长时折叠标题，保留作者
```

```text
a 添加到歌单：
  歌曲列表（Library / Queue / Search result / Playlist）按 a
  → 记住来源页，跳转 Playlist 根
  → 选择歌单后按 a 确认添加
  → 自动跳转对应歌单子项并刷新
  → Esc 取消并回到来源页

严格去重：
  队列按 TrackKey 去重
  歌单添加按 local 路径 / remote source+id 拒绝重复
  Search 结果的 duration 通过 durations 元数据进入队列/歌单，不解析 Platform 列
```

## 交互补充（2026-11-15 晚间）

```text
Search Key Words 输入框：
  左右各留 1 格；光标定位随内容内缩 1 格

r 两击移除：
  Queue：从队列移除
  Playlist：从歌单移除
  Search / Library：从播放队列移除（按 TrackRef 或 标题+艺人匹配）
```

## 状态栏与歌单操作（2026-11-16）

```text
状态栏：
  不显示 Browse/PlayList 等上下文标题
  最左侧优先显示状态消息，其次显示快捷键
  页面特有功能优先：PlayList 根先 n/d，歌单子项先 a/r，Queue 先 r

歌单创建：
  PlayList 根按 n
  在 List 内容区居中显示 38×3 的 New Playlist 输入框
  左右内边距各 1 格
  Enter 创建，Esc 取消
  创建成功后跳转新歌单子项

歌单删除：
  PlayList 根选中歌单按 d
  Enter 确认删除，Esc 取消
  删除后刷新 PlayList 根

确认模型：
  a 添加 → Enter 确认 → Esc 取消
  r 移除 → Enter 确认 → Esc 取消
  d 删除歌单 → Enter 确认 → Esc 取消
  q 退出 → Enter 确认 → Esc 取消
  不再使用同一个键按两次确认
```

## 输入/播放快捷键补充（2026-11-16）

```text
Key Words / New Playlist：
  输入滚动按显示宽度计算，不按字符数；CJK 双宽字符不会把光标顶出输入框
  New Playlist 首次输入不再显示占位文本，避免 IME 预编辑重叠

播放：
  [ 后退 5 秒
  ] 前进 5 秒
  m 循环切换播放模式
```

## 2026-11-16 下边框补充

```text
Player 下边框：
  左侧：area.x+1 留空，从 area.x+2 起放五个按钮
  常规：◀◀ << ▶/❚❚ >> ▶▶（组间 1 格，首尾各 1 格）
  Ctrl：◀◀ ,  << [  ▶ Space  >> ]  ▶▶ .（组间 2 格，键名在按钮后）
  不可用按钮 gray + DIM；按下按钮反白 180ms
  右侧：Mode ⇉ / Mode ↻ / Mode ↺ / Mode ⇄
  中间用 ━ 填充，不与按钮标签重叠

Key Words 输入框（38×3）下边框：
  右侧：当前平台源短名（all / netease / bilibili）
  前 1 格、后 1 格空白；斜体 + faint
List 下边框（Search 状态）：
  右侧仍为 total N，不再放平台标签

状态栏：
  左侧留 1 格空白
  文本结束后 1 格空白，再接外框线
  不固定清除右侧倒数第二格
```
