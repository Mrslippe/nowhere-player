# Ratatui 视觉效果参考

> 来源：[ratatui.rs 官网](https://ratatui.rs/) 的 Showcase / Third Party Widgets / Ecosystem。
> 只记录**能用在音乐播放器上**的手法；纯仪表盘类的不列。

---

## 1. 生态里有什么

### 1.1 第三方控件（视觉相关）

| 控件 | 效果 | 我们能用来做什么 |
|---|---|---|
| `ratatui-image` | Sixel/Kitty/iTerm2 图像 | **已用**：专辑封面 |
| **`tui-big-text`** | 用 font8x8 渲染**大像素字** | **沉浸模式的大标题 / 大时间** |
| **`throbber-widgets-tui`** | 多种 spinner（Braille/方块/箭头） | 搜索中的加载指示 |
| `ratatui-textarea` | 多行编辑器 | 暂不需要（我们是单行命令） |
| `tui-piechart` / `tui-nodes` / `tui-tree-widget` | 饼图 / 节点 / 树 | 不需要 |
| `tui-scrollview` | 可滚动视口 | 长列表可选 |

### 1.2 生态项目

| 项目 | 价值 |
|---|---|
| **`tachyonfx`** | **特效与动画库**：淡入、扫过、溶解、颜色过渡，可组合叠加。**这是"TUI 也能有动效"的答案** |
| `ratcn` | 组件库集合 |
| `ratzilla` | Ratatui → 浏览器（我们用不到，已否决） |
| `mousefood` | 嵌入式 |
| `uefi` | UEFI 环境 |

### 1.3 内置示例里可直接偷的

| 示例 | 手法 |
|---|---|
| **`shadow`** | 用块字符在控件右下画**假阴影**（`░`） |
| **`collapsed-borders`** | 相邻面板共享边框，不重复画线 |
| **`canvas`** | **Braille 画布**（2×4 点/格） |
| `sparkline` | 单行折线（`▁▂▃▄▅▆▇█`） |
| `scrollbar` | 自带滚动条控件 |

## 2. 我们该用哪几个（按收益排序）

| # | 手法 | 收益 | 依赖 |
|---|---|---|---|
| **1** | **Braille 画布画频谱** | 纵向 8 倍分辨率，曲线像曲线 | 无（内置 `Canvas` + `Marker::Braille`） |
| **2** | **沉浸模式大封面** | Sixel 支持任意尺寸，清晰度显著提升 | 无 |
| **3** | **`tui-big-text` 风格的大字** | 沉浸模式显示大号时间/曲名 | 可用 crate 或手写 font8x8 子集 |
| 4 | **spinner 加载指示** | 搜索时有"在动"的反馈 | 手写 4–6 帧 |
| 5 | 假阴影 | 弹层浮起来 | 手写 |
| 6 | **tachyonfx 过渡** | 面板展开/切歌淡入 | **需 ADR**（新依赖） |

### 2.1 为什么 Braille 是第一位

一个单元格里 Braille 有 **2×4 = 8 个点**。同样是 4 行的频谱区：

```
块字符（现在）：      Braille：
▁▃▅▇▅▃▁              ⣀⣤⣶⣿⣶⣤⣀   ← 8 倍纵向精度
▁▃▅▇▅▃▁              ⣀⣤⣶⣿⣶⣤⣀
```

**同样的空间，能画出真正的波形。**

### 2.2 tachyonfx 要不要引

| 支持 | 反对 |
|---|---|
| 让"切歌""面板展开"有过渡，观感提升明显 | 新依赖（红线要 ADR） |
| 社区验证、官方生态页推荐 | TUI 动效收益远小于 GUI；且我们已把"无动效"当默认 |

**建议：先不引。** 等 TUI 功能收尾、产品稳定后，作为"锦上添花"再评估。

---

## 3. 不可迁移的手法

Showcase 里大量项目是**仪表盘/监控**类（btop 风格、图表密集型），它们的美学依赖：

- 常驻刷新的大面积色块
- 多面板同时更新
- 高密度数字

**我们是单任务播放器**，抄这些会显得吵。**只取"精度"和"层次"，不取"密度"。**

---

## 4. 结论

- **立刻做**：Braille 频谱、沉浸大封面、字形精选（`▁▂▃▄▅▆▇█` `░▒▓█` `◐◑`）。
- **候选**：`tui-big-text` 风格大字、spinner。
- **暂缓**：tachyonfx（需 ADR，收益中等）。

## 5. scope-tui：最直接的参考实现

来源：[docs.rs/crate/scope-tui](https://docs.rs/crate/scope-tui/0.3.2)、[git.alemi.dev](https://git.alemi.dev/scope-tui.git)

**同栈**：Rust + `ratatui` + `crossterm` + `cpal` + `rustfft`——和我们完全一样。它做的是"把声卡输出画成终端图形"。

### 5.1 它有三种可视化模式

| 模式 | 画什么 | 我们能借鉴什么 |
|---|---|---|
| **Oscilloscope** | 波形（时域） | 直接可加：`ctap` 样本 → 折线 |
| **Spectroscope** | 频谱（频域） | 我们已有，但它多了三个处理 |
| **Vectorscope** | XY 矢量图（左/右声道做坐标轴） | **视觉最独特**，Lissajous 图形；"oscilloscope music" 就是用这个看的 |

### 5.2 三个应当照抄的处理

| 处理 | 为什么 |
|---|---|
| **对数视图默认开启**（`l` 可切） | 线性频谱在人耳感知上挤在左边 |
| **Hann 窗**（`w` 可切） | 抑制 FFT 泄漏，频谱更干净；成本极低（乘一个窗函数） |
| **时间平均**（PGUP/PGDN 调次数） | 抑制逐帧抖动，观感稳定 |

我们当前三项都没做——**这是频谱"看起来业余"的主要原因**。

### 5.3 参数与我们完全一致

> 默认 buffer **2048** @ **48kHz**，README 说"应该保证至少 20 帧每秒"。

**我们选 2048 / 20fps 是对的**，有独立实现佐证。

### 5.4 其他值得注意的

- **Braille 默认开启**，`--no-braille` 才关——印证 §2.1 的判断。
- **scatter 模式**（散点）在高频比 line 模式更精确；line 模式是"连直线"，高频会失真。
- **触发模式（trigger）**：让波形稳定不滚动，是示波器的经典能力。
- **`--no-ui`**：只画图形不画界面，适合当背景。
- 它用 `rustfft`；我们手写 FFT 也行，但**如果要加多模式，重新评估是否直接用 rustfft**（它已是该领域事实标准）。

### 5.5 结论（对 T-0064 的修正）

原计划只做"Braille 频谱"。看过 scope-tui 后应改为：

1. **频谱加对数 + Hann 窗 + 时间平均**（先做，收益最大）
2. **Braille 画布**（原计划）
3. **新增波形模式**（oscilloscope）
4. **Vectorscope 作为沉浸模式的备选视觉**（独特、好看、实现简单）

## 6. rebels-in-the-sky：彩色像素风的实现拆解

来源：[ricott1/rebels-in-the-sky](https://github.com/ricott1/rebels-in-the-sky)（GPLv3）。终端 P2P 太空海盗篮球游戏，建议 **160×48** 终端。

**结论先说**：它的"色彩丰富又精致"**不是终端魔法，是图像合成**——
在内存里把一帧 RGBA 图画好，再映射成字符格。

### 6.1 四层合成（源码可查）

| 层 | 做法 | 出处 |
|---|---|---|
| **1. 图层叠加** | 星空底图按 2×6 平铺；精灵图以 alpha 混合贴上去（`copy_non_trasparent_from`） | `src/image/utils.rs` |
| **2. 调色板重映射** | 精灵图用**纯红/纯绿/纯蓝**当"通道"，运行时按 `ColorMap{r,g,b}` 替换成任意三色 | `color_map.rs` + `apply_color_map` |
| **3. 光照遮罩** | 生成 horizontal / vertical / radial / exponential 四种**渐变遮罩**，按 alpha 叠加 → 渐变、暗角、光源 | `LightMaskStyle::mask` |
| **4. 阴影遮罩** | 按遮罩把像素 ×0.75（变暗）或 ×1.25（提亮） | `apply_color_map_with_shadow_mask` |

**关键洞察**：**色彩丰富来自"少素材 × 多调色板"**——同一套精灵通过 `ColorMap` 能变出几十种配色；**精致来自渐变遮罩**——光影是算出来的，不是画出来的。

### 6.2 资产来源

- 星球 GIF 由第三方 **像素画生成器**（Deep Fold）产出；
- 精灵为 PNG 序列（含灰度 mask 图用于阴影）。

**他们画的是像素画**，不是程序化矢量图。这一点很重要：**精致感来自美术资产**，代码只负责合成与变色。

### 6.3 渲染到终端（推断，高置信）

160×48 字符 → **160×96 像素画布**，即用**半块字符**（`▀`，fg=上像素、bg=下像素）把 2 个纵向像素塞进一个字符格。

> 未逐行读取其 widget 源码，但：README 说"不是所有终端都能正确显示颜色"、要求 160×48、且全套是 RGBA 合成——**半块 + 24 位色是唯一符合这些条件的方案**。

### 6.4 我们能直接借鉴的三件事

| 借鉴 | 用在哪 | 成本 |
|---|---|---|
| **半块像素画布** | 封面在**无 Sixel 终端**的降级方案（比 ratatui-image 的 halfblock 更可控）；沉浸模式背景 | 中 |
| **渐变遮罩** | 播放器面板背景加**径向渐变**或暗角，立刻"高级" | 低 |
| **调色板重映射** | 视觉元素跟随主题 token 变色（我们的主题系统正好有 accent） | 低 |

**不建议借鉴**：整屏星野/视差滚动——那是游戏的全屏玩法，我们常驻面板 28 列，且 CPU 预算只有 3%。
